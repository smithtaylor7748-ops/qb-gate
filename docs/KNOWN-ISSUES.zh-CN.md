# 已知限制与验证边界（v0.22.0）

本文件描述当前实现，旧版本的问题和设计经过可在 Git 历史及 DESIGN-NOTES.zh-CN.md 中查阅。

## 平台与门禁

- 当前完整支持 Windows x64。macOS / Linux 不是可用发布目标。
- 执行 ACL 只控制程序启动；不会冻结已加载进程、撤回已发送请求或隔离网络。Desktop 的 `app-<版本>` 主程序不能加执行锁，依赖受管会话和巡检。
- 巡检间隔两档统一为 5 秒（Claude Code / Codex 与桌面端同一个数），另有网络与停止耗时。IP 无法确认即发起关闭，没有宽限；网络抖动也可能关闭会话。**巡检越密，撞上探测源同时限流 / 超时的机会越多**，这类「查不到 → 关停」的误杀会随之变多，不会变少。
- **中转会话不受门禁关停。** 启动中转会话仍然要先验 IP —— 执行锁是按文件加的，不认身份，绕过解锁就等于留了一个绕过入口。但出口 IP 变了之后，看门狗只上锁并收掉官方进程，不动中转会话，会话内门禁也不写进中转环境目录。理由：中转请求打的是第三方端点、不带官方 OAuth 身份，收它换不到任何保护，却会弄丢正在写的对话。
- 启动恢复遇到结不清的记录时，只列出那几条（路径与原因），其余照常结清。可以在恢复页显式放弃它们 —— 放弃会把记录移进 `quarantine/` 保留，相关配置文件保持当前状态，不再能按那条记录回滚。
- **面板托管的会话（含中转、账户页起的 GPT 桌面端、以及被移出门禁的 GPT）在面板退出时会被系统一起终止**（Job Object 绑定）。请最小化到托盘以继续使用。这是刻意的：不绑定的话，命名 Job 对象会随面板退出消失，进程还在跑而面板已经认不出它 —— 界面会把它报成「已退出」，此后既停不掉，切账户清场时还可能把它当成官方进程一起杀掉。未受管程序与宿主保护链中的程序可能无法被关闭，界面会报告失败。
- Machine-wide 安装目录可能需要管理员权限才能修改 ACL。部分失败不会被报告成完整成功。
- 第二次启动会唤起已有面板。不同旧版本使用不同名称时，仍应先卸载旧面板避免并存。

## 客户端与扩展

- Claude Desktop 仅官方启动。Codex 官方登录不参与 Claude 槽位切换。当前 Codex 启动使用 Responses；Chat Completions 可诊断，但不能作为当前 Codex 启动协议。
- GPT 汉化只改面板管理的槽位和默认 `config.toml`；如果开始菜单、更新器或其他程序已经起了另一份默认 GPT，面板不会替你关闭它，也不会改它正在使用的配置。两份窗口可能同时出现，分别显示各自的对话；先完全退出默认那份，再点一次汉化。
- 汉化时如果面板槽位和外部 GPT 同时开着，面板会先关闭自己管理的、要改的那几个槽位、写入设置，但不会自动重开槽位；这是为了避免汉化动作在当前对话旁边再弹出一个独立窗口。关闭外部 GPT 后，从账户页手动启动槽位。不想关正在用的 GPT：在它自己的「设置 → General → Language」里选中文，立刻生效（写的是同一行）。
- GPT 账户页启动槽位时，如果检测到任何已有 GPT 窗口（包括外部/默认窗口），现在会先明确提示「继续会打开独立窗口」；确认前取消即可避免第二份对话突然出现。已有窗口不会被 QB Gate 偷关。
- **GPT 自己会把 `config.toml` 写坏**（同一张表写两遍，09-26 本机见过 `[desktop]` 与 `[mcp_servers.node_repl.env]` 各两遍）：GPT 读这种文件会失败、整份桌面设置一项都不认。「设为中文」会先把重复段并掉（不改任何值）再写；同一个键两处的值不一样的，面板说不准哪个才对，不修，照实说是哪张表哪个键。**没核实**：GPT 自己的 app-server 读这种文件时是不是同样整份作废（桌面端那一侧核过，`app.asar` 的日志写的是「Failed to load desktop settings」）。
- **GPT 设了中文要重开才生效**：它只在启动时读这一项，运行中改 `config.toml` 它不重读（26.924 读过它的设置代码，没在真机上逐版本验）。
- **「Codex 出站与换出口」插件是外部程序，本面板只接入。** 需要你自己从它的仓库 Releases 下载发布包解压（默认找 `%LOCALAPPDATA%\Programs\ccodex-sleep-state\ccodex-sleep-state.exe`，也可在插件页指定）。它接管的是**当前激活的 Codex 账户槽位**目录（没有槽位才是默认 `~/.codex`；插件页「接管的 Codex 目录」写着是哪份），接管期间别切槽位。与账户页的官方 turn-state 识别**双向互斥**：0.24.7 起两者都要改同一个槽位的 `config.toml`（识别改 `model_provider`，插件整份接管），同时开就是两个程序抢同一个文件——识别开着时后端拒绝启动插件（到「识别」弹窗点「关闭识别」），插件跑着时拒绝开启识别。它以带窗口的独立进程运行、不随面板退出而结束；**面板重启后认不出之前起的那份**（命名 Job 随面板消失），只会报「端口被占、不是本面板起的」，那时请到它自己的窗口按 Ctrl+C（它会恢复 Codex 配置）。面板的「停止」= 结束进程 + 跑它自己的 `restore`；`restore` 没成功时会原样报出，请到它的面板用「检查与修复配置」。
- **账户页的「识别」入口在窄窗口（≤780px）下收起。** 那一页是固定高度，680 这一档标题栏放不下再多一个按钮（test:ui 钉着不许裁切）。同一个弹窗在中转站页的 Codex 分页仍能打开。
- **Codex（Microsoft Store 版）自动更新后可能需要管理员重新注册，否则任何启动都被系统拒绝（拒绝访问 / os error 5）。** 新版 Codex 的打包应用带了需要管理员注册的服务组件；Store 后台更新一旦没走完，当前用户对该包的注册就失效，此时 `std` spawn、`CreateProcessW`、应用激活（`IApplicationActivationManager`）**全都**返回访问拒绝（激活 API 直接报 `0x80073D28 administrator privileges required`）—— 与本工具用哪种进程创建方式无关，换成 CreateProcessW 也一样。账户页会把这种情形说清楚，并提供「修复 Codex 注册（需要管理员）」一键修复（`Add-AppxPackage -RegisterByFamilyName`，会弹 UAC）；也可在 Microsoft Store → 库 更新 Codex。修复需要管理员，面板无法在不弹 UAC 的情况下自动完成，使用者不授权就修不了。
- API 服务的模型、工具与流式兼容性以实际响应为准。
- Skills 更新检查解析上游固定版本；MCP 精选条目的版本随程序目录发布，手动 MCP 通过重新导入更新。MCP 配置对象包含多个服务时按填写的名称选择一个条目，不自动全部安装。
- 酒馆（2026-09-29 起是内置功能）：你自己装的那份（git 克隆的、解压的）面板只起、只停，程序文件的更新仍由它自己的方式管（例如 `git pull`）；
  软件页下载安装的那份由面板管更新、换版本与卸载（见下面 2026-09-29 那两节）。未登记的已占用端口不会被冒充为受管进程。
- 酒馆「自动定位」只扫固定盘与家目录，跳过系统目录、`node_modules`、`.git` 这类重目录与隐藏目录，也不碰网络盘和可移动盘。默认档深度 4，装在更深处的要点「深扫」（深度 7），再找不到就自己填路径。预算用完时界面会写明「没扫完，结果可能不全」—— 那跟「没找到」不是一回事。候选一律由使用者点「采用」，面板不自动写配置。
- Skills 更新遇到文件修改会阻断，需先保留修改；卸载保留文件。配置快照不包含完整扩展资产，恢复后按实际文件重新核验状态。
- 当前程序会话内保留筛选与草稿；退出面板不持久保存含 Key 的草稿。新操作记录可跨重启查询；旧安装服务的细粒度进度仍使用兼容事件，重启后不会恢复完整逐行进度。
- 历史记录有上限：操作 200 条、会话 100 条，超出的按时间清掉（正在运行和待核验的会话永不清理）。硬盘上的配置恢复记录保留 30 天，只用于崩溃后结清写了一半的配置；环境的「回滚配置」2026-09-27 随旧页删了，不再有记录被它留住。
- Skills 只能装到 Claude Code：Codex 不读 `skills/` 目录，装进去不会生效，所以界面不提供这个选项。
- 「检查来源更新」不会改动精选目录里写死的版本 —— 那几个提交哈希是 ATTRIBUTION.md 里核对过许可证的那一版。它只报告上游有没有新提交；要用新版自己从来源手动导入。

## 账户与用量（v0.20.0）

- **没有「管理账户」页了**（v0.20.0）。删除直接长在总览的槽位横条上，`/accounts`
  重定向到 `/`。那一页独有的「官方目录里的 API 配置」搬进了总览的折叠块。
- **用量里的美元是「按官方 API 价折算」，不是账单**（2026-09-24 起；在这之前只给「缓存省下的」）。
  回答的是「同样的 token 走 API 要付多少」；订阅账户付的是月费，不按这个收费 —— 界面把这句写在数字旁边。
  单价来自内置的官方价快照或本次启动抓到的定价页，「按什么价算」那张表标明是哪一种；
  认不出价的模型不计入，单独列出模型名、条数与 token 数。
- **缓存命中率的分母里没有输出**（`缓存读 ÷（输入 + 缓存读 + 缓存写）`）——
  输出是生成出来的，没有「命中」一说。一个字都还没读过时显示「—」而不是 0。
- **槽位列表一页 3 条**，多的走页码：这一页要在默认窗口里一屏放完。
- **删槽位不可恢复。** 删掉的是整个登录目录：凭证、设置、会话历史一起没。那个账户
  以后要用得重新登录一次。**当前激活的槽位删不了** —— 删它会留下一个指向空处的
  `claude-profile`，而没有任何东西会去修它，下次启动 Claude Code 会安安静静退回
  默认目录 `~\.claude`，界面上什么都不报。先切到别的账户再删。
- **「还能用吗」会带着你的官方令牌对外发一次请求。** 打的是公开的
  `/v1/models`（不打模型、不产生 token、不问额度、不写回任何东西），
  只在你点的时候发。本地访问令牌已过期时**不发** —— 那种时候被拒是必然的，
  报出来只会是假警报；面板也不会拿 refreshToken 去换新令牌。
  ⚠ 这个端点认不认 Claude Code 的 OAuth 令牌**还没用真令牌验过**，
  所以「被拒」那一档写明了两种可能，面板分不开。
- **token 统计的归属有三级依据，都是官方客户端自己写在本机的东西**（0.25.0）：
  ① 桌面端资料目录里的会话记录 `claude-code-sessions\<账户>\<组织>\local_*.json`
  （`cliSessionId` 对上转写文件名）；② 桌面端「无文件夹」会话的项目目录名里嵌着的
  账户 uuid；③ 旧转写里 `bridge-session` 行的 `ownerAccountUuid`。
  **第 ③ 级从 Claude Code 2.1.271（2026-09-15）起就不再被写入**，0.21.0–0.24.8
  只认它，所以那之后桌面端跑的会话全被算成「未归属」，用量卡永远是 0。
  三级都归不出的记录仍然**不摊给任何账户**，单独显示成「归不到任何槽位」——
  多半是终端里直接起、没经过面板的旧会话。桌面端里删掉的会话记录也会让对应转写
  退回这一档。
- **token 统计覆盖两处**：槽位自己的 `projects\`，以及默认目录
  `~\.claude\projects` 里归得上这个账户的那部分；两处都包括子代理转写
  `<会话>\subagents\*.jsonl` 与工作流子代理 `<会话>\subagents\workflows\<wf>\*.jsonl`（都归父会话）。
  仍然不是「这个账户一共用了多少」—— 归不出属的那部分单独列，别的机器上跑的更不在内。
- **GPT 槽位的用量只数 `home\sessions` 里的本机会话记录。** 桌面端的云端任务
  不写本机文件，只用过云端任务的槽位就是 0 份文件、0 个会话 —— 页脚会写明
  「该槽位还没有本机会话记录」，不要读成统计坏了。
- **token 统计必须去重，而且去掉的那一半和留下的一样多。** 续接会话与自动压缩会把
  之前的回复原样重放进新的转写文件。实测一个槽位 6,049 条记录里 2,860 条是重放。
  去重键是 `message.id` + `requestId`；同一个键出现多行时留**最完整的一份**（有用量 > 带 `stop_reason` >
  输出大 > 时刻早，2026-09-24 起，参照 cc-switch）。跟别的工具对不上数时，先看两边去没去重。
- **用量读数的来源与新旧要一起看。** 桌面端的样本只在桌面端运行时才写，关掉之后读数
  就冻在最后一条；Claude Code 留下的快照经常更旧。跨过窗口长度的读数一律显示
  「读数已过期」而不是那个数字，**两个来源同一把尺子**。
- **剩余天数查不出「被风控下线」。** 它只读本地那个时间戳。令牌被回收时凭证文件还在、
  到期日还是将来某一天，而实际已经发不出请求 —— 唯一能确认的办法是实际发一次认证请求。
  所以详情页的「重新登录」是常驻的，不按到期与否隐藏。

## 出口一致性（v0.20.0，综合评分第五项）

- **它只收与出口 IP 对不上的信号。** 浏览器里的 claude.ai 痕迹、扩展权限、
  凭据管理器、环境变量残留都不在这一项里 —— 它们跟出口没关系，分别在软件页的
  Chrome 卡片和「中文环境」详情里的本机体检。
- **浏览器那三项默认只看 Chrome。** Edge 与 Firefox 不在范围里，跟软件页那张 Chrome 卡片一样。
  例外（2026-09-24）：一小时内用「用默认浏览器测」实测过的话，「浏览器语言」「WebRTC」两行改用那次实测，
  哪个浏览器打开的链接就算哪个；DoH 那一行仍只读 Chrome 的策略。
- **注册表里写进了策略不等于 Chrome 已经用上。** 面板读不到 `chrome://policy`，
  改完请重启 Chrome 自己核对。面板只写 HKCU；整机（HKLM）压着的同名策略不是面板设的，
  一个字都不碰，但会把来源报出来。
- **DoH 只设到 `automatic`，不设 `secure`。** `secure` 要求同时给出
  `DnsOverHttpsTemplates`，没配的话 Chrome 什么都解析不出来。那个解析器该填谁，
  只有你自己知道。
- **浏览器语言与出口那一项只报告，不修。** 面板不替你改浏览器或系统的身份 ——
  那是 DISCLAIMER 与 CLAUDE.md 点名不做的设备指纹伪装。
- **判不出浏览器里登的是哪个账户。** 只能报「有 claude.ai 的站点数据」。
- **扩展只列装着的，看不出有没有启用**，也不提供停用或删除的入口 —— 那该在浏览器里
  自己决定。
- **「查不了」的行不参与评分**，分子分母里一起去掉 —— 算 0 分是在冤枉使用者，
  算满分是在替一个没做过的检查打包票。七行（2026-09-24 起；原来五行）全都查不了时这一项整个不计入总分。
- **浏览器语言那一项只判一种组合**：中文语言 + 非中文地区出口。别的组合不下判断 ——
  说不清楚的信号不如不说。

## 中转站（v0.14.0 起）

> **⚠ 中转站（含智能调度）目前仍在内测：界面里已经出现，但还不能正常使用。**
> 请不要把它用于实际工作，也不要依赖它给出的排序、倍率或检验结果。
> 下面各条记录的是实现上的边界，不代表这些功能已经可以放心使用。
> 使用第三方中转站的合规风险见 [免责声明 §5.1](../DISCLAIMER.md)。

- **本机路由只绑 `127.0.0.1`。** 它只转发明确指向它自己的请求，不修改系统代理设置、不接管其他程序的流量、不做链式转发。它不是代理或翻墙工具，也不会让你访问到网络本来访问不到的地方。详见 [免责声明 §5.1](../DISCLAIMER.md)。
- **中转站的熔断只在你自己填的线路之间切换，永远不会触发官方账户槽位切换。** 两条路径在代码上隔死（`qb-station` 不依赖 `qb-accounts` / `qb-launch`），由 `src-tauri/tests/architecture.rs` 的测试钉着。
- **站点检验会计费，只在你点的时候跑。** 六项里有两项**永远记「没测到」**：上下文窗口与最大输出。要测它们得构造超长输入和超大 `max_tokens` 去试探，而「试到多少算到顶」的判据没有定过，每试一次都真花钱。记「没测到」会同时压低可信度和证据档次 —— 这是有意的，没核实就不该读作可信。
- **0.23.1 查套路范围**：后台账号密码或独立浏览器登录，New API / Sub2API 自动取得会话。默认六次受控请求，可另行确认第七次冷前缀对照；整轮倍率须完整且相同请求 ID 的新账单。缓存复用扣除背景，不鉴定模型身份或全站成功率。健康度最多最近 100 条。Linux DO 通过本站登录页完成，原压缩包缺少其 Node broker，本项目使用独立 WebView2 窗口。真实站点登录及计费运行需本人凭证。见[使用与修复说明](RELAY-REPAIR-0.23.1.zh-CN.md)。
- **可信度必须和证据档次一起看。** 同样 29 分，可能是「六项都测了、四项对不上」（该换站），也可能是「只测到一项」（该再跑一轮）。只看分数分不出来。
- **检验出对不上不等于拉黑。** 面板只把真实倍率算出来参与排序，没有「排除 / 禁用」按钮。
- **官方参考价没有 API，只能抓两家的定价文档页。** 页面改版时解析器可能只认出一两行，那种「半成功」会用残缺的表盖掉完整的内置快照，所以解析不足 3 个模型就整批丢弃、沿用快照，界面照实说明用的是哪一份。缓存两项除非官方单独标过，否则按标准倍数推算，`PriceBasis` 标明是哪种。
- **分组不能自动发现。** `/api/pricing` 能拉到模型和它们的分组名，但把分组列表拉下来**建线路**需要登录站点后台，没做。线路仍需手工添加（添加弹窗会顺手建站点，站点名撞上已有的就复用那一个）。
- **`peak_rate` 没有数据来源**，恒为 `None`（按不修正处理）。~~`group_ratio` 没有数据来源、`/api/pricing` 不返回~~ —— 这句是错的：New API 把分组倍率放在 `/api/pricing` 响应的**顶层** `group_ratio` 里，0.25.4 起按线路的分组读（sub2api 那边登录后读 `/api/v1/groups/rates`）。见下面 0.25.4 那一节。
- **站点没公布 `completion_ratio` 时界面什么都不显示。** 「不知道」不等于「没加价」。⛔ 公布了、而且大于 1 **也不等于「翻倍」**：它是「输出价 ÷ 输入价」，Claude 官方本来就是 5；0.25.4 起只在它比官方的比例多出 5% 以上时挂「输出加价」。

- **桌面端启动前必须先退干净。** 它是 Electron 单实例：已经在跑的时候再点「启动」，只会把旧窗口拉到前面，新给的数据目录一个都不生效 —— 面板会拦下来并说明，但这一步没法替你做。

## 中转站（v0.17.0 追加）

- **智能调度只在面板开着时生效。** 循环活在面板进程里，一跳 30 秒（2026-10-24 起；站点账单仍然最多一分钟拉一次）。关掉面板它就不再换上游了，而客户端还在照着上一次选的那条线跑 —— 可能是几天前那条已经涨价的。界面上写着这句话；这不是缺陷，是这个软件的定位（它是个面板，不是后台服务）。
- **本机路由的端口写死默认值 15721。** 走本机路由的那个环境把这个端口写进了磁盘上的配置文件，所以从中转站页面启动时也只用默认端口。手动用别的端口起路由，客户端会连不上，而它报的只是「连不上」。要支持自定义端口的话，端口得先变成环境自己的字段。
- **请求日志里的 token 有时是 `—`。** 2026-10-24 起本机路由边转发边从响应里解出四类 token（流式只留算用量要的那几个事件，不缓冲整条响应），落库时按这条线自己公布的价和官方价各折一个美元数。解不出来的几种如实留空：升级前的老日志、上游没在响应里报用量、上游不理 `accept-encoding: identity` 硬回了压缩过的响应。站点账单那张卡仍按站点自己的口径，跟路由日志对不上是正常的。
- **自动故障转移只在「交出回复之前」换线。** 连不上、超时、5xx、藏在 200 里的错误、被限流 —— 这些发生在第一段内容交给客户端之前时，这一发改用派单顺序里的下一条；**交出去之后**上游再断，只能如实断开（换线等于把两条线的回复拼在一起）。请求本身的问题（400、422 之类）原样回给客户端，不换线、不算线路的错。官方 Codex 那条线永远不换线。
- **静默超时会掐断长时间没有新数据的流。** 默认 Claude 180 秒、Codex 300 秒（跟 Codex 自己的默认一样），首包超时 Claude 90 秒、Codex 60 秒。原来本机路由没有这两道超时，上游卡住就一直挂着；现在卡住会被断开并记成这条线的故障。上游在思考阶段一个字节都不发、又超过这个时长的话，也会被断开。这几个数在「路由设置」里能改（0 = 不限）。
- **本机路由不随面板启动。** 面板起来时只把各软件上次选中的线路、路由设置、派单顺序装回去（2026-10-24 起落盘）；路由本身（监听 15721）仍然在中转站页点「启动」或开启识别时才起。所以面板重启之后，直接打开那些已经指向本机路由的客户端（比如配好了第三方网关的桌面端）会「连不上」，要先在中转站页点一次「启动」。
- **本机路由开到「所有网卡」时，口令是唯一的门。** 拿到口令的人就能用你的中转线路额度；局域网里的流量也没有加密（HTTP）。只在你信得过的网络里开，口令随时可以「换一个」。这台电脑上的进程不查口令（它们本来就读得到配置文件）。
- **出站代理只认 HTTP / HTTPS / SOCKS5 / SOCKS5h**，不支持 PAC 脚本、不读系统代理设置。「测试」试连的是这个软件底下第一条线的地址，那条线本身不通的话也会报失败。
- **熔断状态不落盘。** 面板重启后每条线都从「正常」开始；关了一小时的那条（余额不足之类）也会被立刻再试一次 —— 它还是坏的话，一次就又关回去。
- **六个快捷开关的键名和判定条件都对着 cc-switch 的源码核过了**（`CommonConfigEditor.tsx`），模型映射对的是 `useModelState.ts`。仍然要说明的是：这些是 **Claude Code 自己的**环境变量，它们各自做什么、哪一版开始有，取决于客户端而不是这个面板 —— 上游改了名字，写进去的那一行就会变成一句没人听的废话，而界面上看起来一切正常。`Teammates 模式`、`Tool Search`、`最大强度思考`、`禁用 Artifact` 是实验/兼容性开关，属于这一类。
- **「声明支持 1M」不是一个环境变量**，是在模型名末尾加 `[1M]` 后缀（cc-switch 的 `CLAUDE_ONE_M_MARKER`）。认不认这个后缀由**中转站那边**决定 —— 面板只负责把它写进配置，站点不认的话没有任何提示。
- **免费测活只能证明「线通、Key 没被拒」**（2026-10-24 起，调度开着时）。它发的也是空请求体：站点回 400 / 422、说缺模型、
  认不出文字的 500 都算测通（站点解析了这一发）；有的站先校验请求体、后校验 Key，那种站上 Key 填错了免费测活也会显示「活着」——
  真实请求一来就会被熔断接住。测不出快慢；快慢要花钱测活。
- **花钱测活的花费是估算。** 按这条线公布的单价（没有就按官方价 × 真实倍率，再没有就按偏贵的 $30 / $150 每百万 token）乘充值比例算，
  预算按上界扣。站点按次计价、推理模型把输出上限全花在思考上时，实际扣费可能跟估算对不上；以站点账单为准。
- **测活跑完才进下一跳。** 一跳里的测活（同时 3 条，免费的最多 15 秒、花钱的最多 60 秒一条）要等它跑完，下一跳才开始；
  线很多又都在超时的话，派单会晚几十秒到几分钟。熔断与本机路由的失败切换不受影响（它们不等调度）。
- **「快」用测活速度时整池都要有。** 打开花钱测活之后，要等这个软件的每条线都测出过速度，「快」才改按测活比；
  在那之前仍按本机日志 / 账单的体验分。不同线用了不同模型测（某条线上没有那个模型）时，速度照样放在一起比。
- **只有站点账单的线，「有没有新证据」按账单拉取的时刻算。** 防抖要连续几轮有新证据才换；这类线每拉一次账单就算一轮新证据，
  哪怕账单里没有新的请求。
- **突发测活的冷却期记在动作日志里。** 动作日志只留最近 500 条，被裁掉之后冷却期从头算。
- **协议转换不是无损的**（2026-10-25 起，线路标了跟软件不一样的「上游协议」时）。转换照搬 cc-switch v4.0.14：

- **Codex 的远程压缩在转换线上靠转换器自己处理；原生 Responses 的中转线上那一半没搬**（cc-switch 的压缩回合改写）。

  「这些位置现在是空的」，**不是**「这台机器上再没有任何痕迹」。面板够不到的地方见下面两条。
- **面板只看得见 Windows 这一侧、当前这个用户。** 每个 WSL 发行版里的安装与配置、其它
  Windows 用户账户下的副本，都扫不到也删不掉（扫别人的私有目录本来也不该由面板擅自做）。
  卡片里那份卸载提示词就是兜这一块的：它带着已扫到的完整路径清单，交给别的 AI 去补。
- **正在运行的 exe 删不掉。** Windows 允许改名正在运行的可执行文件，但不允许删除它。
  Claude Code 与桌面端在动手前会先被一键关闭；**Codex 不会** —— 面板不按进程名杀进程
  （档案 §1 第 5 条），所以正在跑的 Codex 要自己先关掉，否则它那几项会出现在复扫的剩余里。
- **删账户槽位 = 所有账户都要重新登录。** `claude-profile-*` 是 Claude Code 的登录目录，
  酒馆桥接指向的是同一份，所以它也会跟着失效。删完「官方账户」页回到「还没有账户槽位」，
  从那里新建（新手引导 2026-09-27 删了）。
  这是使用者定的口径（「要清理就全部清理掉」），不是误删。
- **认证、环境变量、Shell 配置行只报名字与位置，不报内容。** 盘点结果里看不到 Token、
  密钥或那一行原文 —— 结构上就装不下（跟 `sysenv::SecretHit` 同一条原则）。
  所以确认框里那几项只能看到「变量名」「文件:行号」，这是有意的。
- **PATH 与 Shell 配置是合并成一次改写的。** 同一个文件只读写一次，中途失败就整体算失败，
  不会留下改了一半的 profile；代价是那一类要么全成、要么全不成，没有逐项结果。
- **卸载不负责装回来。** 完全卸载之后这台机器上就没有这个软件了，要重新用得自己去
  「安装」那一步。Chrome 是唯一的例外：它另有「清空并重装」。

## 启动对齐（v0.19.0）

- **「已经一致」时什么都不做，所以开着开关也可能一次动作都没有。** 这是有意的：
  切时区要弹 UAC、改显示语言要注销，在已经一致的机器上做这些等于每次开面板
  骚扰使用者一次。每一项做没做、为什么没做，审计日志里都有一行。
- **显示语言默认关，而且设了也未必生效。** 它要先装好对应语言包，并且**要注销之后
  才生效**。面板只负责调 `Set-WinUILanguageOverride`，设完系统认不认由系统说了算 ——
  **面板无法证明它真的生效了**，界面上也不会假装知道。
- **区域格式只对之后新启动的程序生效。** 已经开着的程序（包括面板自己）读到的还是
  旧值，所以改完当场看界面是看不出变化的。
- **切时区要管理员权限。** 拿不到就是切不成，这时日志里会写「系统时区没切成」并带上
  原因，**不会**静默当成成功。
- **对照表只收常用时区。** 查不到对应的 Windows 时区或区域标签时一律跳过并记下原因，
  不猜 —— 猜错会把机器设成一个使用者没要过的地区，比不改糟得多。所以小众出口地区
  可能出现「开关开着、日志里写着跳过」。
- **面板不替你把时区改回去**（2026-09-27 起写明）。切之前的原值记在审计日志里
  （「系统时区 A -> B」），要改回去就按它在 Windows 设置里手动选。原来「设置 › 高级维护」
  有一颗「恢复时区」，它只认早先时区卡记下的原值，而启动对齐从来不记 —— 点了永远提示
  「已恢复」、实际一个字都没动，所以连同那三条时区命令一起删了。
- **首次运行不对齐。** 面板还没就绪的那一档整段不执行，否则会在使用者还没同意过任何
  事之前弹一个 UAC 去改系统时区。
- **这不是「防封」。** 对齐只是让 Claude Code 读到的时区与格式跟出口一致。
  DISCLAIMER 写死了「去除中文环境特征不会降低任何封禁概率」。

## 浏览器出站锁与系统代理（v0.19.0）

- **⚠ 防火墙规则不随面板退出而消失。** 它是系统级持久对象：面板关掉、甚至卸载之后
  规则仍然在，浏览器会继续上不了网，而使用者多半想不到是这里。
  撤销入口在面板里，**卸载面板之前请先撤销**。
- **拦的只是你点名的那几块网卡。** 没点到的接口一概不受影响 —— 这是有意的
  （需求文档要求「不对未知接口、远程桌面、局域网共享或系统服务做广泛阻断」），
  但代价是**选错网卡就等于没拦住，而面板并不知道你选错了**。面板只如实列出网卡名
  与驱动描述，不替你判断哪块是物理网卡、哪块是 TUN —— 猜错的两种后果
  （拦到 TUN 上当场断网、漏掉物理网卡等于没拦）都比让你自己选糟。
- **加规则要管理员权限。** 拿不到就是加不上，会如实报错。面板自己**不提权**
  （安装是 `currentUser` 模式，没有 requireAdministrator 清单），所以想用这个功能
  得以管理员身份启动面板。弹窗里写了这一条。
- **网卡名里带 `*` 时，规则可能落到不止那一块网卡上（v0.19.2 起的已知缺口）。**
  Windows 自己就把 WiFi Direct 那几块虚拟网卡叫「本地连接\* 1」/
  「Local Area Connection\* 2」，而 `New-NetFirewallRule -InterfaceAlias`
  接受通配符。**删**的那一侧已经转义（`QB Gate` 只删自己算出来的那个名字），
  **加**的那一侧没有：不确定防火墙的接口过滤器认不认反引号转义，而猜错的代价是
  规则落在一个匹配不到任何网卡的别名上 —— 一条看起来加上了、实际什么都没拦的规则，
  正是这一版在修的那类毛病。**查不到就不猜**，先如实记在这里。
- **出站锁不等于「不会泄露」。** 它挡的是经过那几块网卡的**新建出站连接**；
  已经建立的连接、其它浏览器、其它程序都不在这条规则的范围内。
  面板不会、也不能给出「绝对无泄露」这种结论。
- **面板只碰自己加的规则。** 判据是规则名前缀 `QB Gate - `；不带这个前缀的一律不动，
  包括你自己加的同类规则。
- **⚠ 改系统代理可能当场断网，而且影响整机。** 那是**整机**设置，所有跟随它的程序
  都会跟着走，不只是那一个浏览器。面板会拦下一种明显自毁的组合（开着代理却没填地址），
  但拦不住「地址填错了」。
- **改完之后已经在跑的程序多半要重启才会读到新值。** 面板改完会读回注册表核对，
  但那核对的是**设置本身**，不是「所有程序都已经用上新设置」。
- **原值存在 `%LOCALAPPDATA%\ClaudeIpGate\proxy-backup.json`。** 连续改两次时，
  备份保留的是**面板第一次动手之前**那一份；还原成功后备份会被清掉，
  「还原」按钮也随之消失。

## 浏览器隐私面审计（v0.19.0）

- **只列「装着的」扩展，判不了有没有启用。** 那要解析 Chrome 的内部状态文件
  （`Secure Preferences`，还带完整性校验），判错就是一句说谎的结论。
  请自行到 `chrome://extensions` 核对。
- **只报告，不动手。** 面板没有禁用或删除扩展的入口 —— 这是需求文档的硬要求，
  也是有意不提供的：没有那个功能，就不会有人误用它。
- **权限判定宁可多报也不漏报**，所以可能出现误报。漏报的代价是面板说
  「这个扩展没问题」，比多提醒一次糟得多。
- **扩展名用了 `__MSG_xxx__` 国际化占位时会留空。** 真名要去 `_locales` 里查，
  面板不编一个名字顶上。
- **⛔ 注册表里有值 ≠ 策略已生效。** 面板读不到 `chrome://policy`，所以设完
  WebRTC 策略只能告诉你「注册表里有了这个值」。要确认 Chrome 真的用上了，
  **请重启 Chrome 后自行到 `chrome://policy` 核对**。
- **面板写的是当前用户（HKCU）的策略。** 如果整机（HKLM）还压着一条同名策略，
  Chrome 以整机那条为准 —— 那不是面板设的，面板一个字都不碰，
  但审计结果里会标出这条策略的来源。
- **只看 Google Chrome。** Edge、Firefox 及其它浏览器不在审计范围内，
  跟「清空重装只认 Chrome」是同一条边界。

### ⚠ 先纠正一个预期（2026-09-22 核对）：没有「花钱买立刻见效」这条捷径了

**EV 证书从 2024 年起也不再给即时 SmartScreen 信誉**，微软把那个特殊待遇取消了；
OV / EV / Azure 现在走的是同一套有机积累
（<https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation>）。
所以**别花几百刀买 EV 换立竿见影**。

签名真正的价值是另一件事：**信誉可以跨版本继承** —— 同一个签名身份连续发布，
后面的版本继承前面攒下的。现在每一版都是从零开始，这才是根本差别。
它也因此跟 `CLAUDE.md` 那条「版本号只在出包那一刻提」绑在一起。

### 各条路的代价（2026-09-20 核对，2026-09-22 补两行 + 三条代价）

| 路线                       | 能不能走          | 代价                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SignPath.io 开源免费档** | ⛔ **现在不合格** | 条款要求 "an OSI-approved Open Source license **without commercial dual-licensing** for all components"（<https://signpath.org/terms.html>），而本仓库有 `LICENSE-COMMERCIAL.md`（README 第 92 行引着它，开头第一句就是「QB Gate 采用**双授权**」）。要走这条得先**永久放弃**商业授权那一档。另有一条软风险：条款排除 hacking / 安全漏洞类工具并限制「侵犯隐私的功能」，而面板扫 Chrome `Cookies`/`History` 字节、写 Deny ACE、杀第三方进程、改代理与防火墙 —— **审核不保证过**。 |

仓库这边**过了**的条件（`gh repo view` 实测）：`PUBLIC`、AGPL-3.0（OSI 认可）、

**走签名这条路之前，三条代价先想清楚（2026-09-22 补）：**

1. ⛔ **签名会把真实法定身份写进每一个二进制**（证书 Subject = 通过验证的姓名或公司）。
   这个仓库现在是以化名 `smithtaylor7748-ops` 发布的 —— 签名等于公开实名，
   而且**不可逆**：已经发出去的签名包永远带着那个名字。这是个产品决定，不是技术决定。
2. 需要 Azure 订阅 + 身份验证（个人档要政府证件；组织档另有成立年限门槛）。
3. ⚠ **签了也不是买断制**：2026-03 微软换了中间 CA（`Microsoft ID Verified CS EOC CA 03`
   一类），一批本来已经有信誉的发布者又开始被 SmartScreen 拦。

### 一条免费的候选（**未验**，2026-09-22 记）

`src-tauri/tauri.conf.json` 现在是 `"installMode": "currentUser"`。
2026-09-22 那次检出的 `Resources` 字段一次点了三样：AppData 里的 exe、
开始菜单 `.lnk`、HKCU 卸载键 —— 这是模型里权重很高的**一组**特征。
改 `perMachine`（或 `both`，让装的人自己选）能把这组拆掉，**一分钱不花**。

代价：安装与升级每次都要过一次 UAC，跟「别人的机器不一定有管理员」那条开源兼容性规矩
冲突。⛔ **改之前先按下面「未验项」的办法量**，别凭感觉 —— 这类启发式的行为没法从代码推出来。

## 0.25.4（2026-09-25）中转站倍率按「中转站百科」帖改对 · 各站的充值比例

- **New API 的分组倍率与充值价只在单测和演示里走过**，没对着真实站点核过。字段形状照 New API 源码
  （`controller/pricing.go` 的顶层 `group_ratio`、`controller/misc.go` 的 `price` / `usd_exchange_rate`），
  改了形状的分叉版本会读不到 —— 读不到就是「不知道」：分组倍率不知道的线路不参加加权比价，充值价按钮不出现。
- **New API 倍率换单价用的是它写死的 $2 / 百万**（`1 === $0.002 / 1K tokens`，它自己的定价页也写死 2）。
严格说是 `1_000_000 ÷ quota_per_unit`；改过 `quota_per_unit`的站，它自己页面上的单价跟账单就对不上，
面板显示的单价跟着错。**账单核对不受影响**（那边是`quota ÷ quota_per_unit`）。
- **分组名留空按 New API 的默认分组 `default` 查倍率。** 你的账号要是被站长划进了别的分组、令牌又没指定分组，
  实际走的是那个分组 —— 这时填上真实分组名才对得上。`auto` 分组的倍率跟着实际路由走，不是一个数，不认。
- **分组倍率不知道的线路不参加「加权倍率」那种比价**：按不打折算出来的是牌价，跟别家的折后价放在一起比等于冤枉它。
  池子里有一条这样的线，整池就退回「真实倍率」（标称 × 实测）那个粗口径 —— 是有意的。
- **「输出加价」只在检验时算**（要官方价，而官方价按「这组价是哪个模型的」查）：老线路、官方价快照里没有的模型

- **充值比例要自己填。** New API 站点在 `/api/status` 公布的在线充值价只做成一个参考按钮，**不自动采用**：
  那一格默认值就是 7.3，很多站没改过、实际靠兑换码按 1 元卖；照它折算会把这些站冤枉贵七倍。sub2api 没有这一项。
  它是站点级的（整站共用），只用于跨站比较（调度的「便宜」与「倍率不超过」）和线路上那句「折合」；
  查套路的账单核对照旧按站内数值比，余额也照旧按站内额度写。
- **0.25.3 及以前存下的检验历史**：New API 那几类当时只存了原始倍率、没乘分组倍率，现在按 $2 / 百万换成单价显示 ——
  是站点**不打折的牌价**，不是那条线实际的价。重新查一次套路就是新口径。

## 0.25.2（2026-09-24）用量的美元 · 订阅页倍率 1:7 · CheckClaude 三组 · DNS 评分

用量：

- **快速模式（`usage.speed` 不是 `standard`）没有官方价。** 这种回复的模型名带 ` (fast)` 后缀、进「没有官方价」那一栏，
  不拿标准价凑。官方给快速模式单独标价之后要把价补进价目表。
- **GPT 的美元在有长上下文请求时只是下限。** 单次输入超过 272K 的请求官方按更高一档算输入价，会话记录里看不出
  每一段差分落在哪一档，所以只计数、美元写「≥」，不猜档位。
- **GPT（Codex）一侧的按天、按模型与美元没在真机上验过。** 本机 `~\.codex\sessions` 是联结点、按规矩整棵拒读
  （见 0.32.0 那一节），只有单测喂的形状。
- **「今天 / 近 7 天 / 近 30 天」三格不随选中的档位变**，是故意的：三个数要同时看见。
- **账户页用量卡仍走单槽位的轻量路径**（不带按账户、最近请求与价目明细），这些只在 `/usage`。
- **最近请求只列 200 条**（扫描时每个槽位封顶 500），按时刻倒序；更早的只进合计。

订阅页：

- **倍率按 1 美元 = 7 元折算，不跟实时汇率走**（使用者定的，往贵了取）。实际汇率一般在 6.8 左右，按它算倍率再低约 3%。
- **比较的前提是中转站按「1 元 = 1 美元额度」充值**（常见口径，页面上写着）。按真实汇率充值（约 7 元 = 1 美元额度）的站，
  它标的倍率要乘 7 才能跟页面上的数比；其他比例照此换算。腾讯云那篇原文只说「倍率 1 = 同价」，没说充值比例。
  （0.25.4 起中转站页每个站点能填这个比例，调度按它折算；订阅页的计算器里「付的钱 ÷ 中转站给的额度」那一项本身就是它。）
- **计算器里「中转站给你的额度」是站内余额**，按那条线路的分组倍率扣 —— 0.25.4 起旁边多一格「那条线路的倍率」（默认 1）。
  包月会员那种按牌价扣额度的，留空就对。
- 订阅页那几个周额度与倍率区间都是网友 / 文章的估算，见 0.25.1 那一节；换算方式改了，估算本身没变。

环境监测：

- **API 可达量的是「绕过代理」那一路**（跟门禁同一个客户端）。只开系统代理、没开 TUN 时，直连那一路回 403 会判失败、
  评分封顶，即使浏览器与桌面端走的系统代理那一路是通的 —— 说明里会写出两路各是什么。理由：Claude Code（Node）
  不认 Windows 的系统代理，门禁量的也是这一路。
- **claude.ai 回 403 不一定是地区拦截。** 带 `cf-mitigated` 的是 Cloudflare 人机验证页，算「查不出」；不带的只降到警告。
  判定以 API 那一个为准。
- **自定义 fake-ip 段会被报成「可疑」**（警告）。只认得 198.18.0.0/15 与 fc00::/7；别的私有段按「被污染」、
  别的公网段按「可疑」。
- **IPv6 出口只查到国家。** 回显服务三个都连不上就当「没有 v6 出口」—— 那三个服务自己挂了时会误报成通过。
- **真实浏览器采集只测打开那个链接的浏览器**，结果一小时内有效、只在内存里（面板重启就没了）。
  **没在装好的面板里点过**：开发模式与单测验过服务端（令牌、Host、只收一份、超大、超时）与演示界面；
  正式包里页面由 Tauri 的内嵌资源供给，那一条要实机点一次（写在桌面 `claude-op` 的实机清单里）。
- **代理形态按网卡的 `HardwareInterface` 认 TUN**，Hyper-V 的虚拟交换机排除。读不出路由表或网卡（PowerShell 受限）时是「查不出」。
- ~~DNS 泄露评分里「以太网安全」那 50 分按网卡名认，只连 Wi-Fi 的机器最高 50 分~~ —— 同一天改掉了，见下面几条。

DNS 泄露（2026-09-24 评分改过）：

- **网卡那一项只在 TUN 开着时算。** 没开 TUN 就没有隧道可绕，路由器的 DNS 是正常的；这时 DNS 这一项只按真实解析
  （bash.ws 回显）算。「TUN 开没开」问的是发往一个 RFC 5737 文档地址（`203.0.113.1`）的路由走不走非硬件网卡 ——
  开着 Tailscale 出口节点、WireGuard 全局这类也算「开着」，这是对的：那时同样有隧道可绕。
- **「走不走隧道」靠 `Find-NetRoute`。** 查不出路由（没有这条命令、路由选中回环这类 `Get-NetAdapter` 不认的接口，
  比如 DNS 配成 `127.0.0.1` 的本机 DNS 代理）的那一条不判、不计分。只看 IPv4 的 DNS，网卡上配的 IPv6 DNS 不看
  （之前就是这样）。
- **Windows 会同时向每张网卡的 DNS 发查询**，所以「连着的物理网卡上配着不走隧道的 DNS」才算缺口；隧道软件拦不拦得住，
  最终以回显为准（占 70 分）。
- **存盘的旧 DNS 报告不进总分，要重测一次。** DNS 结果会留到下次开面板；升级后读出来的旧报告按旧规则算过分，
  格子上写「评分规则改过，请重测一次」。

## 0.25.0 GPT 默认归门禁 · 酒馆的内置 GPT 桥接

- **GPT 归门禁的开关反着存。** `settings.json` 里是 `codex_outside_gate`（默认 `false` = 归门禁），
  旧键 `codex_under_gate` 升级后被忽略 —— 0.24 之前手动打开过的人升上来和没开过的人落到同一处：
  都归门禁。要退出只能在「IP 锁」弹窗里点，`settings.json` 里手改旧键没用。
- **GPT 桌面端归门禁之后，Store 包注册失效那条（os error 5）报在 `workspace::launch` 里**，文案一样，
  「修复 Codex 注册」按钮照旧。
- **酒馆的 GPT 桥接没有增量流式。** `codex exec --json` 的 `agent_message` 只有完成事件，
  酒馆开了「流式」也只会整段一起出现。
- **不传图、不给工具。** 请求里的图片段落被丢掉；`-s read-only` 加提示词里明说不要动工具，
  但 Codex 自带的系统提示替换不了，模型偶尔仍会「想去看看文件」—— 角色扮演的质量取决于模型自己，
  面板不替它背书。
- **一次只跑一个 `codex exec`**（酒馆本来也一次只发一发），每个请求冷启动一两秒；超过 300 秒
  的一轮会被结束并报 504。
- **Windows 沙箱首次可能要在 Codex 里完成 setup。** 桥接跑的是槽位 `home` 下的 CLI，那个 `home`
  的 `.sandbox` 没初始化过时，Codex 可能拒绝执行或要求先完成 Windows setup —— 到 GPT 页起一次
  桌面端把 setup 走完，再起桥接。报错原文会原样出现在酒馆的错误里。
- **酒馆那边的连接要自己配**（Custom / OpenAI-compatible，地址 `http://127.0.0.1:5002/v1`，
  密钥点「复制密钥」）。面板不改酒馆的 `settings.json` / `secrets.json`。
- **默认 `--ephemeral`，用量卡不数这些对话。** 打开「记入槽位用量」后写进 `home\sessions`，
  用量卡会数到，但对话也会出现在 Codex 的本机会话历史里。
- **政策线没有结论。** OpenAI 对「第三方前端经官方 CLI 用 ChatGPT 登录」没有公开的明确条款；
  桥接只能长成「本机酒馆调本机 CLI、不碰令牌」这个形状，是否合规由使用者自行判断（DISCLAIMER §8）。
- **Codex 桌面端云端任务不写本机文件**，所以「GPT 槽位的用量」只用过云端任务时是 0 份文件、0 个会话，
  页脚会写明，不是统计坏了（见「账户与用量」一节）。

## 0.24.0 → 0.24.7 官方 Codex turn-state 识别

- **真实「拿 292」只能使用者本人实测。** 单测、离线/回环端到端都过了；但官方 Codex
  （ChatGPT 登录）真的走本机路由采集/注入 `X-Codex-Turn-State`，取决于使用者自己的账号、
  网络与 OpenAI 当时的行为。ccodex 自己都常采不到合格 292。**这是实验功能，默认关闭，
  不保证有效、不保证「满血」、不增加额度。**
- **识别期间别切槽位。** 0.24.7 起识别直接改当前激活槽位的 `config.toml`，marker 记着接管的
  是哪个槽位；切到别的槽位再点「开启」会被拒绝（先关闭再开），切槽位本身不会自动关闭识别 ——
  原槽位的配置要等你点「关闭识别」才恢复。
- **开启后要（重）启动 Codex。** 客户端只在启动时读一次配置，已经开着的 Codex 不会自己改走
  路由 —— 弹窗里已就此提示；关闭识别后同理，开着的那个会收到 503 直到重启。
- **接管期间 Codex 若自己改写了 `config.toml`**（例如重新登录、改模型设置），识别会静默失效：
  路由上没有它的请求，状态表一直是空的。弹窗里「重新应用到当前槽位」可以重放一遍；关闭时只把
  仍是 `qb_turnstate` 的 `model_provider` 改回去，Codex 自己改成别的就不动。
- **面板异常退出（崩溃 / 被杀）时 marker 留着**：那个槽位的 Codex 会对着死端口报错，直到下次
  启动面板自动关闭并恢复。等不及的话，手工把 `config.toml` 里的 `model_provider` 改回
  `config.toml.qb-turnstate-backup` 里的值（或删掉这一行）即可。
- **0.24.0–0.24.6 装过「接入并启动 Codex」的人**：升级后首次启动会自动删掉旧的
  `qb-router-codex-official` 环境记录与目录（连同当时复制进去的 OAuth 快照）；那份复制件若已
  经轮换过刷新令牌、把槽位登出了，到「官方账户 · Codex」重新登录一次即可。
- **只对 Codex。** Claude Code / 桌面端没有这个入口，也不进官方模式（Anthropic 协议里
  没有 turn-state 对应物）。

# 0.22.1 体检、Codex 关闭、新 IP 查询与 IPv6（2026-09-16）

## 行为

- 一键全面体检不再被后台工作区通知取消。通知刷新实时状态，保留手动检测及其结果；同一资源的并发刷新共享请求。
- 明确的配置修改仍会作废相关测量。作废与随后刷新不再互相取消；迟到的旧 IPC 结果不能重新写回持久缓存。
- Codex 桌面端启动卡提供「一键关闭」与运行状态。确认后复用已有关闭逻辑，核验安装路径、PID 创建时间及祖先链；保留账户和登录资料。
- IP 纯净度弹窗增加「还没有合适的 IP？可以前往 IPRoyal 选购。」入口，地址由后端既有 `PurityCriteria.iproyal` 提供。
- 原「面板自测」默认持续显示本机出口及住宅 / 家庭 IP 判断，「检测本机 IP」和一键全面体检仍查询本机，输入框有值也不会改变这两者的对象。标题栏可选输入 IPv4 / IPv6 后点「查询指定 IP」，IPQuery 结果追加在卡片下方，不覆盖本机读数；返回 IP 必须与请求匹配。
- 指定 IP 查询结果只展示在独立区域，不写入当前出口、门禁、人工复核进度或综合评分；住宅/原生属性不通过「未标记机房」推断。
- IP 纯净度弹窗标题右侧增加「禁用 IPv6」开关，默认开启、启动应用；关闭时恢复各网卡原值，退出面板保留状态。原值在请求管理员权限前持久保存，失败、重启、网卡移除不会丢失恢复依据。实际状态始终可见，详情和恢复操作在小入口展开。
- 删除「为什么面板不直接给结论」说明框和自动检测无法取得的原生 IP 项；指定 IP 查询不再占用额外卡片，不显示无法取得的住宅/原生占位项。
- 范围为本机网卡绑定（包含隐藏、虚拟网卡），不修改注册表的待重启配置，不宣称移除 Windows 内部 IPv6 回环。检测读取实际绑定状态；没有网卡或读取失败均不当作已禁用。
- 修改期间的门禁查询会失效，迟到结果无法重新写回已作废的门禁缓存。启动时先重建执行锁，再应用 IPv6，最后恢复租约与监督，避免 UAC 等待期间提前放行。

## 数据源核对

- [IPPure 官方接口文档](https://ippure.com/MyIP-Info-API.html)描述的是调用者的出口 IP，未提供指定任意 IP 的参数。因此原有出口检测继续使用 IPPure，新地址另走 [IPQuery 官方公开接口](https://ipquery.io/)。
- IPQuery 文档提供 `GET /{ip}`、0–100 的 `risk_score` 和风险标记，并说明公开 API 无需 Key、允许商业集成。
- 两家的分数口径分开标注，不把 IPQuery 的风险分当成 IPPure 系数或套用其通过阈值。
- IPv6 使用 Windows 的 NetAdapter 绑定命令，参照 [Microsoft IPv6 配置说明](https://learn.microsoft.com/en-us/troubleshoot/windows-server/networking/configure-ipv6-in-windows)。修改可能影响依赖 IPv6 的系统功能，界面在开关旁说明范围和代价。

## 开源分发与不同电脑环境

- 运行代码不绑定开发者用户名、仓库位置或网卡名称；安装位置取系统安装信息、当前用户目录、PATH 和用户指定的托管目录。
- Codex 桌面端按官方 Store 包身份定位，动态读取安装目录和版本；不会按进程名关闭其他软件。非 Store 发行形式暂不宣称支持。
- IPv6 按稳定实例 ID 修改单张网卡，网卡重命名及名称含中文、空格、单引号、通配符不参与命令拼接。备份放在当前用户的应用数据目录。
- 安装版不要求用户安装 Node、Rust、Visual Studio；NetAdapter 能力或权限不足时显示错误，不伪报成功，并允许关闭自动禁用设置。
- 临时目录回归覆盖中文、空格、单引号、方括号和自定义安装根目录，以及定位/启动/门禁清单一致性。其他既有回归覆盖原生安装、用户级/机器级 winget、Scoop、npm、PATH、编辑器及桌面端副本。
- 尚未在另一台干净 Windows 机器上实测；自动回归不能代替不同 Windows 版本、网卡驱动和权限策略的验收。

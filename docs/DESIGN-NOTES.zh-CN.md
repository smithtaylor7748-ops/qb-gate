## 0.25.4（2026-09-25）：中转站的倍率 —— 先换成同一种单价、同一种钱，再比

使用者转来 linux.do「中转站百科第一集」（`2504277`），要对照项目里的倍率算法。帖子讲的是三层：
**官方美元标价 → 「1 美元额度 = 几元」的充值比例 → 分组倍率**。「1 元 = 1 美元」本身已经约打了 1/7 折，
分组倍率是在那之上的进一步折扣；充值按 7 元一美元的站，标出来的倍率会显得便宜 7 倍（帖子叫它「倍率陷阱」）。
对着这三层查，面板错了四处，根子是同一个：**比较之前没把两边换成同一个单位**（跟 0.25.2 订阅页那次一模一样）。

### 一、New API 的 `model_ratio` 是单价，不是「官方的几倍」

它的单位写在 New API 源码里：`1 === $0.002 / 1K tokens`，默认表 `"gpt-4o": 1.25, // $2.5 / 1M tokens`；
它自己的定价页算单价也是 `model_ratio * 2 * groupRatio`（`web/src/features/pricing/lib/price.ts`）。
照官方价原样抄进后台的 Opus 5（$5 / $25）因此是 `model_ratio 2.5`、`completion_ratio 5` ——
面板把 2.5 读成「官方的 2.5 倍」、把 5 读成「输出翻 5 倍」，查套路报告里写着「输入 2.500×、输出 12.500×」。

使用者那句「New API 的倍率算在了单价内，所以单价便宜」说的也是这件事：站长可以把折扣放在分组上
（倍率 2.5、分组 ×0.2），也可以直接压低倍率（0.5、分组 ×1）。两种都只有**先换成单价、再除官方单价**
才读得出来 0.2；原始倍率一个是 2.5、一个是 0.5，哪个都不是 0.2。
所以 `category_prices()` 现在两种后端都给单价（New API 乘 `NEW_API_USD_PER_MTOK`），
`category_ratios_against(official)` 一律是「单价 ÷ 官方单价」。原来那个 `category_ratios` 改名 `newapi_ratios`，
文档第一句就说它不是倍数 —— 这个名字本身就是误读的入口。

⛔ **这不是 0.16.0 那条「官方价被约掉」回来了。** 那一条是拿站点倍率乘**官方价**凑站点单价、再除回官方价；
这里乘的 2 是 New API 源码写死的单位，`category_prices()` 的签名里压根没有官方价。
`the_official_price_never_goes_into_the_station_price` 钉着：只改官方价，单价不动、倍率跟着变。

### 二、「翻倍 ×5」是每一条正常线路都会挂的误报

`completion_ratio` 是「输出价 ÷ 输入价」，New API 给 Claude 写死 5、给 GPT-5 写死 8 —— 就是官方自己的价格结构。
原来的判断是 `> 1` 就挂黄标，于是照官方价收费的 Claude 线路全都挂着「翻倍 ×5」。
真正想抓的是「标一个低倍率、再把补全倍率调高」的站 —— 那要跟**官方的**输出 ÷ 输入比
（`StationRates::output_markup`）。前端手里没有官方价，所以检验时在后端算好、存在线路的 `output_markup` 上。

### 三、分组倍率一直在 `/api/pricing` 的顶层，只是没人读

KNOWN-ISSUES 写着「`/api/pricing` 不返回 `group_ratio`」。它返回，只是不在 `data` 那一行行里，
在响应的**顶层**（`controller/pricing.go`：`"group_ratio": groupRatio`，登录后还是按这个账号调整过的那一份）。
没读到的后果在调度里：加权比价拿「原始倍率」直接加权、分组 ×1 —— 同样照官方价抄、分组 ×0.2 和 ×0.8 的两条线
加权出来一模一样，而这一口径在整池都有 token 结构时**排在真实倍率前面**。

读上了之后还有一条：**分组倍率不知道的线路不参加加权比价。** 折扣大多就在分组上，不知道它就不知道价；
按「不打折」算出来的是牌价，跟别家的折后价放一起比等于冤枉它。整池退回真实倍率那个粗口径 —— 粗，但单位是对的。

### 四、跨站比较先折成同一种钱：每个站点一格充值比例

账单、倍率都是按站内额度记的。同一个「×0.1」，1 元一美元的站是每 $1 牌价 0.1 元，7 元一美元的站是 0.7 元。
使用者选了「每个站点加一格」（问他时的另一个选项是只写进说明）。放在站点（`Provider.topup_per_usd`）而不是线路上：
它是账号级的充值价，整站共用，放在线路上会在几条线路之间各填一份、迟早对不上。

- `station_ops::decide` 把「便宜」的三种口径（实扣单价、加权倍率、真实倍率）都乘上各自站点的比例再比；
- 「倍率不超过」底线原来比的是「便宜」那一维的值 —— 整池走实扣单价时那是 1e-6 量级，底线等于没设。
  现在 `Candidate` 多一个 `real_rate` 专给底线用（真实倍率，没有就退回加权倍率，都折过）；
- **查套路不折算。** 那一步问的是「这家站收的跟它自己说的对不对得上」，两边都是站内口径，比例约掉了；
  使用者 09-18 那句「不用管货币单位」管的就是这里。
- New API 在 `/api/status` 公布的 `price`（后台「充值价格」，它自己的定价页叫 `priceRate`）只做成参考按钮。
  默认值就是 7.3，很多站没改过、实际靠兑换码按 1 元卖 —— 自动采用会把这些站冤枉贵七倍。

### 订阅页计算器：额度按分组倍率扣

「中转站给你 $100 额度 → 实际倍率 = 付的钱 ÷ 100」漏了一项：站内额度是按分组倍率扣的，
分组 ×0.2 时每 $1 牌价的用量只扣 $0.2 额度（帖子：「输入 5 元，给你倍率 0.1，那么实际就是 5 × 0.1 = 0.5 元」）。
加一格「那条线路的倍率」（默认 1，包月按牌价扣的留空就对）。计算器的主算式跟两个帖子（`2504277` 的
1400 ÷ 6000 = 0.23、`2772890` 的 1200 ÷ (2400 × 4) = 0.125）是同一个：花的元 ÷ 每月能用出的美元额度，没动。

## 0.25.4（2026-09-25）：一键汉化 —— 跟上游的脚本走，但只信文件

使用者一轮提了三件：GPT 一键设中文；Claude 以插件形式装载 `javaht/claude-desktop-zh-cn`，上游以后的更新要跟得上、
插件商店能同步；两处都要符合两家的使用政策。几个取舍，每一个都有一条更顺手、但会出事的反面：

| 取舍 | 反面为什么不行 |
| --- | --- |
| **GPT 写它自己的设置项**（`[desktop] localeOverride`，在它设置里选中文写下的同一行） | 注入翻译 / 改 app.asar：OpenAI 条款不许 modify 它的服务；而它本来就有中文，只是面板起的每个槽位都是一份新资料、默认英文 |
| **Claude 跑上游自己的脚本，不照着抄一份** | 抄进来的是某一天的快照。上游平均一周一版，Claude 一改前端结构它就改正则与替换表 —— 抄的那份从那天起就在变旧，「后续更新可以匹配」做不到 |
| **只跑安全模式，而且改前改后比对 app.asar / claude.exe 的哈希与签名状态** | 只靠「参数里写死 safe」是在信上游：它哪天把安全模式也改成会动 app.asar，参数一个字没变、越线却发生了。比对文件是结构性的，不管上游怎么改都守得住 |
| **不走反重力那套 CDP 注入** | Claude 桌面端见到 `--remote-debugging-port` 就拒绝启动（有意的保护）。上游的 Frida 模式就是绕过这道检查 —— 那正是条款不许的那一类 |
| **zip 自己读、先挑再解**（`install::zipread`） | `.NET ZipFile` 整包解开会把上游仓库里的 Frida 脚本也落到使用者机器上 —— 面板永远不调用它们，落盘只多一份杀软信号 |
| **查新版只问 `releases/latest` 的跳转** | `api.github.com` 未登录一个出口 IP 一小时 60 次，共用 VPN 出口的人会撞上（同 0.25.3）；归档注释里就有提交号，也不用为它去问 API |
| **别的账户资料的 locale 只改那一个值的字节** | Claude 的 `config.json` 里有登录令牌缓存；整份解析再序列化会重排键，等于把令牌读出来又写回去 |
| **门禁用 `judge_now` 只判不解锁** | 上游脚本最后会用 `app-*\claude.exe` 自己重启 Claude，那份按规矩不能加 Deny；拿租约解锁没有意义，判不过就不做才是那条线 |

还有一处要记：上游脚本收尾时用 `explorer.exe` 异步起 Claude，脚本退出那一刻它多半还没进进程表 —— 面板等它出现再关，
不等的话「一个都没关到」会被当成「没起」，留下一份不归面板管的 Claude。

## 0.25.3（2026-09-24）：应用自己的更新 —— 问一个小文件、核同一个发布里的哈希、先退出再装

使用者：「我 GitHub 上上传了新版本，已经安装老版本的用户打开软件时（弹窗）收到更新通知，还有一键更新功能」。
四个取舍，每一个都有一条更顺手、但会出事的反面：

- **问 `releases/latest/download/update.json`，不问 `api.github.com/…/releases/latest`。** API 那条最省事（版本、说明、
  附件地址一次拿全），但未登录一个出口 IP 一小时只给 60 次 —— 这个面板的使用者几乎都在共用出口后面，同一个出口上
  别人把额度用完，他的检查就永远 403，症状是「从来没收到过提醒」，谁也查不出来。附件走下载服务器，不吃这个限额。
  代价是发版要多生成一个文件（`scripts/update-manifest.mjs`），而说明正好借这个文件管起来：弹窗里显示的与 Release 正文
  同出一份 `.github/release-notes.md`，版本号对不上 `release:check` 就红。
- **验真用同一个 Release 的 `SHA256SUMS.txt`，没用 Tauri updater 的签名。** 签名更严（私钥不在 GitHub 上时，拿到仓库
  发布权限也伪造不了包），但要使用者生成并保管一把私钥、自己填进仓库 Secrets；丢了私钥，已装的人就再也收不到一键更新，
  只能手动重装。使用者选了前者。哈希清单挡得住下载损坏、中间人换包，挡不住发布权限被拿走 —— KNOWN-ISSUES 写了。
  另外核一处：清单里固定名那份与带版本号那份的哈希必须一致，否则固定名指着的不是这一版。
  `update.json` 里**没有地址也没有哈希**：地址按常量拼（只接受核过的 `v<三段数字>` 标签），哈希只认 `SHA256SUMS.txt` ——
  一份文件同时说「去哪下」和「下来应该是什么」，改它一处就能让面板装任何东西。
- **先正常退出、在退出处理的最后一步才启动安装包。** Tauri 的 NSIS 安装包在 `/P` 被动模式下发现程序在跑，直接
  `KillProcessCurrentUser`，不问（CLI 2.11.4 内嵌模板的 `CheckIfAppIsRunning`）。「起安装包 → 自己退出」看着顺手，
  实际是跟安装包赛跑：输了的那次面板被强杀，退出处理的重锁没跑，执行锁停在杀之前的样子。所以一键更新只把核过的
  路径记下来、`app.exit(0)`，`RunEvent::Exit` 里重锁完再 `launch_pending()`，启动前再算一遍哈希。
  参数 `/P /UPDATE /R`：`/UPDATE` 让安装包跳过「先卸旧版」、不新建也不删快捷方式（中文桌面上 NSIS 建的快捷方式本来就
  会坏，坑 7.5）、不动开机自启项；`/R` 装完以使用者身份把面板重新打开。
  面板自己可能落在别人的 Job 里（从 Claude 桌面端的终端起的），先带 `CREATE_BREAKAWAY_FROM_JOB` 起，被拒再普通起。
- **只提醒、不自动装，也没有定时器。** 面板一退出，它起的会话跟着 Job 全关（坑 7.38），「后台静默更新」等于在使用者
  写到一半时关掉他的对话。启动时问一次、设置页手动问，够了；代价常驻在「一键更新」按钮上方。

演示模式那一半：弹窗是全局的，启动那一次要是在演示里「查到」新版，`test:ui` 的 151 个组合就全被它盖住。
所以演示里只有设置页的「检查更新」会「查到」编出来的 0.99.0，`test:ui` 单独走一段流程看它。

## 0.25.2（2026-09-24）：DNS 泄露的评分 —— 问「这条查询从哪张网卡出去」，不问名字、不问地址

使用者：「合理化分数评分机制，只连 wifi 就不需要其他的评分了吧」。原来 100 分 = 以太网安全 50 + 无国内 DNS 30 + 证据完整 20。

- **按名字找「以太网」是写死本机事实。** 只连 Wi-Fi、系统不是中英文的机器，那 50 分永远拿不到 —— 这是开源兼容性那一条
  最典型的样子：在作者那台插着网线的中文系统上它工作得好好的。
- **按「地址是不是内网」判也不对。** 本机实测：xray 的 TUN 把有线网卡的 DNS 改成了隧道网段里的 `172.18.0.2`，
  `Find-NetRoute` 说这条查询走 `xray_tun` —— 这正是防泄漏的**正确**配置，却被报成「指向内网」。反过来，断开的 WLAN
  上还挂着路由器的 `192.168.10.1`，网卡根本没连着，也被扣分。本机按旧规则 50 / 100、两条都是误报。
  所以改成直接问路由：**连着的**物理网卡上配的 DNS，查询从隧道出去就是安全的，从物理网卡直接出去才是缺口
  （Windows 会同时向每张网卡的 DNS 发查询，那一路就绕过了隧道）。
- **没开 TUN 时这一项不适用**，而不是「全都不走隧道所以全扣」—— 没有隧道就没有可绕的边界，那时是不是泄露只有回显说得清。
  「开没开」问的是发往 `203.0.113.1`（RFC 5737 文档段）的路由：不用 1.1.1.1 / 8.8.8.8，代理常给这几个 DNS 单独配 /32，
  量到的就不是默认路由了。
- **70 / 30**：回显里有国内解析器是实测到的泄露，网卡配置只是「可能」—— 隧道软件拦不拦得住，回显说了算。
  不适用的那项从分子分母里一起去掉（跟 `score.ts`、出口一致性同一条）；没有回显时分数是「—」，不是 0。
- **「证据完整」20 分删了。** 它给的是「有没有数据」：一台真泄露的机器照样白拿这 20 分。没有回显时 `score.ts`
  本来就把整项拿出总分，这 20 分没有任何一种情况在说安全的事。
- **旧报告要作废。** DNS 结果是存盘的（`persist`），升级后旧报告还会被读出来；它的分数按旧规则算，认法是没有
  `adapters_note` 字段 —— 不进总分，界面请使用者重测。没有给存盘加版本号：只有这一处要作废，加一套版本机制不值。
- 读网卡的 PowerShell 跟解析器是一对，抽成 `adapter_script()`，单测钉住输出格式的那几个片段；
  实机把 Rust 拼出来的那一串原样跑过一次（`#tun 1`、有线 `连着 / 走隧道`、WLAN `断开`）。

## 0.25.2（2026-09-24）：订阅页的倍率按 1:7 折成元 —— 一页两把尺子

使用者圈着价目表的「等效倍率」：「按人民币折算（1：7）」「还要标注 1:7，以及这个是按贵的折算的，一般来说 6.8 左右」，
随后拿计算器算出 0.1 来问「为什么是 0.1」。

- **两把尺子。** 中转站的倍率是站内标价相对牌价的倍数，而站内额度是拿元买的 —— 常见 1 元 = 1 美元额度，
  于是 1× 实际是「每 $1 牌价的用量付 1 元」。官方那一列却是 `$20 ÷ $1,400`，美元除美元，比中转站的尺子小 7 倍；
  计算器汇率填 1 时算的是元除美元，所以同一档 Claude Pro 在表里是 0.014×、在计算器里是 0.1×。
  使用者要的 1:7 就是把官方这一侧换到中转站那把尺子上。
- **为什么是 7、不是实时汇率。** 使用者定的，往贵了取：官方显得贵一点，结论只会更保守。实际一般 6.8 左右，
  这个数只进说明文字（「按实际汇率倍率再低约 3%」，由两个常量算出来，不写死百分比）。
- **计算器去掉「汇率」。** 倍率的单位本身就是「元 / 美元牌价」，金额按元填就够了；留着汇率，同一笔钱
  填 1 和填 7 会得出差 7 倍的两个倍率 —— 正是使用者撞上的那种。付美元的人按提示先乘 7。
- **结论跟着数改。** 按 1:7，官方各档 0.07×～0.292×，跟逆向中转（0.05×～0.3×）重叠 —— 逆向中转卖的本来就是
  别人的订阅，重叠是应该的。所以「比任何中转站都便宜」「比最便宜的逆向中转还低」都不成立了，改成实际位置；
  页面要说的理由从「便宜得多」变成「一个价，但账号是你自己的、没有那六条坑」。颜色也只按价钱说话：
  原来 0.05～0.3× 是黄的「逆向中转的价位」，按 1:7 官方各档全落在里面，再用黄色就等于把官方标成可疑。
- **腾讯云那篇原文只说「倍率 1 = 同价，0.8 = 八折」，没说充值比例。** 所以官转那条写成「站内标价是牌价的
  0.8～1.5 倍；按常见的 1 元 = 1 美元额度充值……」，不替原文说它没说的话；按真实汇率充值的站怎么换算写进 KNOWN-ISSUES。
- **「元」而不是那个词。** 订阅页「不提特定国家、货币」是使用者早先定的，测试按渲染出来的文字盯着一串词。
  这次是使用者点名的例外，只放开到够用为止：页面上写「元」。
- **一个数只许有一处算。** 价目表、刻度条、首页两格、计算器原来各自调 `effectiveMultiplier`，这次换口径要改四处，
  漏一处就又是一页两个数 —— 收成一个 `planMultiplier`，测试把每一档渲染出来的数钉住。
- 顺手：0.0875（$200 × 7 ÷ $16,000）在二进制里略小于 0.0875，`toFixed(3)` 给「0.087」，读者心算是 0.088；
  格式化改成四舍五入进位。

## 0.25.2（2026-09-24）：用量的美元、柱状图、CheckClaude 三组 —— 为什么这么写

使用者：用量卡「1 条回复、全是 0」看着不准，要 cc-switch 里有的数据面板也有、「要看见每天、7 天、30 天花了多少刀」、
趋势图不好；环境监测对照 zzusec/CheckClaude（MIT）补。

### 一、美元：从「只给缓存省下」改成「按官方 API 价折算」

0.25.1 之前 `token_summary` 头上写着「这里的美元是缓存省下的，不是你花了多少」—— 订阅账户按 API 单价折出来的总额
不是账单，摆出来怕误导。使用者这次要的恰恰是这个数（cc-switch、ccusage 的主数字都是它），所以口径改成：
**同样的 token 走 API 要付多少**，并且「订阅不按这个收费」这句话**跟数字放在一起**（卡片页脚、用量明细页的标题下），
不藏进悬停。误导的风险在于把它读成账单，不在于数字本身 —— 说清楚就够了。

「今天 / 7 天 / 30 天」三档（`TokenSummary.spend`）**不随选中的档位变**：使用者要同时看见三个数，而为此发三次请求、
每次整遍扫描转写不值得 —— 桶已经在手里。

### 二、缓存写要分两档记

`cache_creation_input_tokens` 是合计；`cache_creation` 里分 5 分钟档与 1 小时档，官方价差一截（输入 ×1.25 对 ×2）。
实机那一天 633 条回复的缓存写**全是 1 小时档**。价目表原来只存 5 分钟档（官方表里 1h 那一列解析了就丢），
按它算这一块少 37.5%，而界面上看起来跟真的一样。现在 `TokenBucket.cache_write_1h` 单独记，`ResolvedPrice.cache_write_1h`
单独给价：官方标了用标的，没标（库里旧行、内置快照）按官方倍数推并标「推」。中转站那套四类判定（`PriceCategory`）不动 ——
它比的是站点报价，跟这件事无关。

### 三、报错不算回复

`<synthetic>`（`isApiErrorMessage`）那种行也带 `usage`，只是四类全 0。截图那一刻 main 槽位今天只有一条「请重新登录」，
被数成「1 条回复」而 token 全是 0 —— 读的人只会觉得统计坏了。四类全 0 的不入账，但**单独数出来**（`empty_replies`，按天）：
不瞒，也不冒充用量。cc-switch 的「任一计费维度 > 0 才导入」是同一条。

### 四、去重：留最完整的一份，不是先见到的那份

键不变（`message.id:requestId`）。cc-switch 实测过一种形状：子代理的短请求先写一行 `message_start` 那一刻的快照
（输出 1、没有 `stop_reason`），后面那行才完整。按「先见到的」留，留下的正好是快照。现在按
「有用量 > 带 `stop_reason` > 输出大 > 读写大 > 时刻早」挑；这台机器上 490 个多行的键没有一个用量不同，所以对现有数据无损。

### 五、「按账户」：默认目录只扫一遍

切过账户的那天，量分在两个账户上（截图那天 02:30 之前是 ture、之后是 main），只看当前账户的卡会以为「今天几乎没用」。
`tokens::scan_all_slots` 把默认目录只扫一遍、每份转写只判一次归属，分给所有槽位；归不出主的、归到面板以外账户的各一行，
不摊给任何人。账户卡仍走单槽位的轻量路径（每分钟一次，不带明细）。

### 六、柱状图：单色、单轴、没记录的日子不画柱

- 形状按 dataviz 的规矩：一个系列就一个颜色、不要图例；柱宽封顶 24px、顶端 4px 圆角；网格线 1px 实线；
  y 轴取整刻度；只直接标最高与今天两根（每根都标等于一根都没标）。
- **没记录的日子不画柱、提示框写「没有记录」**，不画 0 高的柱 —— 跟 Sparkline 那条「断开，不连到 0」同一个理由。
- 美元 / Token 是切换，不是双轴。
- 手写 SVG，没加 recharts 之类的依赖：一张柱状图不值得多一个包的许可、体积与 `cargo deny` / 第三方声明的负担。
- 深色主题不直接用 `--accent`：它的亮度超出深色图表的亮度带，大块柱子发白；同色相挑了一档校验脚本过的色。

### 七、日期不许经过 UTC

`new Date("YYYY-MM-DDT00:00:00").toISOString().slice(0, 10)` 在 UTC 以东给的是前一天 —— 东八区的使用者整张趋势图错一天、
今天那格掉出去。作者机器在 UTC−4，恰好对。`lib/dates.ts` 一律按本地年月日构造、按本地日历加天（夏令时那天也不多不少），
vitest 在 Asia/Shanghai 和美东夏令时结束那天都钉着。后端切天也是本地时区（`tokens.rs`），两边口径一致。

### 八、环境：选了哪三组、各自怎么判

- **服务可达**：不带任何凭据 POST `api.anthropic.com/v1/messages`，401 = 地区放行、403 = 地区拦截。这是整个体检里
  唯一一个「Anthropic 自己的回答」，别的都是间接信号。不带身份、不花钱。claude.ai 前面有人机验证，
  带 `cf-mitigated` 的 403 说明不了地区，只算「查不出」。
- **claude.ai 的解析**：系统解析器（跟 Claude Code、浏览器同一个）解出来落在哪一段。内网 / 回环 = 被污染（关键项）；
  认不出的公网段只警告 —— 也可能是代理用了自定义 fake-ip 段。地址段（Anthropic 公布的、Cloudflare 公布的）是全世界
  一样的常量，不算写死本机事实。
- **代理形态**：原来只读 `ProxyEnable`，PAC 开着也说「系统代理没开」。现在读 PAC 与自动检测，再看默认路由挂在哪张网卡：
  **按 `HardwareInterface` 认隧道，不按名字** —— 本机叫 `xray_tun`，别人的叫 `Clash`、`Meta`、`wg0`。
  Hyper-V 的虚拟交换机也是非硬件网卡，但那是宿主机自己的网，排除。DNS 泄露里那条按名字认 `tun` 的一起换了。
- **IPv6 看真实出口**：只用只有 AAAA 的回显服务（双栈域名在没有 v6 时会退回 v4，得出错结论）；有 v6 出口再查国家、
  跟 IPv4 比。原来「网卡开着 IPv6 就警告」—— 很多宽带根本不给 v6，开着也漏不出去。

### 九、真实浏览器采集的边界

「中文环境」原来在面板内置的 WebView2 里测，那不是使用者登 claude.ai 的浏览器。做法照 CheckClaude 的 BrowserBridge：
127.0.0.1 上开一个一次性小服务、默认浏览器打开、采完就关。几条边界都是故意的：

- 端口让系统挑（`:0`），路径带随机令牌，校验 `Host`（挡 DNS 重绑定），静态资源只给 `assets/` 下的构建产物；
- 只收一份 ≤64 KB 的 JSON，收到就关监听，120 秒没人交回也关；
- 结果只放进程内存，不落盘、不进日志 —— 语言、时区、WebRTC 地址都算个人信息；
- 页面跑**同一份** `signals.ts`（Vite 第二个入口 `probe.html`），分数回到面板按同一张权重表算（`scanFrom`），
  交回来的东西当不可信数据逐项校验；
- `qb-app` 不认识 Tauri：页面从哪来由 `AssetSource` 决定，`src-tauri` 用内嵌资源实现（开发模式下 Tauri 自己退回读 `dist/`）。

请求头里的 `Accept-Language` 与 WebRTC 候选地址是出口一致性那两行最该用的实测值：一小时内有报告就换成实测，
没有就退回读 Chrome 的配置 / 策略。

### 十、关键项封顶

加权总分会把致命问题摊薄：API 回 403 只占「出口一致性」10 分里的一行，总分照样可以 95、档位照样「良好」。
四个关键项（API 403、claude.ai 被污染、IPv6 出口在别的国家、实测 WebRTC 泄露）任一失败，档位封顶「偏差」并点名；
**权重表不动**，总分照实 —— 封顶只改结论，不改各项拿了多少。

### 十一、没做的

- 三路出口（国内 / 国外 / 被墙网站三个视角的出口 IP）：使用者这轮没选。
- 24 小时出口稳定性：这个项目的定位就是「工作需要频繁换 IP」，拿跳变次数扣分跟定位打架。
- 虚拟机检测：开了 Hyper-V / VBS 的物理机也会被认成虚拟机，误报多、价值低。
- 四家情报 + ASN、边缘机房：已有三家国家互核；CheckClaude 的「边缘机房」比的其实是 Cloudflare 的 `loc`，已经在用。
- 一键改 DNS / 关 PAC：会改网络配置、可能当场断网，按 `checkup.rs` 文件头的规矩只给命令和代价。
- Claude 额度联网（cc-switch 的 `/api/oauth/usage`）：使用者选了保持只读本机。

## 0.25.1（2026-09-23）：GPT / Gemini 登录态 —— 到点、失效、别人的窗口，是三件事

使用者：「GPT 和 Gemini 的登录态对着那个开源项目（cockpit-tools）修一下，因为 GPT 有时候突然弹出
第二个使用页面」。对照它的 Codex 账户与多开代码（只读行为事实），面板原来把三件不同的事混成了一件。

### 一、「访问令牌到点」不是「登录失效」

两条联网额度都拿本机那张访问令牌直接问。过期了服务端回 401，界面就说「登录令牌已失效，请重新登录」。
可访问令牌本来就会到点（Gemini CLI 一小时，Codex 若干天），刷新令牌还在，官方客户端下次跑起来
会自己换新 —— 登录好好的。让人去「重新登录」，既是错的，也是那个多出来的登录页的来路之一。

cockpit-tools 的口径：额度只依赖访问令牌，**只在它真过期时才换新**；不因为 id_token 过期、不按周期保活
去换 —— 每多换一次，OpenAI 那边就多轮换一次刷新令牌。

### 二、为什么 Gemini 换、GPT 不换

| | Google（反重力、Gemini CLI） | OpenAI（Codex） |
|---|---|---|
| 刷新令牌换新之后 | 不作废，官方客户端手里那份照样能用 | **作废**（每换一次就轮换） |
| 面板在内存里换一张 | 安全 | 官方客户端手里那份立刻作废，它下次换新时被登出、弹出登录页 |
| 所以 | 换，只放内存、不写回（`google_oauth`） | **不换**；看 JWT 的 `exp`，到点了说「开一下桌面端它会自己换新」 |

GPT 也可以「换了再写回 `auth.json`」—— cockpit-tools 就是这么做的，但它的前提是自己在管理那些账户的
令牌、并且能判断官方客户端此刻有没有在用。QB Gate 的 GPT 槽位是官方客户端在自己的目录里登录、自己保管
令牌，面板往里写一次，就多了一个跟官方客户端抢同一族刷新令牌的人 —— 0.24.7 放弃「复制 OAuth」
的分身环境，就是因为两份 Codex 各自轮换同一族令牌而互相登出。

### 三、「登录已失效」要有来源，而且要能自己消失

列槽位只看令牌在不在，说不出「服务端还认不认」；那只有点刷新时问一次才知道。`login_health` 记下那一次
明确的拒绝（Gemini 的 `invalid_grant`、GPT 没到点的 401），让账户行上那一半改口、露出「登录」。

它按**凭据文件的修改时刻 + 长度**记，而不是按令牌内容：一来列槽位这条路本来就不读凭据内容；二来官方客户端
一重新登录、或者自己把令牌换新了，文件就变 —— 这一笔自动作废，不需要谁记得去清。代价是它只在内存里，
面板重启就忘，要再点一次刷新才会重新发现。

### 四、「第二个页面」：别人的 Codex 窗口不是我们的

起 / 切 GPT 槽位之前原来按 exe 路径把所有 Codex 桌面端都关掉。那是照「单实例」写的，可 Electron 的单实例锁
按 `--user-data-dir` 算：面板给槽位的是它自己那份资料，默认实例挡不住它，关它没有必要；而关掉它的代价是真的
—— 起它的那个程序（多开工具、`codex://` 链接、商店更新后的重启）会再把它拉起来。于是在使用者眼里，面板每起
一次槽位，旁边就「突然弹出」一个 Codex。

「哪些是面板的」按资料目录判：面板给的 `--user-data-dir` 都在它自己的状态目录下（槽位、中转环境），
唯一的例外是没有槽位时退回的 `~\.codex\desktop`。读不出命令行的实例当成别人的 —— 宁可多开一个窗口，
也不把认不出来的当成自己的去关。「一键关闭」是使用者明说要全关，照旧全关。

## 0.25.1（2026-09-23）：官方账户菜单栏 —— 「看哪一边」只能有一个说了算

### 一、列表的 key 不许拿路由当

快速跳转里好几条会跳到同一个地址：「官方账户」那一项和每个账户都是 `/`。
path 回答的是「点了去哪」，不是「这一条是谁」。拿它当 key，React 对不上号，
过滤之后旧项留在列表里 —— 看上去像「搜索坏了」，其实每一条的数据都是对的，错的只是对号。
所以每一类结果带自己的前缀（`ext:` / `nav:` / `claude:` / `gpt:` / `antigravity:` / `provider:` / `env:`），
**以后往这个列表里加一类，先给它一个前缀。**

它能在 `test:ui` 里一直全绿，是因为那一圈只收抛出来的异常，而重复 key 在开发模式下只是一句
`console.error`。现在 `watchErrors` 把这句也算页面错误 —— 151 个组合一起替所有列表守着。

### 二、「看哪一边」：会话里一份，地址里一份

侧栏和总览读 `SIDE_KEY`（会话，在内存里）；用量明细读地址里的 `?side=`
（要能从用量卡直接链进来、刷新不丢）。两份各记各的，就会同时出现三句互相矛盾的话：
页面上是反重力、侧栏一项都不亮、「回账户页」回到 GPT。定下来的规则：

- **在 `/usage` 上以地址为准，并把它写回会话。** 那一页显示哪一边，侧栏就亮哪一边，回去就回哪一边；
- **不认识的值一律当 Claude**（默认那一边），不落进「最后一个分支」。`Home` 的三路分支也改成
  「是 GPT / 是反重力 / 其余都是 Claude」—— 原来是「是 Claude / 是 GPT / 其余都是反重力」，
  一个拼错的值就把人带到另一个产品的页面上；
- 侧栏子项在 `/usage` 上点，是「去那一边的账户页」，不是「让明细页换一边」—— 明细页自己有一排切换；
- 「按下」（`aria-pressed`）和高亮用**同一个**条件（`side === s.id && 在官方账户那一块`）。
  两个条件各写一份，迟早一个改了另一个没改：看上去三个都不亮，读屏却报其中一个「已按下」。

### 三、搜到账户只是带路，不切槽位

点搜索结果里的账户，只切「看哪一边」、跳到账户页，**不替你把那个槽位设成激活**。
切槽位有后果（Codex 影响下一次启动用哪份登录；反重力一条账户两半一起切），
跟「账户切换只能人工触发」是同一类动作，得在账户页上自己点。

GPT / 反重力的账户在**搜索框打开那一刻**读一次，不挂轮询：侧栏常驻，为一个偶尔才开的搜索框
挂两路 15 秒的轮询不划算。两路用 `Promise.allSettled` —— 一路读不到只是那一类不出现，别的结果照常。

## 0.25.1（2026-09-23）：联网额度只手动刷新，反重力的「不准」是数据旧，不是算错

### 一、「只手动」为什么落在后端，不只落在前端

最省事的改法是把 `GptBand` 里那个 `setInterval` 删掉。可那样「打开页面就查一次」还在，
酒馆弹窗、反重力用量卡也各自在挂载时查 —— 四个入口各管各的，下一个人加一个新卡片，
顺手写个 `useEffect` 就又回来了。所以命令本身带 `refresh`：

| `refresh` | 后端做什么 |
|---|---|
| `false` | 只读内存里「最近一次」问到的，**这条路径上没有一行联网代码**；没问过就是 `null` |
| `true` | 问一次，成功就记成「最近一次」 |

前端挂载时只能拿到 `false` 那一份，想联网就得有一个人点下去。「最近一次」没有 TTL：
0.32.0 Hub 那条有 5 分钟缓存，那是为了让「打开页面就查」别太频繁 —— 打开页面不查了，
TTL 也就没有意义，界面标明几点问的就够了。

### 二、一行一个图标，一次只问一个账户

原来的「刷新」是账户卡右上角那一颗，一点就对**所有**槽位各问一次。使用者要的是每行一颗、
放在额度条右边（截图里圈的那块空白）。这也顺带把「一次联网 = 一个账户」钉死了：
想看哪个账户就点哪一行，不会因为想看一个而把六个都问一遍。账户卡右上角那颗现在只重读本机。

Claude 那一行也有图标，但**只重读本机** —— Claude 额度只读本机这条没有被推翻；图标长一样，
悬停文字写「不联网」。

### 三、反重力「不准」的根因

账户行读的是 IDE 写在 `state.vscdb` 的 `userStatus`。2026-09-23 只打形状核过：每个模型只有
`15.1` 一个比例、`15.2` 一个重置时刻，**没有 5 小时 / 每周两个窗口**；而且只有 IDE 开着时才写 ——
使用者那个槽位停在 09-21。再加上全是 100% 时 `lowestQuota` 严格小于才换、平局取第一个族，
于是永远显示「Gemini 3.8 Flash 剩 100%」，重置时刻还是两天前算的。**数没算错，是旧。**

cockpit-tools 显示得准，是因为它问的是另一个接口 `retrieveUserQuotaSummary`：按 `bucketId`
给四格（Claude 与 GPT-OSS 一组、Gemini 一组，各有 5 小时与每周），每格一个 `remainingFraction`
与 `resetTime`。`fetchAvailableModels` 里每个模型那个 `quotaInfo` 反而不可靠 —— cockpit 那边观察到
付费账户 33 个模型全是 1、重置时刻跟着 5 小时那一格走，而同一时刻 Gemini 周窗口已经 95%。
所以这里主问汇总，模型清单只在汇总拿不到（免费档回 403）时当兜底。

### 四、为什么不发 `onboardUser`

cockpit 在 `loadCodeAssist` 没给 project 时会发 `onboardUser` 把账户登记到一个档位上，再轮询那个操作。
那是**会改账户状态**的调用，而这里的一切都是「只问」。付费账户不带 project 发 `{}` 也答得上来
（cockpit 自己的缓存里就是这样）。代价写在 KNOWN-ISSUES：从没被登记过的账户可能因此问不到。

### 五、令牌过期时在内存里换新 —— 以及为什么客户端标识不进仓库

访问令牌只有一小时，而且只有官方客户端开着时才换新。不换的话，「只手动刷新」就会变成
「点了多半是 401」—— 使用者不常开的那几个账户恰恰是最想看额度的。使用者拍板换新。

换新要带签发令牌的那个客户端的 id / secret。cockpit 把它们写成常量；这里**不写**：

1. 仓库是公开的，Google 的客户端 secret 进了仓库就是在替 Google 分发它；
2. 反重力一更新可能就换了，常量的过期形态是「所有人都换不了」；
3. 本机装着的反重力里本来就有（IDE 2.5.5 的 `main.js` 里两组），换新的那一刻去读，
   跟「面板替你从官方地址取回官方安装器」是同一个思路：不持有，只在用的那一刻借用本机已有的。

两组里哪一组对应哪个令牌没法事先知道（IDE 的令牌里没有 `id_token`，看不到 `aud`），就按位置配对、
Google 回 `invalid_client` 就换下一组 —— 试错一组没有副作用。认准的只记「哪个文件第几组」。
换来的访问令牌按**刷新令牌的指纹**存：同一个槽位里换了人登录，旧的那张立刻不算数，
不会出现「这一行显示的是上一个人的额度」。

语言服务器一百多 MB，分块读（4 MB 一块、块间重叠 512 字节、留一个回看字节），
单测把前缀长度从 0 挪到 1400、块大小 600，逐个位置切一遍标识，要求一条不丢、一条不重。

### 六、一格没有比例 = 用光了

proto3 的 JSON 映射会把值为 0 的标量字段整个省掉。一格有 `resetTime`、没有 `remainingFraction`，
最可能的意思是「剩 0」。按 0 画，带 `remaining_implied`，悬停里说「Google 没给比例，按用光算」。
这是全模块唯一一处「推」，其余读不出来一律报原因、不显示数。

## 0.32.0 —— 为什么这么写

### GPT 的额度不用联网：它一直写在会话记录里

使用者要「参考那个项目实现 GPT 和 Gemini 的额度」，而那个项目走的是调接口那条路。
动手前先按坑 7.60 那条规矩看了一眼本机有什么 —— Codex 每发完一轮往
`home\sessions\**\rollout-*.jsonl` 追加一条 `token_count` 事件，里面除了 token 数
还挂着：

```json
"rate_limits":{"limit_id":"codex",
  "primary":{"used_percent":2.0,"window_minutes":10080,"resets_at":1790247800},
  "secondary":null,"credits":{...},"plan_type":null}
```

`codex/usage.rs:44` 的 `sample()` 从 0.24 起就只读 `info.total_token_usage`，把同一条
记录里的 `rate_limits` 整个丢掉；全仓库 grep `rate_limits` 零命中。所以这一侧不是
「做不到」，是**没读**。加一个读取器就有了 5 小时 / 7 天两根条，而且零网络 ——
跟 Claude 读 `plan-usage-history.json` 是同一条已有口径，一条规矩都不用动。

两个反直觉的地方写进了测试：

- **要取「最新一条 `rate_limits` 非空的」，不是「最新一条记录」。** 本机 09-18 那两份
  rollout 里 `primary` / `secondary` 整块是 `null`（走中转或 API Key 的会话不带额度），
  翻到 09-17 才有数。取最新一条的话永远读出空，而症状是「这个功能好像没做」。
- **窗口名字按 `window_minutes` 算，认不出来的按分钟如实写。** 硬塞进「五小时 / 七天」
  两个格子里，OpenAI 一换窗口长度，界面上就是一句自信的错话。

### Hub 的邮箱是本机解出来的，配额才需要联网

「反重力软件匹配不到账户」这件事，先当成 bug 查，实机逐个核完才确定不是：

| 看过的地方                                      | 里面有什么                                            |
| ----------------------------------------------- | ----------------------------------------------------- |
| `%APPDATA%\Antigravity\app_storage.json`        | 16 个键，界面布局与引导状态                           |
| `~\.gemini\antigravity\antigravity_state.pbtxt` | 引导步骤、迁移状态、`installation_uuid`               |
| `%APPDATA%\Antigravity\Local Storage`           | 搜不到邮箱                                            |
| `logs\language_server.log`                      | 只有一句 `Auth succeeded`；`SetUserTier` 两次都是空串 |
| Windows 凭据管理器                              | **只有这里有**：一条 `gemini:antigravity`             |

两个产品两套令牌库 —— IDE 里登的账户进不了 Hub，这是事实不是缺陷。

写代码之前先跑了一个**只打印形状**的探针（`antigravity-hub-cred`），结果把方案改了一半：
那条凭据是 1439 字节的 UTF-8 JSON，里面有 `auth_method` / `id_token`(921 字符) /
`token{access_token, refresh_token, token_type, expiry}`，而 **`id_token` 的载荷里直接就有
`email` 与 `email_verified`**。于是「Hub 登的是谁」变成一次本机 base64 解码，**零网络** ——
原本打算为它开的那个联网口子，一半不用开了。

剩下那一半（档位与各模型配额）Hub 确实没写在本机，只能联网问。使用者拍板做，于是有了
全项目唯一一处为额度联网的地方。**分界线是「谁是客户端」**：参考项目把 Google 发给
反重力的 OAuth client_id/secret 硬编码进自己程序、自己跑登录、自己持有与刷新令牌；
本项目不跑 OAuth、不持有任何 Google 凭据，只把 Hub 自己已经有的那份访问令牌原样转发一次。
代价写在 `CLAUDE.md` 与 `DISCLAIMER.md` §6 里，开关默认可关。

⚠ 那次试跑拿到的是 401 —— Hub 的访问令牌一小时过期，而试跑时它已经过期 24 分钟。
**所以响应的真实形状至今没看到过**，解析器是按字段名搜的（层级随时会变），
读不出来时显示原因而不是猜出来的数。这一条记在 KNOWN-ISSUES 里。

### 槽位合并：指路，不搬家

两套槽位合成一条时最容易犯的错是「顺手把目录也整理一下」。§7.33「迁移搬一半」就是
那么来的。所以 `account::migrate` 只做一件事：把老的两份索引各自升成一条新条目，
`ide_dir` / `cli_dir` **指向老位置**。出了事把 `index.json` 删掉就回到原状，
老目录一个字节没动。

更要紧的是**不猜配对**。面板手里没有任何能把「某个 IDE 槽位」和「某个 Gemini CLI 槽位」
对上号的依据：IDE 的邮箱在它的 `state.vscdb` 里，而 CLI 那边**只看 `oauth_creds.json`
在不在、从不读内容**（那是 `gemini` 模块的硬规矩，不能为了配对去破）。猜错就是把两个人的
账户并成一行。所以升上来的是「只填了一半」的行，要合由使用者自己点，而那一步同样只改索引。

顺带一条容易漏的：切换现在**一次动两半**，所以原来挂在 `gemini_switch` 上那道
「酒馆的 Gemini 桥接在跑时不许切」的守卫必须跟着搬到 `antigravity_ide_select`。
留在原处的话，桥接会继续拿着上一条槽位的 `GEMINI_CLI_HOME` 跑，而界面显示的是新的那条。

### 明细为什么从弹窗搬到路由

三个账户页是固定高度、不滚动的（`test:ui` 钉着 680×640 起四档不许裁切）。
0.30.0 把明细塞进一个 `size="wide"` 的弹窗，而弹窗同样受高度限制、还不能翻页 ——
趋势图、按模型分布、覆盖率说明摆不下。搬到 `/usage` 之后那些限制都没有了。

它**不进 `NAV`**（侧栏那六条不动），只从三张用量卡的页脚进来 —— 跟 `/onboarding`
同一种「有路由没导航项」。三个旧弹窗**删掉**了，不是留着并存：同一份内容两个入口，
迟早一处改了另一处没改（坑 7.58）。

`TokenSummary` 为此多了 `daily`。⛔ **它只列真有记录的那几天** —— 补一个 0 进去看上去无害，
但那是在断言「这天没用」，而真相可能是那天的记录读不出来。缺口由画图那一侧留成断口
（`ui/Sparkline` 的 `null`），跟中转站那条曲线同一条规矩。

### 桥接设置为什么非拆不可

0.31.0 它是 `AntigravityBand.tsx` 里一个内联的 `<Modal>` 字面量，靠那个文件的局部 state
驱动。后果不是「不好看」：**只有反重力页开得了它**，而 Claude / GPT 两页的酒馆磁贴上
没有入口 —— 可那两条桥的端口与模型恰恰也在这里改。而同一份配置在插件详情页还有
第二套输入框，两处各写各的。

拆成组件之后四处共用，插件页那三处重复的输入框删掉。留在插件页的只有弹窗里没有的
（推理强度、记入槽位用量）与「不是起之前要调的旋钮」那一类（路径、资产、备份）。

### Claude 桥的两个网页：调它的 HTTP，不嵌它的 iframe

那七个旋钮和那张调用日志表是 `bridge.py` 自己起的两个 HTML 页，由使用者本机那份
SillyTavern 扩展用 `<iframe>` 嵌进酒馆的扩展抽屉。改一句提示词要先起酒馆、进抽屉、
等 iframe 加载；用 GPT / Gemini 聊天时那个 iframe 还指着没人听的 5001（坑 7.66）。

面板直接调它的 HTTP 接口就没有这些问题。唯一要小心的是：**`bridge.py` 是使用者自己那份，
面板不分发**，别人机器上可能是别的版本、甚至根本没有。所以每一条都先探活、错误文案
必须**能照着做**（连不上 = 去起酒馆，404 = 升级 bridge.py，401 = 密钥对不上重起一次）。
内置的模型与 effort 选项是快照，而**桥当前用着的那个值永远算合法选项** ——
不然上游加一个新模型，一打开设置就把人家的模型悄悄换成列表第一个。

## 0.31.0 两个故障，同一个形状：判据写错，而每一层都在报成功

使用者报了两件事：「Gemini CLI 还是下载失败」「酒馆，GPT 和 gemini 启动失败，无法使用」。
两条都不是功能没做 —— 功能全在，**判据写错了**，而且错的那一步之后每一层都在正常工作，
所以谁都没报错。

### 一、位置表猜死了第三方包的内部目录

审计日志里连着两天是同一句：

```text
09-21 02:32:44 Gemini CLI 安装失败：npm 报告成功，而检测仍然找不到 Gemini CLI 的入口文件。npm 最后几行：added 5 packages in 56s
09-21 18:16:11 Gemini CLI 安装失败：npm 报告成功，而检测仍然找不到 Gemini CLI 的入口文件。npm 最后几行：changed 5 packages in 43s
```

`added 5 packages` 就是答案 —— **npm 每次都真的装成功了**。包在
`%APPDATA%\npm\node_modules\@google\gemini-cli`（0.60.0），入口是 `bundle\gemini.js`
（它 `package.json` 写着 `"bin": {"gemini": "bundle/gemini.js"}`）；而
`detect::gemini_cli_candidates` 从 0.26.0 起找的是 `dist\index.js` —— 那个目录**从来没存在过**。

0.29.0 修好 npm 那条命令（把 `cmd /k` 换成 `run_streaming`）之后，症状只是从
「窗口一闪什么都没装」变成「装完了却说没装」。同一张表还喂着
`find_official_gemini`，所以**酒馆的 Gemini 桥接从 0.26.0 起一次都没起来过**。

三条修法各自对应一条一般化的教训：

| 修了什么                                                                                                | 教训                                                                                                            |
| ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 入口改成读包自己 `package.json` 的 `bin`，两种见过的布局只作兜底                                        | **别人的包的内部布局不是你能假设的东西。** 它自己声明了入口，就去读那个声明                                     |
| 包目录不再只认 `%APPDATA%\npm`：`NPM_CONFIG_PREFIX`、`%ProgramFiles%\nodejs`（nvm-windows / MSI）一并查 | 「开源兼容性」那条规矩 —— npm 前缀是别人机器上最容易不一样的东西之一                                            |
| 报错带上「找过哪些路径」（`gemini_cli_searched`），另加诊断例子 `gemini-resolve`                        | **「没找到」三个字不构成线索。** 位置对不上这类错在代码里看不出来，只有把候选路径跟盘上的真实位置并排放才看得见 |

版本读取顺带修了一处同源问题：原来从入口往上数两层取 `package.json`
（`dist\index.js` → `dist` → 包目录）。`bin` 可以指向包根下任何一个文件，
数层数迟早数到别人的 manifest 上。现在包目录是已知的那一个，不靠数。

### 二、等待上限比真实启动还短，超时还把它杀掉

GPT 那次的日志：

```text
02:43:49 已放行 sillytavern
02:43:49 酒馆 GPT 桥接已起：127.0.0.1:5002，槽位「free」
02:44:57 已上锁 20 个可执行文件
02:44:57 酒馆 GPT 桥接已停（127.0.0.1:5002）
```

**68 秒** = 等满 60 秒 + 回滚。桥接起得好好的，死在下一步。

实机量了一次：SillyTavern 自带的 `Start.bat` **每次都先跑一遍 `npm install`** 校验依赖
再 `node server.js`。依赖全热（npm 只花 2 秒）时，从起进程到 `GET /` 回 200 + `text/html`
用了 **47.2 秒**；冷启动（当天第一次、npm 要联网、杀软在扫 449 个包）远不止。

60 秒正好卡在这条线上，而超时走的是 `StartAttempt::drop` 的回滚 ——
**把这次起的酒馆一并收掉**。于是每点一次「起 GPT 酒馆」，就把上一次正要起来的那份掐掉一次；
重试非但不帮忙，反而保证了它永远起不来。

修法三条，第三条才是关键：

1. 窗口 60 → **180 秒**。它是上限不是等待时长，起来了立刻返回 —— 调大不拖慢任何正常启动；
2. 等待期间每 4 秒把「已等 N 秒 / 最长 180 秒」刷到界面上。一声不吭地等三分钟跟卡死没有区别；
3. **等超了不杀**：进程还活着就从 `attempt.created` 里摘掉，如实说「它可能还在装依赖，
   起来之后再点一次会直接复用」。

> **回滚是对的，但「等超了」不等于「它坏了」。** 把一个还在正常启动的东西当失败清掉，
> 就是在主动保证它永远起不来。有单测钉着窗口不许调回 150 秒以下，注释里写着那 47.2 秒是怎么量的。

### 三、顺带修掉的两条同族

- **`tavern_healthy` 少了 `.no_proxy()`。** `bridge_healthy` 写了，它没写 —— 两处隔了一百行，
  一眼看不出少了什么。reqwest 默认读 `HTTP_PROXY` / 系统代理，而这个面板的使用者十有八九
  正开着代理工具。一旦环境里有那个变量，对 `127.0.0.1:8000` 的探测会被送去代理，
  **酒馆明明起来了、面板永远等不到**，症状跟上面那条一模一样。本机当时
  `ProxyEnable=0` 才没撞上 —— **「我这儿没事」不是结论**。
- **只带日志的进度事件把段标题抹成了空。** `events::Reporter::log` 发出来的 `phase` 是空串
  （它只想追加一行日志），而前端 `tasks.ts` 照抄过去，界面就退回默认的「启动中…」。
  于是**日志刷得越勤，界面上能看见的信息越少**。空串现在等于「没有新标题，保留旧的」。
  第 2 条那个每 4 秒的进度正是因此走 `phase` 而不是 `log`。

### 四、三条桥的设置收回面板（使用者定的）

使用者的原话：「这个改成都由面板操控设置，按钮做在启动页，酒馆按钮的右上角。」

起因是他发来的一张截图：SillyTavern 里一个标签页停在 `127.0.0.1:5001/settings?embedded=1&…`，
`ERR_CONNECTION_REFUSED`。那是他本机那份酒馆扩展 `claude-tavern-bridge`（**面板不分发它**），
把 Claude 桥接的 5001 写死在三处，用 GPT（5002）/ Gemini（5003）聊天时去连一个没人听的端口。
**看起来像「桥接坏了」，其实聊天用的那条桥好好的，坏的只是那块面板。**

两边一起改：

- **面板侧**：反重力页启动卡里酒馆那格**右上角**一颗小按钮，开「酒馆桥接设置」弹窗 ——
  每条桥一块：状态 / 槽位 / 还缺什么 / 端口 / 模型 / 酒馆里填的地址（带「复制地址」）。
  `Tile` 因此多了 `corner`：**磁贴本身是 `<button>`，角标不能嵌在里面**（`button` 套 `button`
  是非法 HTML，浏览器解析时会把内层拆出去，点了谁都说不准），所以包一层定位容器、
  角标当兄弟节点；`className`（`launchcol-wide` 那类跨列 class）要跟着外层走，
  留在磁贴身上就不生效了。
  路径 / 资产盘点 / 备份恢复仍留在插件详情页 —— 那些不是「起之前要调的旋钮」。
- **扩展侧**（1.2.0，改的是使用者本机那份，原文件留了 `.bak`）：三条桥各探一次活并列出来，
  没在跑的那条直接写明「该去哪儿起」；管理页**只在 Claude 那条真的在听时才加载**，
  否则换成一句话说明它只属于 Claude 桥接。端口从 `localStorage` 读覆盖值，不再写死。
  探活用 `fetch(..., {mode:'no-cors'})` —— 酒馆在 8000、桥接在 500x，跨源且三条桥都没配 CORS，
  但**连不连得上**这一位信息照样拿得到：连上了拿到 opaque 响应，端口空着直接 TypeError。

「还缺什么」两处（插件详情页与这个弹窗）共用 `lib/tavernReady.ts` 的纯函数。
**各写一份迟早会互相矛盾** —— 一处说能起、另一处说缺东西，而没人说得清该信哪个。
顺序固定为 路径 → CLI → 槽位 → 登录，**就是该先做哪一件**（没有 CLI 就没法在槽位里完成登录）。

## 0.30.0 反重力账户页：能力从 Antigravity-Tools-Lite 对照来，实现一行没抄

起因：使用者给了 `anglee0323/Antigravity-Tools-Lite`，要「识别它的能力，补全反重力账户页」。
它是 CC BY-NC-SA 4.0（`lbjlaq/Antigravity-Manager` 的分支）—— 只能识别机制、自己实现。
它有五个能力：多 Google 账号、在反重力里切号、看配额、本地 token 仪表盘、公开价格页同步。
对照本项目的规矩，三个撞线、两个顺路，最后**五个都做了，但做法跟它没有一样的**。

### 一、IDE 槽位 = `--user-data-dir`，Hub 仍单一身份

0.26.0 定「没有多槽位」的依据是 Hub 的令牌在 Windows 凭据管理器。**实机对照才发现那只对 Hub 成立**：
`%APPDATA%\Antigravity` 底下没有 `state.vscdb`；`%APPDATA%\Antigravity IDE\User\globalStorage\state.vscdb`
有，里面 `antigravityUnifiedStateSync.oauthToken` 1068 字节 —— IDE 是 VS Code 分支，令牌在它的
全局存储里。VS Code 认 `--user-data-dir`（`main.js` 里六处）。

Lite 的切号是**把自己持有的令牌写进那个库**，顺手改 `telemetry.serviceMachineId`。本项目不写库：
换目录。探针（2026-09-21）：临时目录起 IDE → 页面是「Welcome · Continue with Google」、库里没有任何
登录键 → 使用者登第二个账户 → 两份资料各持各的邮箱与档位（Google AI Pro / 免费档），同时跑互不影响。
**这一步不是从 Lite 学的，是从本项目自己的 `CLAUDE_CONFIG_DIR` / `CODEX_HOME` / `GEMINI_CLI_HOME` 学的。**

两个顺带的坑：

- **端口文件跟着目录走。** 面板起的那份 IDE 的 `DevToolsActivePort` 在槽位目录里。汉化引擎
  （`qb-extensions`）跟 `qb-accounts` 同层、不能反过来问它激活槽位是哪个，所以由编排层灌进去
  （`antigravity_ui::set_ide_user_data_dir`）：起 IDE 前、刷新状态时、面板启动时各灌一次。
  漏掉启动那一次的症状是「面板重启后点附加，附到上一次默认目录留下的死端口上」。
- **新槽位是干净的 IDE。** 只复制 `settings.json` / `keybindings.json`。`globalStorage` 一个字节不搬 ——
  复制式迁移造过两份 refresh token（§7.29）。

### 二、配额不调内部接口：IDE 自己把它写在本机

使用者原本选了「做，推翻 CLAUDE.md 那条」。动手前先看 IDE 的库里还有什么：
`antigravityUnifiedStateSync.userStatus`（27 KB，base64 protobuf 套 base64）解开是姓名、邮箱、
档位（`g1-pro-tier` / Google AI Pro）、**14 个模型各自的剩余比例（float32）与重置时间（Timestamp）**。
也就是说 Lite 调 `v1internal:fetchAvailableModels` 拿到的东西，IDE 每次同步都写在本机了。

于是配额走的是「用量只许读官方客户端自己写在本机的文件」那条已有的例外口径（Claude 页读
`plan-usage-history.json` 是同一条路），**规矩没有推翻**：零网络、零令牌、不据此做任何决定。
代价是它只有 IDE 上次同步时那么新 —— 界面写「IDE 写入 hh:mm」，不说成此刻；Hub 不写这份状态。

### 三、用量：自写的 protobuf 线格式读取器，字段号按实测数出来

对话记录 `~\.gemini\antigravity*\conversations\*.db` 的 `gen_metadata.data` 是 protobuf，没有 schema。
对着本机 49 个库、12,410 条记录逐 tag 走（`antigravity::proto`，四种线类型、遇 group 报错、
截断报错不报空）：1.4 是用量（1 系统提示、2 输入、3 输出 = 9 + 10、5 缓存读，`5` 常比 `2` 大好几倍
所以输入不含缓存）、1.19 模型 id、1.9.4 时间戳（10,643 条有，其余用 `steps.metadata` 的 1 号字段兜底）。
装进 `TokenBucket`，直接走 Claude 那套 `token_summary::summarize` —— 命中率、缓存省下、时间档一个算法。
不引 `prost`：猜一份 schema 错一处整条消息解不出，逐 tag 走错一处只是少一个字段。

三条口径：旧 `.pb` 归档不猜只报数；`antigravity-backup` 那种整目录备份里同名对话只计一次
（实机就有一份，49 个库 + 48 个 `.pb` 里 32 个是备份）；没有账户标识，不按账户摊派。

### 四、价目：Google 的页面没有机器可读版，走内置快照

面板启动时抓的官方价只有 Anthropic / OpenAI（它们的文档页给 markdown）。Google 的定价页是
JS 渲染的 HTML，没有稳定的机器可读版 —— 与其写一个一改版就静默失效的解析器，不如内置快照并把
`verified_at` 写清楚。3.6 / 3.7 / 3.8 Flash 是**促销价**（2027-01-01 翻倍），注释里写了到期日。
`price_key` 顺带剥 `-thinking` 后缀：反重力把开了思考的 Claude 记成 `claude-opus-4-6-thinking`，
同一个模型同一份价。

### 五、版式：引擎进弹窗，右下换用量卡

使用者要三个官方账户子页长一个样（槽位 / 启动 / 用量）。汉化 / 审批引擎照 GPT 页「识别」的先例
收进启动卡标题栏一颗按钮打开的弹窗；左卡脚注上一对页签切「IDE 槽位 / Gemini CLI 槽位」——
不另起一行，这一页是固定高度，`test:ui` 四档一个都不许裁。

## 0.29.0 的四件事

### 一、别把 shell 当启动目标（Gemini CLI 三个版本没装上过）

`quote_argument` 给每个参数套引号，而 `cmd.exe` / `powershell.exe` 自己解析命令行
且不先脱引号 —— `"/k"` 就不再是开关。实机复现三种形状：

| 交给 `cmd` 的东西                           | 结果                                           |
| ------------------------------------------- | ---------------------------------------------- |
| `"/c" "npm --version && …"`（旧写法的形状） | exit 1，`'"npm --version …' is not recognized` |
| `/c "npm --version && …"`                   | exit 0，正常输出                               |

**最贵的不是错，是错的形状**：`/k` 让那个窗口留在原地显示报错，而面板这边一路
`Ok(())`、界面提示「已打开安装窗口」、紧接着 `invalidate(["software"])` 重新检测
（那时 npm 一动都没动，必然读到装之前的状态）。**每一层都在说成功。**

护栏：`NativeProcess::create` 现在拒绝带参数的 shell，报错里指出替代做法
（`winget::run_streaming`，或先写成 `.cmd` 文件再起那个文件）。

同一族的第二处：`sysenv::ipv6` 的提权脚本要作为**一个参数**穿过
`Start-Process -ArgumentList`，PowerShell 5.1 在那里会吃掉内嵌的双引号 ——
含双引号的那一版子进程 **exit 0 而一张网卡都没改**。老代码用 `-EncodedCommand`
绕开了它（base64 里没有引号）。0.29.0 为了不触发杀软的启发式要去掉 base64，
于是必须让脚本本身一个双引号都不产生：计划改用 PowerShell 数组字面量写，
不用 `ConvertFrom-Json`。有测试钉着这条不变量。

### 二、反重力一键安装：没有官方哈希时，闸门是签名

`codex_store` 那条链的 SHA-256 来自微软 FE3 的清单（TLS 上拿的）。反重力没有对应物 ——
官方下载页只给地址。所以三道闸换成：地址从 HTTPS 页面读 + 域限定 Google 自己的三个主机 +
Authenticode 主体必须含 Google（读不出 = 没验成 = 不装）。

⛔ 算出来的 SHA-256 **只记进日志、不作判据**。没有可信对照值时拿它当判据就是自己跟自己比，
那正是档案里 `real_multiplier` 那一类失效。也**不要编一个「预期哈希」常量**：
版本一变就过期，而过期的形态是「所有人都装不了」。

抓页面这一步栽过一次，值得单记：那个站点**不管发什么 `Accept-Encoding` 都回 gzip**
（连显式 `identity` 也是），而面板的 reqwest 没开解压特性。于是 `.text()` 给出一个
六万多字符的字符串 —— 200、`Content-Type: text/html`、长度也像个网页 ——
里面全是替换字符、一条地址都没有。**第一版代码把它报成了「页面可能改版了」**，
一条会把下一个人直接带去改解析器的错误结论。现在按 magic bytes 认 gzip 自己解，
并且解不出可读 HTML 时**说清是传输层的问题**。

为什么不给 workspace 的 reqwest 开 `gzip` 特性：那会让每一个客户端都自动加
`Accept-Encoding: gzip` 并透明解压，包括本机路由那条要求逐字节流式转发的上游连接。
为一个下载页去改 SSE 代理的行为，代价和收益完全不成比例。

### 三、杀软误报能改的只有「未签名」与「零信誉」之外的边角

Defender 的 ML 模型看三件事：谁签的、多少人在用、它在干什么。第三条是产品本身
（写 Deny ACE、收进程、下 exe 再执行、注 JS 进别人的 Electron、扫 Chrome 的 Cookies），
删掉等于删掉这个软件。这一版没做代码签名，所以只能补那些「正规程序都会声明、
恶意程序常常懒得写」的东西：完整的 PE 版本资源、带 `requestedExecutionLevel` 的应用清单、
不用 `-EncodedCommand`、开机不再枚举使用者的桌面。

⚠ **这些改动的效果没法从代码推出来**，要靠 VirusTotal 前后对照量。
详见 [ANTIVIRUS.zh-CN.md](ANTIVIRUS.zh-CN.md)。

⛔ **不在面板里加「一键给自己加杀软排除项」**：程序给自己开白名单本身就是恶意软件行为。

### 四、「Pill 和版本行互相矛盾」是个结构问题，不是七个笔误

0.28.0 修了 Codex CLI 那一张，剩下四张是同一个形状 —— 因为每张卡都**各写各的三元表达式**，
Pill 读 `installed`、版本行读 `version`，而后端允许这两个字段不一致。一张一张修必然再漏。

现在三档（未安装 / 版本号 / 已装·版本读不出）统一走 `lib/software.ts` 一份渲染函数，
Pill 与版本行同源；第四档「报告还没回来」也不折成「未安装」。后端那处真错
（`detect::codex_desktop` 的两个字段来自两个互不相干的分支）抽成纯函数
`codex_desktop_software`，四条单测钉着「有版本号 ⇒ 一定 installed」。

`test:ui` 新增一条跨卡断言：任何一张卡上 Pill 与版本行不许给出相反的结论。
⚠ 那条断言里**先断言它至少看到 4 张卡** —— 选择器一改，循环会一张卡都不进、
`bad` 恒为空、测试恒绿。这个仓库在这上面栽过不止一次。

## IP 锁

### 四条不显然但很贵的设计

- **「查不到 IP」和「IP 变了」必须分开处理。** 合并的写法会让网络抖一下、
  隧道重连一次、查询服务限一次流，就直接杀掉正在进行的会话。
  现在是：查不到 → 立刻上锁但**留着进程**（能不能发出请求由锁说了算，
  那才是真正的管控点），网络回来且 IP 仍合法就自动解锁续跑；
  CLI 侧 180 秒后才关停。
- **桌面端不给宽限。** 它冻不住 —— 真正在跑的是 `app-*` 下那个不能加 Deny 的
  副本，而且早把自己加载进内存了。「等等看」的实际含义就是「让它在无法核实的
  网络上继续跑」。代价：VPN 重连或查询服务限流会直接关掉正在用的桌面端，
  丢掉没保存的对话。
- **IP 仍在白名单、租约却被人收走了 → 看门狗要自己要回来。** 否则「加白名单」
  这个动作本身（编辑器开场就重新上锁）会静默废掉正在跑的 Claude。
- **自动更新会把锁弄丢。** 官方安装器写的是全新 exe，继承干净 ACL。
  所以租约期钉 `DISABLE_AUTOUPDATER=1`，退出时重锁**全部**副本，
  安装器装完主动重锁。
- **`claude.exe.old.*` 是没有 Deny ACL 的可绕过副本。** 而且发起升级的会话
  自己占着删不掉（Windows 允许改名正在运行的 exe，不允许删除），
  所以清理放在**下一次**升级的开头。

### 解锁不能用 REVOKE_ACCESS

实测 `SetEntriesInAclW` + `REVOKE_ACCESS` 对 **deny** 条目会**返回成功却什么都不做**
（`gate/acl.rs` 的往返测试就是钉这条的）。照着写的话，锁上之后再也解不开，
面板会彻底打不开 Claude。

现在的做法是自己重建 DACL：取显式条目（`GetExplicitEntriesFromAclW` 不返回继承来的）、
滤掉我们那条再写回去。写回时**必须主动带 `UNPROTECTED_DACL_SECURITY_INFORMATION`**，
继承来的权限才会回来；一条显式条目都不剩时写一个**零条目的合法 ACL**，
**绝不能写空指针** —— 空指针 DACL（NULL DACL）的意思是「不做任何访问检查、人人完全控制」，
跟零条目 ACL 正好相反。早期版本在这里写错过，每解锁一次就把一份 `claude.exe` 交给所有人。

> 这个错误留下的残留至今没有自愈路径，见 [KNOWN-ISSUES](KNOWN-ISSUES.zh-CN.md) 第 1 条。

## 安装

### 为什么由面板接管安装目录

「Claude 装在哪」每台机器都不一样，光是要上锁的落点就有十几种。面板靠扫描去找，
漏一处就是「面板找不到软件」，或者漏锁一份 —— 而漏锁的那一份就是现成的绕过入口。

面板自己装的那份放在面板指定的位置，另有一份安装记录
（`<托管目录>\installs.json`：版本、SHA-256、来源、时间），启动永远先用它。

### 为什么不用 winget 的 `--location`

Claude Code 与 Codex 在 winget 上都是 portable 包，理论上能指定安装位置。实测三条都不成立：

1. **winget 源里的版本落后。** 2026-09-11 实测：Claude Code 2.1.263 对官方 2.1.268，
   Codex 0.146.1 对 0.154.0。（这个差距会变，结论是「不能假定 winget 跟得上」。）
2. **当不了兜底。** 它下的就是同一个官方地址，官方连不上时它也连不上。
3. **会在托管目录之外留东西**：`WinGet\Links` 的 shim 和卸载登记。

所以直接从官方源下，自己核对官方给的哈希与签名。

桌面端是例外：它的官方安装器把位置写死在 `%LOCALAPPDATA%\AnthropicClaude`，
还会自己在那里更新，面板改不了它的落点，也就不假装改。

### 完整性校验为什么换了做法

早期版本自己钉 SHA-256（`installers.lock.json` + `scripts/pin-hash.mjs`），现已下线 ——
哈希得手工钉，钉不上安装按钮就永远是灰的，而它确实一直是灰的。

现在用的是**官方发布时一起给出的哈希**（Claude Code 的 `manifest.json`、
GitHub Release 的资产摘要），再加 Authenticode 签名。托管安装里这两条都是硬条件：
哈希对不上、签名不对或者读不出签名，都删掉下载的文件、不装，原来那份原样留着。
GitHub 偶尔不给某个资产的摘要，那时 Codex 只剩签名这一条可核，日志里会写明。

### 清外部副本时的边界

**永远不碰**：账户凭证与配置（`~\.claude`、`claude-profile-*`、`~\.codex`）、
桌面端和它自带的副本、编辑器扩展里的副本、`~\.local\bin` 目录本身和 `PATH`
（uv、pipx 等别的工具也往那里装东西）。

删之前逐个再核一次签名，不是 Anthropic / OpenAI 签的一律不删。
托管那份没装好之前不让清 —— 不然清完这台机器上一份都没有了。

### Codex 桌面端直装为什么装的是 Store 包，不是解压出来的 exe（0.28.0）

两个 MIT 来源里，codex-windows-cn 的做法是把 MSIX 当 zip 解开、只取 `app/` 子树、
直接跑 `Codex.exe`，再用 `versions/<版本>/` + `current` junction 做多版本并存。
面板**没有**照搬，理由三条：

- 面板早就能启动这个包 —— 走的是 `Get-AppxPackage` 查到的 `InstallLocation\app\ChatGPT.exe`，
  按槽位给 `CODEX_HOME` / `CODEX_ELECTRON_USER_DATA_PATH`。缺的只是「装」，不是「跑」；
- 未打包运行丢的是包身份：`codex://` 协议、Store 自动更新、Apps & Features 登记全没了。
  codex-app-mirror 自己的 `windows-portable-experiment.md` 把这条路标为 experimental / unsupported；
- 多版本并存只在未打包下成立，MSIX 是单包身份。真要退版本，`Add-AppxPackage -ForceUpdateFromAnyVersion`
  装一份旧 `.msix` 就是回滚，不需要 junction。

所以直装的终点是 `Add-AppxPackage`（正规注册），两条路只是**取包的方式**不同：
`winget install --source msstore` 让 Store 部署服务自己装；FE3 直连自己下 `.msix` 再注册。

### FE3 直连为什么内置一张微软根证书

`fe3.delivery.mp.microsoft.com` 的证书链到 **Microsoft Root Certificate Authority 2011** ——
每台 Windows 的系统证书库里都有它（Windows Update 自己靠它），但它**不在 Mozilla 的根清单里**，
而面板的 reqwest 走 rustls + webpki 根。实机（2026-09-20）：curl（schannel）能通，
面板的 `GetCookie` 被当成未知 CA 拒掉。

两条路：给整个 workspace 开 `rustls-tls-native-roots`（所有客户端都信系统证书库，
包括使用者自己装的中间人 CA），或者只把这一张根加给 `codex_store` 自己的客户端。选了后者：
影响面最小，指纹有单测钉着，别的网络客户端一个字不变。下载 CDN 用的是公共 CA，不需要它。

### 下载为什么走 `http://`

FE3 给的地址就是 `http://tlu.dl.delivery.mp.microsoft.com/…`。试过换成 `https://`：
那个主机名上没有配证书（回的是 Fastly 的兜底证书，主体对不上，握手失败）。
Windows Update 自己也是明文下、靠哈希保完整。这里同样：SHA-256 是从 TLS 上拿到的清单里来的，
装之前再核一次 Authenticode，下载域限定 `delivery.mp.microsoft.com`。三道闸在，明文不是缺口。

### 卸载谁先关谁

`purge_execute` 里每个目标关进程的方式不一样，而且**不能互相借用**：

| 目标                            | 关什么                                          | 为什么不是别的                                                                                            |
| ------------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Claude Code                     | `killswitch::execute()`（全部 Claude）          | 托管那份 exe 被终端会话占着删不掉                                                                         |
| Claude 桌面端                   | `execute_desktop()`（只收 `Role::Desktop`）     | 0.28.0 之前跟上面一样全收 —— 卸个桌面端把终端里正在写的会话也关了，界面上却写着「开着的桌面端会先被关掉」 |
| Codex 桌面端                    | `codex_desktop::close()`（按官方包 exe 路径认） | Store 包在跑时 `Remove-AppxPackage` 失败                                                                  |
| 反重力                          | `execute_antigravity(None)`（按安装目录认）     | Electron 单实例 + 托盘常驻，跑着整目录删不掉                                                              |
| Codex CLI / Gemini CLI / Chrome | 不清场                                          | 面板不按进程名杀；Gemini 是按请求起的短命进程；Chrome 走它自己的流程                                      |

## 账户槽位

### 新建槽位为什么是空的

不从任何地方复制凭证。复制凭证就是又造一份同样的 refresh token，
两边都用起来之后，一边刷新就可能让另一份作废。在新槽位里登录一次即可。

### 迁移留下的重复槽位

早期版本从旧脚本迁移时是**复制**槽位的，留下两份相同的凭证、两个同时「激活」的账户。
现在列槽位时会把它们合成一份：旧目录改名留底（不删），原处换成指向面板槽位的联结点。

### 用量的实时样本有两条路径，不是一条

`%APPDATA%\Claude` 是个**联结点**，只指向**当前**槽位的桌面端资料目录。
别的槽位的 `plan-usage-history.json` 在它自己的 `Claude-<标签>` 里。

0.19.2 之前只读前者，症状是：非当前槽位按 org 一条实时样本都匹配不上，
退回十几天前的 `cachedUsageUtilization`，界面打出「快照已过期」——
**而数据是新的，只是在另一个目录**。实测 2026-09-16：`main` 槽位的缓存旧了
20093 分钟，同一时刻 `%APPDATA%\Claude-main\plan-usage-history.json`
里有它 174 条样本，最后一条写于十二分钟前。

现在两条路径都读，按 `(t, org)` 去重（当前槽位那两条会解析到同一个文件）。
路径由 `AccountRoots::history_files` 拼 —— 「Claude 的目录名怎么拼」
全项目仍然只有那一处。org 过滤那道留着：`Claude-<标签>` 里也可能混着
别的账户在那个目录下用过时留下的样本（实测 `Claude-main` 里就有 121 条）。

**过期判定对两个来源一视同仁。** 原来只判 `source === "cache"`，
桌面端那一档再旧也当当前值显示 —— 可桌面端的样本只在它运行时才写，
关一天读数就冻在最后一条，而那一天里窗口早就重置过了。
来源仍然标出来：那决定的是使用者该去开桌面端还是去跑一次 Claude Code。

### 账户列表要轮询，token 统计不能进去

`accounts_list` 是纯本地文件读（两个小 JSON + 几次 `is_dir`），没有 PowerShell、
没有网络请求，所以 30 秒轮询是安全的，也符合 `resources.ts` 开头那条
「本机状态可以轮询」。原来它既没有 `pollMs` 也没有 `staleMs`，加上全局的
`refetchOnWindowFocus: false`，等于**一次会话只打一发** —— 文件更新了，
页面纹丝不动。

⛔ **token 统计绝不能塞进 `accounts_list`。** 那要扫几十 MB 的会话转写，
进来之后这条轮询就变成每 30 秒磨一次盘。它走自己的按需命令
（`accounts_tokens`，只在详情页打开时跑）。

### token 统计：不去重就是两倍，而且长得像真的

数的是槽位目录里 `projects/<项目>/<会话>.jsonl` 的 `type: "assistant"` 行。
零网络请求，跟额度那两个窗口同一条口径。

续接会话、自动压缩、`--continue` 都会新开一个转写文件并把之前的消息**原样重放**
进去，包括 assistant 那几条和它们的 `usage`。实测 `main` 槽位：

|        |  条数 | 输出 token |
| ------ | ----: | ---------: |
| 不去重 | 6,049 |  6,377,231 |
| 去重后 | 3,189 |  2,960,298 |

**2.15 倍**，而且多出来的那一倍长得完全像真数据 —— 没有任何地方会报错，
界面上只会显示一个偏大的数字。去重键是 `message.id` + `requestId`：
同一批数据里这两者从没分叉过（`message.id` 从没对应过两个 `requestId`，
同一对键也从没带过不同的 token 数，两条都实测过），所以去重是无损的。

**没做增量缓存。** 想过按文件偏移做，实测否掉了：两个槽位合计 90 MB、
9,634 条带用量的记录，一遍扫完 0.46 秒。为这点开销换一份要自己维护失效逻辑的
磁盘缓存不划算 —— 而缓存算错的样子，正是「显示一个看起来很正常的错数字」。

**不折算成钱**：`qb-accounts` 不能依赖 `qb-station`（同层，
`crates_only_depend_downwards` 卡着），而且订阅账户按官方 API 单价折出来的
金额本来就不是你实际付的。

### 删槽位为什么拒绝当前那个

删掉目录之后 `claude-profile` 那个联结点就悬在半空，而**全项目没有任何东西**
会去修它：`active_label` 只是 `is_dir()` 一查回 `None`，于是下一次启动
Claude Code 不设 `CLAUDE_CONFIG_DIR`，安安静静退回默认目录 `~\.claude`。
症状是「我明明有账户，一开就让我登录」，而界面上什么都没报 ——
那正是 §7.26 那个坑的形态。要删它就先切到别的槽位，那条路会把三处指向一起换好。

桌面端那份资料**默认跟着删**：留下的话，以后建一个同名槽位会静默继承这一份旧的
桌面端身份 —— 新槽位是空的、桌面端却还登着上一个人，两边对不上而没有任何提示。

### 「新建即登录」为什么要经过切换确认框

登录 = 在那个槽位里起一个 Claude Code，让官方客户端自己弹登录界面
（面板从头到尾不经手账号密码，仓库里也没有一行 OAuth 代码）。
而 `workspace::launch` 有一道拦截：要起的身份必须已经是当前槽位 ——
那道拦截守着「任意时刻只有一个账户激活」，**不许为了少一步而绕开**。

于是分两条：原来没有激活槽位时，新槽位直接成为当前的（`create_slot` 干的），
**不切、不关任何进程**就起；已经有别的槽位在用时，先走切换确认框
（它本来就会扫一遍「会关掉哪些进程」），切完自动起。
全新使用者不该平白挨一次清场，这就是那个分支存在的全部理由。

### 「重新登录」必须常驻

剩余天数只读本地那个时间戳，**查不出「被风控下线」**。令牌被回收时
`.credentials.json` 还在、到期日还是将来某一天，看起来完全健康，
而实际已经发不出请求了 —— 那正是使用者点名要这个按钮的场景。
按「看起来过期没」决定要不要给这个入口，等于在最需要它的时候把它藏起来。

### 切换为什么要先清场

否则会出现「一个跑着的桌面端脚下换资料目录」，以及进程还连着旧账户。
所以切换 = 先关闭全部 Claude → 三处指向一起换（要么全换要么都不换）→ 不自动启动任何东西。
**清场失败就不切**，槽位一点不动。

## 中转站

### 排序为什么按「最弱项」而不是加权总分

勾了「便宜 + 快 + 稳」之后，一条又便宜又快但成功率 60% 的线路，在加权总分里
会被前两项抬上去排第一。而使用者勾「稳」的意思是**他要稳**，不是「稳可以用便宜换」。

所以排序取三维里**最低**的那一维（maximin）：一条线路的名次由它最差的地方决定。
各维先按「跟最好的那条比是几分之几」归一化，否则毫秒和倍率没法放在一起比。

配套两个数，都是为了不让界面抖：

- **8% 迟滞** —— 新的要比在任的好 8% 以上才换。健康度天然会小幅波动，
  没有迟滞的话每刷新一次都在换站，而换站本身是有成本的；
- **2% 以内视为分不出高下** —— 差 1% 就宣布「A 比 B 好」是在假装精度。

底线筛选（「成功率不低于 x%」之类）如果把所有还活着的线路都卡掉，面板**放开底线
并说明**。宁可用一条不达标的线，也不能让使用者面对一个空列表 —— **绝不制造死局**。

### 熔断为什么分两档

429 和 401 是两件完全不同的事：

|                 | 含义                             | 处置                           |
| --------------- | -------------------------------- | ------------------------------ |
| 429             | 限流。站点是好的，只是这会儿排队 | **只降权**，过一阵还会回来     |
| 401 / 402 / 403 | Key 无效 / 欠费 / 被拒           | **立即熔断**，重试没有任何意义 |

合并成一档的话：按 429 那样处理 401，会拿一把废 Key 一直重试；
按 401 那样处理 429，会因为一次排队把一条好线路扔掉半天。

半开探测靠「重度降权」实现，不另开一条探测路径 —— 多一条路径就多一处会漂的状态。

### 本机路由为什么存在

只有一个理由：**换上游中转站时不必重启客户端**。

客户端把 base_url 指到 `127.0.0.1` 之后，换上游只是改路由器里的一个指针，
下一发请求就生效。没有它的话，换站要改配置文件 + 重启客户端 + 丢掉当前对话。

它**不是**代理软件，边界写在 `local_router.rs` 顶上并由 DISCLAIMER §5.1 对外承诺：
只绑回环、不改系统代理设置、不做链式转发。这三条动一条就要同步改那一节，
否则免责声明描述的是另一个软件。

换上游**只影响下一发请求**，正在飞的那一条不受影响 —— 中途切上游会把
已经开始的流式响应截断，而使用者看到的是「回答说到一半没了」。

### 价目解析为什么「认不出来就整批丢弃」

页面改版时解析器往往还能凑巧认出一两行。那种「半成功」比彻底失败危险得多：
它会用一份残缺的表**盖掉完整的内置快照**，后果是大部分模型的真实倍率悄悄变成
「不知道」，而界面上看起来只是「这些站都还没检验过」。

所以解析不足 `MIN_PARSED_MODELS` 个模型就返回空，调用方继续用快照，
界面照实写出用的是哪一份。**一次失败的抓取绝不清空已有的价。**

同理，站点没公布 `completion_ratio` 时记 `None` 而不是 `1.0` ——
填 1.0 等于断言「输出不加价」，而输出往往才是大头。

## 脚本与编码

这三条踩过不止一次，写脚本前先看：

- **面板拉起的 PowerShell，输出编码要自己钉死成 UTF-8。** 这条最贵，v0.19.2
  才收干净。帮手进程一律带 `CREATE_NO_WINDOW`，**没有控制台**；没有控制台时
  `[Console]::OutputEncoding` 落到系统代码页上，那个代码页编不出来的字符会被
  换成一个**字面的 `?`** —— 字符在 PowerShell 那头就已经丢了，Rust 再怎么解码
  也回不来（跟「乱码」不是一回事：乱码还原得回去，这个还不回去）。
  zh-CN 实测：`Get-NetAdapter` 的「以太网」到手是 `???`，「蓝牙网络连接」是
  `??????`。
  **它的危险之处不在显示。** 出站锁那一页把使用者勾中的网卡名原样送回去当
  `-InterfaceAlias`，于是规则加在一个不存在的接口上，而界面报「已加 N 条」——
  一个看起来生效、实际什么都没拦的功能。
  现在只能走 `process::powershell_std` / `powershell_tokio`，它们把
  `-NoProfile -NonInteractive` 和那句前奏一起钉死；`src-tauri/tests/architecture.rs`
  里有一条测试守着，谁自己 `Command::new("powershell")` 就红。
  **跟区域设置无关** —— `é`、`ü`、西里尔字母在 CP437/CP850 上同样编不出来，
  开源出去之后这是每一台机器的问题。
  前奏要写成 `New-Object System.Text.UTF8Encoding $false`（不带 BOM）：
  用 `[Text.Encoding]::UTF8` 会在输出最前面插一个 BOM，而这些脚本的产物大多
  直接喂给 `serde_json`，BOM 进去当场解析失败。

- **`WScript.Shell` 存不了非 ASCII 路径。** 中文桌面（`…\OneDrive\桌面\`）会被它变成 `??`，
  存出来的 `.lnk` 目标是空的。绕法：先在纯 ASCII 的临时路径建好，再用 `Copy-Item` 搬过去。
  `scripts/setup-desktop.ps1` 就是这么做的。
- **`.ps1` 必须存成 UTF-8 with BOM。** Windows PowerShell 5.1 没有 BOM 就按 ANSI 读，
  中文注释会变乱码并直接引发语法错误。

## 日志分类

`src/lib/logline.ts` 把 `ip-gate.log` 的行拆成事件。一条设计取舍值得记住：

**分类（`category`）与语气（`tone`）是两回事。**
「拒绝放行：出口 IP … 不在白名单内」既属于门禁，又是一条错误。
早先的写法把「出错」单列成一个分类，结果是按「门禁」筛选时**恰恰漏掉最该看的那几行**。
现在 `category` 只回答「这条讲的是什么」，`tone` 只回答「严不严重」，
界面上的「出错」筛选看 `tone`，不看 `category`。

同类的漏还出现过两次，都是关键词没覆盖到：

- 「面板退出时**重锁**失败」里没有「上锁」二字 —— 少一个关键词它就掉进 `process`。
- 「升级**没生效**：…」里一个 DANGER 词都没有 —— 于是一条实打实的升级失败
  落成 `tone = default`，点「出错」筛选时看不到。

**加日志文案时，回头看一眼这两张关键词表。**

## 字为什么会从盒子里长出去

v0.12.1 的实机截图：IP 白名单小窗里「执行锁」那一格的字整段横着压在隔壁格上。
根因有两条，各自都不显然。

### 一、`min-width: 0` 压不动里面那个词

`.metric-v` / `.row-main` 这些容器早就写了 `min-width: 0`，但溢出照旧。
原因是那一条只让**容器自己**能被压扁，管不到它装的东西：
裸文本在 flex 容器里是一个**匿名 flex item**，而 flex item 的 `min-width` 默认取
`auto` —— 也就是它的最小内容尺寸，等于最长那个不可断开的词。

本机上这些词都很长，而且一个断行机会都没有：

| 来源                         | 样子                                               | 长度                 |
| ---------------------------- | -------------------------------------------------- | -------------------- |
| 会话 id（`config_io::id()`） | `20260913-045632-ef2e6a0958ef48deb76f0b4d12ca77b1` | 48                   |
| Windows 路径                 | `C:\Users\me\AppData\Local\…\claude.exe`           | 视情况，反斜杠不断行 |
| 环境变量名                   | `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`         | 40，下划线不断行     |

解法是 `overflow-wrap: anywhere`，**不能写 `break-word`**：
两者在「撑不下时断哪里」上一样，但只有 `anywhere` 会把最小内容尺寸降到单个字符。
写成 `break-word` 的话，字看起来会换行，盒子却照样被撑破。

### 二、小窗里的溢出是**裁掉**，不是滚出去

`.modal` 是 `overflow: hidden`（圆角需要它）。所以在小窗里溢出的字既不滚也不报，
直接消失 —— 而 `npm run test:ui` 当时只查 `.qb-main` 会不会横向滚，一个都拦不住。
这就是为什么那张截图上的问题跑满全绿的 CI 也发现不了。

现在 `test:ui` 两档一起查：live（按演示数据现在的样子谁顶出了盒子）和
stress（把每个叶子文本节点轮流换成 48 个不可断开的字符，看谁先被撑破），
并且**单独进六个安全小窗各查一遍**。

### 三、顺带：`.btn` 的尺寸原来只写在档位类里

`padding` / `font-size` / `min-height` 只有 `.btn--sm` 和 `.btn--md` 有，基类一个都没有。
`Button` 组件总会带档位，但 `<Link className="btn">` 这种手写的不会 ——
渲染出来零内边距、字号继承自父级，字紧贴着边框，看上去就是「文字突出按钮外面」。
现在基类自带 `--md` 那一份，档位类排在后面照样覆盖得掉。

### 长字符串本来就不该整串显示

CSS 只保证它不跑出去，不保证它有用。`lease.holder` 是全部持有者用「、」拼成的整串，
五个会话加一个桌面端就是三百多字符 —— 让它在四分之一屏宽的格子里换行，
结果是一格高出旁边四倍，仍然没人看得懂。

所以显示走 `src/lib/lease.ts` 一个函数：会话 id 只留时间戳那一段，
多于两个就说「已租给 <第一个> 等 N 个」，完整清单挂在 `title` 上。
**四处渲染共用它** —— 总览评分卡、白名单小窗的指标格、安全对象摘要、评分明细。
漏掉哪一处，哪一处就会在同样的实机状态下重新溢出，而这种状态只有同时开着
五个会话的人碰得到，自己测很难复现。

## v0.17.0：中转站的两套计价口径，和三件「看起来在跑、实际没跑」的事

### 一、官方价被约掉了 —— 一条全绿的静默失效

`CategoryVerdict` 原来有 `real_multiplier` 和 `advertised` 两栏，注释写着
「真实倍率 = 站点单价 × 标称倍率 ÷ 官方单价」。读起来像在拿官方价做核验。

问题是调用方（`station_ops::run_audit`）手里**从来没有站点的绝对单价**。
它拿站点公布的倍率乘上官方价凑出一个「站点单价」，`verdicts` 再除回去：

```text
凑出来的单价    = category_ratio × official
real_multiplier = 凑出来的单价 × advertised ÷ official
                = category_ratio × advertised        ← official 被约掉了
```

也就是说：**站点说它便宜，这张表就说它便宜。**「官方单价」那一列与
`PriceBasis` 在那条路径上是纯装饰，改它们不会让任何判定变化。
而 20 条单测全绿 —— 因为每一条测的都是「这个算式算得对不对」，
没有一条测「官方价有没有真的参与」。

补的那条测试是这么写的：**只改官方价，别的都不动，结论必须跟着变**。
（`the_official_price_actually_changes_the_measured_multiplier`）
这类断言是唯一拦得住「参数被约掉」的形状 —— 断言输出值对不对拦不住它。

两栏整个删掉之后，这张表只报它真答得了的问题：站点自己公布了什么。
「它到底收了几倍」搬去了 `measured_multiplier`：分子是账单实扣、
分母是同一批 token 按官方价算出来的成本，两头都不是站点公布的数。

### 二、sub2api 根本不用倍率这个概念

使用者指出来的：「newapi 是可以这样算，但 sub2api 不是，sub2api 的单价
就是官方单价。」

查下来是两种后端公布价格的方式根本不同：New API 系给相对倍率，
sub2api 系给**绝对单价**（美元／百万 token），折扣全在分组倍率上。
`StationRates` 原来只建模了前者，所以后者那种站点在面板上读出来一片空白 ——
而「空白」跟「免费」跟「倍率 1.0」在界面上长得都像。

加的是**两套互斥的字段**，哪一套有效由 `basis()` 从「谁填了」推出来。
**没有加一个 kind 字段** —— 理由跟 `inventory.rs` 那条一样：字段和内容
对不上的时候（适配器改了、迁移漏了、手改过配置），字段会骗人而内容不会。

两套**不互相换算**。换算要除以官方价，而那正是上面第一节那条失效的入口。
要合流只有一个口子 —— `category_ratios_against(official)`，明着除。
顺带逼出 `Route.rates_model`：绝对单价换成倍率必须知道是哪个模型的，
而官方价是按模型查的。倍率那一套不需要它，所以早先没有也看不出症状。

### 三、三件「看起来在跑、实际没跑」的事

这一轮补的三处，症状形状是同一个：**界面上有，行为上没有。**

| 哪一处         | 界面说什么         | 实际发生了什么                                                                         |
| -------------- | ------------------ | -------------------------------------------------------------------------------------- |
| 行上的「启动」 | 「运行中」         | 只起了本机路由。客户端没起，回终端敲 `claude` 走的还是官方，整条中转链路一次都没被用到 |
| 「智能调度」   | 「调度中」+ 呼吸点 | 一个 React `useState`。刷新页面就没了，从点下去那一刻起什么都没换过                    |
| `Route.rates`  | 「计费翻倍 ×5」    | 全项目没有一处往这个字段写过东西，`blended_ratio` 永远返回 `None`，排序整池退回粗口径  |

三处的共同点是**没有任何报错**。第一处现在由 `station_launch` 一口气做完
切上游 → 拉路由 → 起进程三件事（拆成三次前端调用的话，中间失败会留下
「路由起了、客户端没起」的半成品状态，而界面显示「运行中」）；第二处落进
`station_schedule` 表，面板启动时接回来；第三处由检验那一步回流
（`AuditOutcome.rates` + `.model`）—— 顺手学到的东西就该顺手存下来。

### 四、调度循环为什么放在接口层

第一版把 `start_scheduler` 放在 `app.rs`，循环里调
`commands::station::run_schedule_tick`。而 `commands` 本来就依赖 `app` 拿
`AppState` —— `architecture.rs` 的 `module_cycles_only_ever_shrink` 当场报出
`[["app", "commands", "tray"]]` 这个强连通分量。

搬到 `commands/station.rs` 是对的：这个循环要发界面事件、要读 IPC 那张表，
本来就是接口层的事。`app.rs` 只留那个停止句柄（它是状态，不是逻辑）。

**这条测试值回票价的地方**在于：环成立的时候代码照样编译、照样跑，
只有「以后拆不开」这一个后果，而那个后果要等到下次拆 crate 才暴露出来。

### 五、一跳 60 秒，不是越勤越好

调度每一跳要给池子里每条线各拉一次站点账单。那是免费的（不打模型），
但十条线的池子在 10 秒档上就是每分钟 60 个请求打到账单接口 ——
有些站点会因此限流，而限流的表现是健康度读不到，于是排序退化成只比倍率。
**盯得太紧反而让它瞎掉。**

60 秒也跟迟滞是一套的：换上游的代价（正在飞的请求落到另一把 key 上、
日志断成两段、熔断窗口重来）决定了换的频率本来就该低。

## v0.18.0：桌面端接进中转 —— 一个「没验过的假设」拖了两个版本

### 那句注释是怎么写错的

`workspace::launch` 里桌面端那一档原来是：

```rust
let env = if client == Client::ClaudeDesktop { vec![] } else { ... };
```

配套的文案是「桌面端不支持独立中转环境，请从桌面端自己的设置里改 base_url」。
读起来像一条查证过的限制。**实际上没人验过。**

查法很笨但有效：`Select-String` 扫桌面端的 `app.asar`（36 MB）。主进程启动
第一件事就是

```js
if (process.env.CLAUDE_USER_DATA_DIR) { app.setPath("userData", e); … }
```

而且它优先级最高 —— 桌面端自己那套目录重定位包在
`if (!process.env.CLAUDE_USER_DATA_DIR)` 里面。

**这一类错误的形状值得记**：它不是「代码写错了」，是**一句没有证据的断言被
写成了注释，然后被当成前提用了两个版本**。注释里写「不支持」的时候，
该问的是「谁验过、怎么验的」。

### 桌面端和 Claude Code 只差「端点写在哪」

|               | 数据目录               | 推理端点                                |
| ------------- | ---------------------- | --------------------------------------- |
| Claude Code   | `CLAUDE_CONFIG_DIR`    | `ANTHROPIC_BASE_URL`，同样是环境变量    |
| Claude 桌面端 | `CLAUDE_USER_DATA_DIR` | 目录里那份 `claude_desktop_config.json` |

桌面端那份配置用的是它自己的**第三方网关模式**（`deploymentMode: "3p"` +
`inferenceGatewayBaseUrl`），本来是给企业自建网关的。七个相关键在它的 bundle
里全部核实过。

所以两边是同一个形状：**起进程时指一个面板管的目录，官方那份一个字不动，
只对这一次启动生效**。

### 只并入，不整份覆盖

`claude_desktop_config.json` 同时装着 `mcpServers` 和 `preferences`。整份写会把
使用者配了半天的 MCP 抹掉，而且没有撤销。这跟 0.14.0 那条
「`auth.json` 不能整份覆盖，会把 Codex 官方登录抹掉」是**同一个教训的第二次出现** ——
凡是「我们只想改其中一个键」的配置文件，都要先读再并。

### 两个故意不写的键

参照的那个项目写了 `disableDeploymentModeChooser: true`（把「部署模式」选择器
藏掉）和 `coworkEgressAllowedHosts: ["*"]`（放开 cowork 出网白名单）。
**两个都没跟。**

前者是从使用者手里拿走一个开关 —— 他想切回官方就该切得回去；后者是放宽一道
安全限制，而中转站要的只是换个推理端点。**「顺带把别的口子也打开」是这个项目
的明确禁区**，DISCLAIMER 第 5 节就建立在这上面。

### 单实例：两处都要拦

桌面端是 Electron 单实例。已经在跑时再起一遍，只会把旧窗口拉到前面，
新给的环境变量一个都不生效 —— 症状是「点了启动，窗口弹出来了，可它走的还是官方」，
**没有任何报错**。

拦在两处：`workspace::launch` 里查 `killswitch::desktop_processes()` 非空就报错，
界面右列先说一句。**两处都要留** —— 事后报错不如事前说明，
而只有界面说明的话，从别处调进来的一样会中招。

（0.18.2 起中转站的「启动」改成替使用者关掉，不再只拦下来报错 —— 见文末 v0.18.2 一节。
上面这两处拦截仍然都在。）

## v0.18.1：中转站右列 —— 「选中的上游」只有一个定义

### 点行只是排队，界面却只认已落定的那条

点一行走的是 `selectRoute(id, false)`，后端 `request_switch` **只写 `pending`**，
下一发请求进来时 `begin()` 才把它落成 `current`；智能调度换线也是这一条路。
而界面原来只读 `status.current_route`，于是：

| 什么时候                     | 看到什么                               | 实际                                       |
| ---------------------------- | -------------------------------------- | ------------------------------------------ |
| 面板刚启动（`current` 为空） | 点哪一行都不高亮，右列「启动」一直灰着 | 选择已经排上了，只是没人读 `pending_route` |
| 已经有 `current`             | 行上的「当前上游」还挂在旧的那条       | 下一发请求就换                             |

**演示夹具把这件事藏了两个版本**：它的 `station_select_route` 直接改 current，
截图和 `test:ui` 里点行永远立刻生效。现在夹具也按软件记一份 `pending`，跟后端同一套语义。

界面上「选中的上游」只有一个定义：`pending_route ?? current_route`。
「正在路由」、行上的高亮、右列启动三处都读它；还在排队的写「已排队 · 下一次请求生效」。

### 右列「启动」不传 routeId

`station_launch` 带了 routeId 就会 `set_now`，而 `set_now` 顺手把 `pending` 清掉 ——
刚点的那一行、调度刚排上的那条，都会被悄悄换回旧的。原来右列启动传的正是
`current.id`，还会先把智能调度关掉，提示里只说「已启动」。

使用者的原话：「智能调度调度最优中转站，而启动 claude 也只是打开这个软件」——
两件事本来就不冲突。所以右列启动**什么都不传**：选中的是哪条就走哪条，调度照常。
「指定这一条再启动」是行上那个按钮，它先停调度、切线、再启动，而且提示里把三步写全。

### 右列的空地拿状态填，不拿组件填

右列跟总览卡等高，三个按钮只占上面一截，944 / 786 下总量卡折行后空得更多。
这块空地**不许塞新组件**（排序看板被删过），所以是让启动块和调度卡按高度撑满，
多出来的地方写真实状态：走哪条、为什么灰、按什么挑、上一轮结论、面板关掉即停。

几处实现上的坑：

- **卡片上的口径定时刷新时不调 `decide`。** 它会给每条线现拉一轮站点账单；
  放进定时器就等于替驻留循环加跳。卡片每 30 秒只读库里的调度状态和路由器内存里的选择；
- **启停和启动不用 `disabled` 防连点。** 按钮一 disabled 键盘焦点就掉回 body，
  按空格开完调度 Tab 得从页首重走。改成处理函数里认第一下；
- **`components.css` 有一条全局 `.sub`（`--text-3`）。** 主色底上的副标题要显式
  `color: inherit`，不然是暗字压暗红；
- **调度卡不用 `overflow: hidden` 裁圆角。** 那会把里面两个按钮的焦点环裁掉，
  圆角由两个按钮各自带上。（0.18.2 调度卡连同小开关一起拆了，见下一节。）

## v0.18.2：右列三个大按钮，和「替使用者关掉桌面端」

### 不要小开关，要「点一下就启动」的按钮

0.18.1 的智能调度是一张卡片：右上角一个 26×14 的开关外形，底栏是调度设置。
使用者指着那个开关说「不要做小按钮，做成那种点击启动的按钮」—— 右列三个现在都是
整块点的大按钮：启动（主色实心）、智能调度（关着白底绿框写「启动智能调度」，
开着整块转绿写「智能调度运行中」）、调度设置（一行带箭头）。

又要求「高级的特效，能让用户知道启动的同时也更加美观」。动效因此按**它在告诉人什么**
分三层，每一层都对应一个状态，没有纯装饰：

| 层   | 长什么样                                                                                                           | 说的是                         |
| ---- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------ |
| 悬停 | 一道光扫过、微微浮起                                                                                               | 这块能点                       |
| 按下 | 从按下的位置泛开涟漪                                                                                               | 点到了                         |
| 状态 | 启动中光带一直扫 + 底边进度条 + 真实阶段；成功打勾泛光，失败转红抖一下；调度开着时一道光沿边绕、状态点一圈圈往外扩 | 它在干活 / 干完了 / 它真的在跑 |

启动块上的阶段文字**不是前端编的**：`station_launch` 每走一步更新那条操作记录
（「正在关闭运行中的桌面端（N 个进程）」「检查身份、配置与门禁」），
`workspace://changed` 触发工作区刷新，按钮读的就是那一句。找记录只按
「目标是这个软件的中转环境、还在跑」，不匹配操作名里的中文。

启动状态**按软件记**：启动要好几秒，中途切到别的分页，那一页不该跟着显示「正在启动」。
行上的「启动」也让右列那块跟着动 —— 在哪儿点的，进度都看同一个地方。

系统开了「减少动态效果」就全停，只留状态本身（文字、颜色）。

### 桌面端：替使用者关掉，而不是让他去托盘退出

原来点「启动 桌面端」时桌面端开着，就报错让人自己从托盘完全退出。现在
`workspace::close_desktop_for_relay` 在 `station_launch` 里先做三步：

1. **面板自己起的桌面端会话按会话停**（Job Object，PID + 创建时间核验），交回租约 ——
   只杀进程不交租约，租约会一直显示「有人持有」；
2. 其余的（开始菜单、托盘起的）走 `killswitch::execute_desktop`：跟一键关闭**同一套**证据、
   祖先链否决、核验，只是用 `only_desktop` 收窄到 `Role::Desktop`。**按 role 筛，不按进程名**：
   Claude Code 和桌面端跑的都叫 `claude.exe`，按名字筛会把终端里正在写的会话一起收掉；
3. 进程终止到真的从进程表里消失之间有延迟，**等它没了才往下走**（每 400ms 查一次，最多 8 轮）；
   关不干净就报错、不启动 —— 起了也是走官方，而且没有任何报错。

代价常驻写在启动按钮上：「开着的桌面端会先被关掉」。桌面端 Code 页里跑着的会话
也是 `Role::Desktop`，会一起关 —— 这正是「完全退出桌面端」本来的意思。
`workspace::launch` 里那道拦截保留，别的入口调进来不会先关，那一道是兜底。

顺手修掉的一处：那道拦截的报错文案原来行尾写成了 `\",`（续行符后面多了一对引号和逗号），
界面上显示出来夹着 `",` 和一串缩进空格。

### 两个差点漏过去的坑

- **类名撞车。** 绕边光第一版叫 `.qb-st-ring`，而检验弹窗的可信度圆环早就叫这个名字。
  两边规则一叠加：绕边光被圆环的 `position: relative; height: 84px` 拽回文档流，
  把按钮里的字挤到底下切掉；圆环反过来吃了绕边光的 `opacity: 0` 和 mask，**整个消失**。
  `test:ui` 不打开检验弹窗，所以后一半一条断言都拦不住。现在叫 `.qb-st-edge`，
  station.css 里新加类名之前先搜一遍；
- **悬停把「一直扫」盖掉了。** 点完启动鼠标还停在按钮上，
  `:hover:not(:disabled) .qb-st-sheen` 比 `[data-fx="launching"] .qb-st-sheen` 更具体，
  「启动中光带一直扫」被「悬停扫一次」覆盖。悬停那条现在显式排除干活中的状态。

## v0.19.0：完全卸载 —— 先只读盘点，再确认，最后复扫

使用者的原话：「卸载就是全部卸载，不留一丝一毫，没必要有选项。」于是这一版多了
一条跟「清外部副本」相反的路径：那个的前提是「留着托管那份继续用」，这个的前提是
**这台机器上不再要这个软件了**。托管那份、版本库、配置、会话、认证、环境变量、
Shell 里为它设的那几行、启动项、账户槽位，全都算进来。

### 规划是纯函数，事实靠注入

`install::purge::plan` 不碰磁盘，事实由调用方先探好塞进 `Facts`。理由跟
`managed::plan_claude_externals` 一样：真正容易出错的是**边界**（该不该算进来、
归属依据够不够），不是 I/O。提成纯函数之后每一条边界都钉得住一条单测，
而单测不碰真实运行期状态（档案 §1 第 8 条）。

六条边界各有一条测试：托管那份与版本库**要**清（这正是它跟清外部副本的分界线）、
桌面端带的副本与编辑器扩展**不**碰、账户槽位单独成一类、结构上装不下密钥值、
每一项都必须给得出归属依据、桌面端走 winget 而不是逐个删文件。

### 采集器为什么在 L3

一次完整盘点要同时问三个领域：安装清单（`install`）、账户槽位（`accounts`）、
注册表与环境变量（`sysenv`）。三个都是 L2、互不依赖 —— 谁也不该为了盘点去认识
另外两个。硬塞进 `qb-install` 就得往 `ALLOWED_SIDEWAYS` 里加行，而那张表只许变短。

### PATH 与 Shell 配置合并成一次改写

这两类动的是**别人也在用**的东西。逐项改会把同一个文件读写好几遍，中途失败就留下
一份改了一半的 profile。所以它们不走逐项循环，由 `apply_merged` 按文件合并：
一个文件只读写一次，要么全成、要么全不成。

`path_without` 与 `body_without_lines` 是纯函数并各有单测 —— 它们写错的代价是
使用者的 PATH 或 profile 被毁掉。其中一条专门钉着「没命中时原样返回」：
不做「顺手规整」，空项和结尾斜杠都可能是别人依赖的写法。

`~\.local\bin` 永远不从 PATH 里摘：uv、pipx 也往那里装东西。

### 执行完必须复扫

`Report.left` 是重新扫一遍之后**还剩下的**。不看命令报了什么，看再扫一遍还剩什么 ——
跟升级那条「按哈希核对，不看安装器的退出码」是同一条教训。正在运行的 exe 删不掉，
它会如实出现在 `left` 里，而不是被报成成功。

复扫**不能**证明整台机器再无痕迹：它走的是同一套扫描器，证明的只是「这些位置现在是空的」。
面板够不到 WSL 和其它用户账户，那一块由卡片里那份带着完整路径清单的提示词兜底。

### 认证与环境变量只报名字

`Item` 结构上装不下值 —— 跟 `sysenv::SecretHit`、`relay::ProviderView` 同一条原则：
报出来的东西迟早会被打进日志、截图或者贴进 issue，所以不是靠「记得别打印」，
是让它根本拿不到。确认框里那几项只看得到变量名和「文件:行号」。

### 这一轮自己抓到的两个

- **`signature` 不在 `install` 下面。** qb-install 和 src-tauri 都把它再导出了，
  唯独 qb-app 那份清单里没有，于是 `crate::install::signature::signer_of` 编译不过。
  它是 qb-platform 的模块，正确写法是 `crate::signature::signer_of`。
- **合并处理的那两类差点被提前报成成功。** 第一版里 `apply` 对
  `PathEntryRemove` / `ShellLineRemove` 返回 `Ok("（合并处理）…")`，那等于
  **在真正动手之前就说成功**，而且同一项会被报两遍。现在逐项循环里直接跳过它们，
  `apply` 那条分支改成显式报错 —— 将来谁直接调它会当场炸，而不是静默撒谎。

## v0.19.0：启动对齐 —— 默认开，但「已经一致」时什么都不做

使用者要的是「默认在用户启动本软件时就执行更改时区以及语言」，所以三个开关有两个
默认开。难点不在怎么改，在**默认开不等于每次启动都折腾一遍系统**：切时区要弹 UAC、
改显示语言要注销。所以 `usecase::locale_ops::decide` 的第一条就是「目标与现状相同 →
不进计划」，它在已经一致的机器上产出空计划。

判断与动手分开：`decide` 是纯函数，四项事实（目标时区、当前时区、当前区域格式、
当前语言覆盖）由调用方先取好。四项全是 `Option`，因为**「取不到」必须能跟「取到了
且已经一致」分开** —— 合成一个就会把查询失败当成对齐成功。

### 三个开关，不是一个

| 层       | 用什么                      | 什么时候生效     | 默认   |
| -------- | --------------------------- | ---------------- | ------ |
| 时区     | `tzutil /s`                 | 立刻（要管理员） | 开     |
| 区域格式 | `Set-Culture`               | 之后新开的程序   | 开     |
| 显示语言 | `Set-WinUILanguageOverride` | **要注销**       | **关** |

代价不是一个量级，所以不合并成一个开关。显示语言默认关，是因为它要先装好语言包、
还要注销一次：默认开的话使用者得到的要么是「设了等于没设」，要么是「突然被要求
注销」—— 两种都属于这个项目「默认值必须是最不意外的那个」要挡的意外。

### 启动钩子挂在就绪判定之后

首次运行、面板还没配置好时读到的是默认值（时区对齐开着），照做就会在使用者还没
同意过任何事之前弹一个 UAC 去改系统时区。跟同一个 `setup` 里「白名单为空就不上锁」
是同一条理由：**还没配置好 = 现在什么都不做才是对的**。

它后台跑、不挡启动 —— 要先查一次出口 IP，放在主线程上等于拿网络延迟给窗口
出现的时间封顶。每一项做没做、为什么没做，都进审计日志。

### 查不到就不猜

`locale::locale_for_zone` 查不到返回 `None`，跟 `iana_to_windows` 同一条规矩。
一条测试拿 `MAP` 逐个对照 `LOCALES`：时区表里有的这里都要有，否则会出现
「时区能对齐、区域格式却说查不到」，而使用者看不出两个开关为什么行为不一致。

区域标签拼进 PowerShell 之前要转义。它一路来自第三方 IP 归属查询的返回，
**不是我们自己造的常量** —— 不转义就是一条命令注入，单测钉着这一条。

### 这不是「防封」

DISCLAIMER 写死了「去除中文环境特征不会降低任何封禁概率」。对齐只是让 Claude Code
读到的时区与格式跟出口一致，日志和界面都不许写成安全措施。

## v0.19.0：两个口子 —— 边界落在代码里，不落在说明里

`CLAUDE.md`「不许加的功能」里有一条「内置代理 / VPN」。使用者拍板开了两个**有边界的**
口子：浏览器出站锁（`qb-platform::firewall`）与系统代理修改（`qb-sysenv::sysenv::proxy`）。
那一节的三条硬约束不是写给人看的承诺，是逐条对应到代码的：

| 约束                            | 落在哪                                                       |
| ------------------------------- | ------------------------------------------------------------ |
| 按 exe 路径限定、规则名统一前缀 | `firewall::RULE_PREFIX` + `rule_name`，`-Program` 收绝对路径 |
| 加了什么必须看得见、能一键撤销  | `firewall::list` 只列自己加的；代理的原值**落盘**，见下      |
| 绝不自动加                      | 两个模块都只有函数，没有定时器、没有启动钩子                 |

第三条只能在调用侧保证，所以 `commands/network.rs` 的文件头也写了同一句：
**别给这些命令找任何自动调用点。**

### 出站锁：为什么是「按物理网卡拦」而不是「只放行 TUN」

直觉写法是「允许走 TUN + 阻止其它」，但 Windows 防火墙里 Block 优先于 Allow，
靠优先级凑不出这个语义。能精确表达的只有一种：把 Block 规则**限定在使用者点名的
那几块物理网卡上**（`-InterfaceAlias`）。TUN 不在规则里，走 TUN 的流量根本不经过它。

由此还定了两条：

- **不加 Allow 规则。** 出站本来就默认放行，一条「允许走 TUN」什么都没做，
  却会让界面看起来「我已经把流量绑到 TUN 上了」——那是一句谎话。
- **入站一条都不加。** 目标是「别让浏览器从物理网卡直连出去」，那是出站方向的事；
  加入站规则解决不了它，还会改变这台机器对外的可达性。

删除路径的唯一判据是名字前缀，`remove_all` 逐条走 `remove`，所以「只删自己加的」
这条判据全项目只有一处实现。误删使用者自己的防火墙规则不可逆，而且他多半
不知道是谁删的。

### 那条转义测试写错过一次

第一版断言「注入的文字消失了」，当场挂。转义的本意恰恰是把那串文字**原样留在
引号里当数据**，所以 `Remove-NetFirewallRule -All` 这几个字当然还在。要钉的不是
它在不在，是它**跳不跳得出那对引号**：把成对的引号抠掉后不该剩落单的，
按 `'' -> '` 还原要等于原文。

### 系统代理：原值必须落盘

时区那份存在 `AppState` 的内存里是够的 —— 它承诺的只是「退出时还原」。
系统代理承诺的是 DISCLAIMER §5.2 那句「面板里能回滚到原值」，
**只存内存的话面板一关原值就没了，那句话当场变成空话**。所以它落在
`state_dir()/proxy-backup.json`。

连带一条语义：**连续改两次，备份保留最早那一份**（`keep_earliest`）。
使用者点「修」→ 又改成别的 → 再点「还原」，期望回到的是面板动手**之前**，
不是上一次改之前。覆盖掉的话，真正的原值就再也找不回来了。

### 代理这一侧不拼字符串

`reg.exe` 的参数**直接交给 `Command::args`**，不经过 shell —— 代理地址里有什么
字符都不构成注入。这跟 `firewall` 那边拼 PowerShell 字符串、必须自己转义是两种处境。
**别「顺手」把这里改成拼命令行**，那会凭空造出一个本来不存在的注入面。

另外两条边界各有单测：拒绝「开着代理却没给地址」（那等于让整机流量走一个不存在的
代理，后果是全机断网）；PAC 与手动代理是**两条独立路径**，只关手动代理而留着 PAC，
流量照样被接管，而界面会显示「没开代理」。

## v0.19.0：浏览器隐私面审计

### 策略写 HKCU，但两处都读

Chrome 的策略 HKLM 与 HKCU 都认。需求文档要求「所有修改都应尽量只影响我指定的
软件」，所以写 **HKCU**（只影响当前用户、不要管理员）。但**读的时候两处都读、
并报出来源** —— 只写 HKCU 却只读 HKLM，会把自己刚写进去的策略报成「没设」。

### MV2 与 MV3 两种清单形状都要认

MV2 把 host 模式混在 `permissions` 里，MV3 拆出了独立的 `host_permissions`。
只认其中一种是这类扫描最典型的漏报 —— 而**漏报在这里等于面板说「这个扩展没问题」**。
两条单测各钉一种形状，另有一条反面的：老实扩展不许被报成有风险，
误报多了这一栏就没人看了。

### 只报告，连禁用的函数都不提供

需求文档写死了「只报告风险，不擅自删除」。所以这个模块里**没有**禁用或删除扩展的
函数 —— 没有那个函数，就不会有人误调它。同理，不判断「扩展有没有启用」：
那要解析 Chrome 的 `Secure Preferences`，判错就是一句说谎的结论，
所以它进 `Audit::unchecked`，跟 `chrome_scanned` 那条「没扫 ≠ 没有」同源。

### ⛔「注册表里有值」不等于「策略已生效」

需求文档专门点了这一条。面板读不到 `chrome://policy`，够不到就如实说够不到：
`set_webrtc_policy` 返回的话里必须带着「去 chrome://policy 核对」，
界面不许把它改写成「已生效」。这跟升级那条「不看安装器退出码，看磁盘」、
卸载那条「执行完必须复扫」是同一条规矩 —— 只是这一次够不到那面镜子。

## v0.20.0：综合评分的第五项 —— 出口一致性

一开始做成了账户页上一张独立的「账户体检」卡片，七行：claude.ai 痕迹、
浏览器语言、WebRTC、DoH、扩展权限、环境变量、凭据管理器。使用者看了一眼就否了，
两句话：**「我是让你塞综合评分里面去」**、**「痕迹这些不用管，管的是与 IP
不符合的东西」**。

这两句话砍掉的不是界面位置，是**这一项到底在回答什么**。重做之后它只收
与出口 IP 对不上的信号，七行变五行：

| 行         | 它怎么跟出口打架                              | 从哪来                           |
| ---------- | --------------------------------------------- | -------------------------------- |
| 出口一致性 | 绕过代理和跟随代理量到的是两个国家            | `checkup::compare_egress`        |
| IPv6       | 没关的话可能从另一条路出去                    | `checkup::check_ipv6`            |
| 浏览器语言 | 网站拿到的 `Accept-Language` 跟 IP 地区对不上 | 新写：读 Chrome 的 `Preferences` |
| WebRTC     | 绕开代理直接用 UDP 打出去，暴露真实地址       | `browser_audit`                  |
| 浏览器 DoH | DNS 走系统解析器，解析的出口跟网页的不是一条  | `browser_audit`                  |

痕迹、扩展权限、凭据管理器、环境变量残留**全部拿掉** —— 它们跟出口没关系，
而且各自已经有地方（软件页的 Chrome 卡片、「中文环境」详情里的本机体检）。

前两行**直接取 `checkup::scan()` 的结果，不另写一遍**：出口一致性那一项要真发
两轮请求（绕过代理 / 跟随代理），那种判定只该有一处。

### 权重为什么只给 10

四项变五项，10 分从纯净度（35 → 30）和 DNS（25 → 20）各拿 5。给得最少是因为
五行里有三行是浏览器策略，只报告或只写当前用户的注册表，跟前四项不是一个量级；
但它抓的是**面板显示的出口不是请求实际走的那个** —— 那件事一旦成立，
前面四项全都建立在一个错的 IP 上。

### 三条边界

- **能修的那两项，修法复用已有的那一处。** WebRTC / DoH 走 `browser_audit`
  自己的写入口（只写 HKCU、写完读回、文案里带「去 chrome://policy 核实」）。
  两处各写一份注册表，改一边漏一边是迟早的事；
- **「查不出来」从分子分母里一起去掉**（`EgressChecks::ratio`），跟 `score.ts`
  顶上那条「分母只算已检测项」同一个道理，只是下沉了一层。合并进「通过」之后，
  「没装 Chrome 所以没查」会读成「Chrome 很安全」；
- **语言与出口那一项只报告。** 改浏览器或系统的身份去「对上」出口，
  是 CLAUDE.md「不许加的功能」第一行点名的设备指纹伪装。
  检测与如实报告不在此列 —— 区别是前者让使用者知情，后者替他伪装。

判定是纯函数（`browser_locale` 收一个 `Option<String>` 而不是自己去读 Chrome），
否则这一项的单测得看跑测试那台机器上 Chrome 装没装、设了什么语言。

### DoH 只设 `automatic`，不设 `secure`

`secure` 要求同时给出 `DnsOverHttpsTemplates`（一个具体的解析器地址），
没给的话 Chrome 什么都解析不出来。**「收紧隐私」的按钮把浏览器打断网，
是这一类功能最糟的失败形态。** 而那个地址该填谁，只有使用者自己知道。

### 环境变量残留：三处口径，最松的那处就是使用者看到的那处

`checkup` 的清单原来只认死名字，于是 `CLAUDE_CODE_*` 整族
（含 `_USE_BEDROCK` / `_USE_VERTEX`，它们直接把 Claude Code 切到另一个云端点）
**一个都查不到** —— 而 purge 的归属判定（`purge_ops::is_owned_env`）和启动前的
残留检查（`qb-accounts::residue`）早就认了它。

现在多了一档按前缀算的 `WATCHED_ENV_PREFIX`，进程环境那一遍改成**遍历**
（前缀那一档没有名字表可查）。定点清除只清 `HKCU\Environment`，
而且只清这一项管得着的那些名字 —— 收一个任意名字进来，就等于给了界面一个
「删任意环境变量」的入口。

## v0.22.5：酒馆的「装在哪」—— 按证据找，不按路径表找

### 硬编码路径表在这里行不通

`install::inventory` 那张表成立，是因为 Claude 的落点**有限**：原生安装器、
winget、Scoop、npm、桌面端自带，每一种的目录都可以写死成一条规则。

酒馆和桥接不是。它们是使用者自己 clone 下来放的，可能在任何一个盘的任何一层。
v0.12.0 之前这里写死的是作者本机那份 `D:\tools\…`，在作者机器上碰巧一直对；
删掉之后默认值变成三个空路径，**而错误路径没跟着改** —— 空目录 `join("bridge.py")`
拼出来是个相对文件名，于是点一次酒馆只得到「路径不存在: bridge.py」。

### 三档证据

`plugins::tavern_locate` 不列举位置，按证据找：

| 档        | 依据                              | 代价                      |
| --------- | --------------------------------- | ------------------------- |
| `Running` | 正在跑的 `bridge.py` 的命令行     | 一次 `Win32_Process` 枚举 |
| `PidFile` | `bridge.pid` 记的那个进程的命令行 | 同上                      |
| `Scan`    | 从固定盘根与家目录起的限深 BFS    | 秒级                      |

跑过一次桥接的人第一档就够了，零扫描。档位**必须在界面上分开显示** ——
「正在跑的那个」和「盘里翻出来的」可信度差着量级，合成一句「找到了」等于骗人。

### 认标志物，不认目录名

目录叫什么完全不作数。判据是内容：

- 桥接：`bridge.py` 里同时有 `--claude` 和 `--data-dir`（面板正是拿这两个参数起它的）；
- 酒馆：`server.js` 加 `package.json` 里 name 是 sillytavern。

只认文件名的话，盘里任何一个同名文件都会被当成命中，起起来立刻报参数错，
而面板已经说「找到了」。

### 备份目录必须排在后面

实机样本：一个使用者的盘里九份 `claude-code-sillytavern-bridge*`，一份在用，
八份是 `备份1`…`备份8` 和 `*.reinstall-backup-*`。**随便挑一个就是挑错。**
`score` 给带备份词的路径扣 500、给最近改过的加分、给浅的加分，
然后**列出来让人自己点「采用」** —— 面板不替他决定用哪一份，也不自动写配置。

### 预算与「没找完」

没有上限的扫盘在插着几块硬盘的机器上会跑到天亮。默认档深度 4 / 4 万目录 / 15 秒，
深扫 7 / 40 万 / 90 秒，由使用者显式点。预算用完时 `truncated` 要**如实报出来**：
把「没找到」和「没找完」显示成同一句，人会去装一份他其实已经有的东西。

一次 `read_dir` 同时认标志物和收子目录 —— 分开写的话每个目录要多三次 `stat`，
乘上几万个目录就是预算够不够用的差别。内容判据只在文件名先对上时才做。

### `checks` 算了但没人渲染

`status()` 从一开始就逐项算好了依赖检查，detail 里也写着「展开看缺哪一项」，
**但前端没有任何一处把 `checks` 渲染出来** —— 那句话指着一个不存在的地方。
算了不显示等于没算。现在它在详情页里，没过的那几项默认展开。

## v0.22.6：opener 的「命令」和「网址范围」是两件事

### 光秃秃的 `opener:allow-open-url` 什么都打不开

`capabilities/default.json` 里一直写的是字符串 `"opener:allow-open-url"`。
它的描述原文是「Enables the open_url command without any pre-configured scope」——
放行的是**命令**，范围是空的。而插件（2.5.5 `scope.rs` 的 `is_url_allowed`）
对空范围的判定是 `allowed.iter().any(…)`，**一个都不放**。

于是面板里每一处 `openUrl` 都在报 `Not allowed to open url …`：

| 调用点                           | 使用者看到的                                   |
| -------------------------------- | ---------------------------------------------- |
| 外链（`ui/ExternalLink.tsx` 等） | `void openUrl(href)`，错误被吞掉 —— 点了没反应 |
| 酒馆启动完打开页面               | 弹出报错，**而且报成了启动失败**               |

后一条更糟：`plugin_start` 返回的时候桥接和酒馆已经在跑、租约也拿着，
前端却把整个启动标成失败、也不刷新状态。`sillytavern.rs` 开头那条「成功的启动和
崩溃看起来一模一样」反过来又发生了一次。现在两处（酒馆详情页、总览）把「页面没打开」
单独接住，照实说「酒馆已就绪，但页面没打开」并给出地址。

### 范围只放两类

| 范围                 | 给谁                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| `https://*`          | 全部外链（纯净度来源站点、选购入口等）                               |
| `http://127.0.0.1:*` | 酒馆页面（`sillytavern::page_url`）。端口使用者能改，所以不写死 8000 |

没有用插件自带的 `opener:default`：它还带 `http://*`、`mailto:`、`tel:` 和
`reveal_item_in_dir`，面板一样都用不上。更要紧的是**不许图省事写成 `*`**：
`open_url` 最后交给 ShellExecute，范围放开之后页面里一句 `openUrl` 就能直接
运行本机程序。

匹配是 `glob::Pattern`（`*` 能跨过 `/`），不是 URLPattern —— `http://127.0.0.1:*`
能匹配带端口的地址，靠的是这一点。

### 为什么这么久没人发现

前端测试（`test`、`test:ui`）全在浏览器里跑演示数据，没有 Tauri IPC；
`cargo test` 不碰前端。**这条链只在装好的面板里才走得到。** 所以钉它的
`src-tauri/tests/capabilities.rs` 直接读权限文件：面板会打开的地址（酒馆
取自 `page_url`，外链取自 `probe::verdict::criteria()`）必须在范围里，本机程序
路径必须不在。实测过：换回光秃秃的写法，第一条当场报出 `http://127.0.0.1:8000`；
放宽成 `*`，第二条当场红。

## v0.24.0：官方 Codex 接进本机路由（turn-state 的最后一段接线）

> ⚠ **0.24.7 起，这一节里「官方环境 + 复制 OAuth + 另起 Codex」那条接线被下一节取代，
> 代码已删**（`router_official_environment` / `seed_official_oauth` / `is_official_router` /
> `station_turnstate_launch` 都不在了）。下面「base_url 不带 `/v1`」与「官方上游怎么保住」
> 两小节**仍然成立**；「官方环境靠 provider_id 认」「OAuth 是复制、只播一次」「一键接入」
> 三小节只作历史记录 —— 留着是因为它们写着当初为什么那样做、以及为什么后来不那样做了。

turn-state 的采集/注入机制（`qb-station::turnstate` / `sse`、`local_router` 的官方模式）
0.24.0 早先就写好并单测过了，但**没有任何东西把官方 Codex 的流量导进路由** ——
端到端跑不起来。这一段把接线补上，全在 `workspace.rs` 与 `commands/station.rs`，
`qb-station` 一个字没动（`relay_breakers_can_never_reach_account_switching` 保持绿）。

### base_url 不带 `/v1` —— 差一段就 404，而错误信息看不出来

官方端点在装机版 Codex 二进制里逐字核过是 `https://chatgpt.com/backend-api/codex/responses`
（**没有 `/v1`**）。中转 Codex 的端点是 OpenAI 兼容站点的 `/v1/responses`（**有 `/v1`**）。
两者不能共用一套 base：

|            | 客户端配置的 base                              | Codex 实际打             | `route_of` 剥 `/codex` 后 | `join_url` 拼出                     |
| ---------- | ---------------------------------------------- | ------------------------ | ------------------------- | ----------------------------------- |
| 中转 Codex | `http://127.0.0.1:15721/codex/v1`              | `.../codex/v1/responses` | `/v1/responses`           | `站点/v1/responses` ✓               |
| 官方 Codex | `http://127.0.0.1:15721/codex`（**无 `/v1`**） | `.../codex/responses`    | `/responses`              | `.../backend-api/codex/responses` ✓ |

所以官方这条**跳过 `client_base`**（那个会给 Codex 补 `/v1`），直接用
`client_base_url(Codex, port)`。两头都不带 `/v1`，拼出来正好对上官方那条路径。
任何一头多一段，上游收到的是 `.../codex/v1/responses`，404，而错误里完全看不出多了什么。
0.24.7 起钉着这件事的是 `turnstate_ops` 里的
`takeover_touches_only_model_provider_and_its_table`（断言写进槽位配置的 base 不含 `/codex/v1`）。

### 官方环境靠 provider_id 认，不新加字段

官方环境 = `provider_id == ROUTER_OFFICIAL_PROVIDER_ID` 的那个（`is_official_router`）。
这是**我们自己赋的内部常量**，`router_official_environment` 每次都按回去（自愈），
不是从「base_url 看着像回环」那种使用者能撞上的值里推的 —— 所以跟 `via_router`
那条「别推」的教训不冲突。按 provider_id 认省下了给 `Environment` 加字段
（那会牵动 qb-contract、全部 TS 绑定、导入导出与一堆夹具），而这处判断只有 workspace.rs 用。

### OAuth 是「复制、只播一次」，不是整份托管

官方环境要让 Codex 带着**使用者自己的 ChatGPT OAuth** 打路由。OAuth 不在
`~/.codex/auth.json`（那通常是 apikey 模式），而在**当前激活的 Codex 账户槽位**
（`qb-accounts::codex`，`.../home/auth.json` 里的 `tokens`）——`official_oauth_source`
按「槽位 → `~/.codex`」的顺序找第一处带有效 `tokens` 的。

`seed_official_oauth` 在启动前把它**复制**进官方环境目录，铁律两条：

1. **只读源、绝不移动或改写源** —— 这是 §7.10「auth.json 覆盖登出」教训的正面照做：
   那个坑是往真实目录整份写把官方登录抹了；这里方向相反，只从真实目录读一份出来。
2. **只播一次** —— 环境目录已经有有效 OAuth 就原样留着。Codex 会自己轮换刷新令牌
   并写回**环境目录**的 auth.json；拿一份可能更旧的源覆盖上去会把它弄失效。
   因此官方环境的 auth.json **不进** `configuration_files`/指纹系统（`configuration_state`
   只哈希 config.toml）——否则 Codex 每次续期都会把配置状态刷成「被外部修改」。
   相应地，那道「中转环境目录出现 OAuth 就拒启」的守卫对官方环境**放行**（它本就该有 OAuth）。

### 官方上游怎么保住：`replace_upstreams` 不清 `OAuthPassthrough`

官方上游是 `arm_official_codex` 临时挂上去的，不在 SQLite 的 `station_routes` 里。
而使用者每加/删一条中转线路都会触发 `load_upstreams` → `replace_upstreams` 整批重装。
所以 `replace_upstreams` 现在**保留** `OAuthPassthrough` 那一条（官方线是唯一的
`OAuthPassthrough`，这条等式有测试钉着）。不保留的话，接进路由之后随手编辑一条
中转线路，官方线就被这次重装悄悄冲掉，Codex 下一发请求 503 而看不出所以然。

### 一键接入是显式动作，不搭在注入开关上

`station_turnstate_launch` 一步做完：备环境 → 挂官方上游并选中 → 拉路由 → 播 OAuth →
起 Codex。它跟中转的 `station_launch` **分开写**，不共用：官方这条挂 OAuth 上游、用官方
环境、播 OAuth；中转那条换占位 Key、用中转环境。塞一个函数里全是分支，而分支一多
就会有一条路径接错——这正是「账户四条线」「唯一受控例外」最经不起的错。

注入开关（`station_turnstate_configure`）只管「有可用 292 时补不补注」，**不**顺带挂上游：
挂官方上游会把 Codex 的当前身份切成官方，属于「会改变系统行为的动作」，必须显式点击，
跟「账户切换只能人工触发」同一类纪律。

### 验证边界

单测、离线/回环端到端都过了。但**真实官方 Codex（ChatGPT 登录）走路由采集/注入 292
只能由使用者本人用他的账号实测** —— 这一步谁也替不了，别把偶发成功写成稳定能力
（ccodex 自己都常采不到合格 292）。见 `docs/KNOWN-ISSUES.zh-CN.md`。

## v0.24.7：识别直接作用于槽位 —— 不再造分身、不再复制 OAuth

0.24.0 的接线是「另建一个环境目录 `qb-router-codex-official`，把槽位的 `auth.json` 复制一份进去，
再起第二个 Codex 走本机路由」。0.24.6 修互斥 bug 时把它整个摊开看了一遍，使用者批准推翻。
代码在 `crates/qb-app/src/usecase/turnstate_ops.rs`（纯函数 `apply_to_config` / `revert_config`，
带 I/O 的 `enable` / `disable`，落盘 marker）与 `commands/station.rs`
（`station_turnstate_enable` / `station_turnstate_disable`）。

### 为什么推翻

1. **复制 OAuth 迟早把槽位登出。** ChatGPT 的刷新令牌是轮换式的：复制件和原件谁先刷新，
   另一份就作废。档案 §7.29 在 Claude 上踩过一模一样的坑。「只播一次」缓解不了 —— 两份 Codex
   只要都活着就都会刷。
2. **两个 Codex 实例，使用者分不清哪个在走路由。** 账户页那颗「启动 Codex 桌面端」起的是槽位
   自己的那份（官方直连），识别弹窗起的是分身（走路由）；两者窗口长得一样，而 turn-state
   状态表只对后者有数据。互斥 bug 那张截图就是在这种混乱里撞出来的。
3. **多一套目录就多一处要维护的配置**：分身目录的 `config.toml` 要跟槽位的保持同步（模型、
   MCP、项目授权），而没有任何东西在同步它。

### 现在怎么做：备份 + 增量改两处 + 反向恢复

「开启识别」= 挂官方上游（`arm_official_codex`，`OAuthPassthrough` 那条唯一受控例外不变）
→ 起路由 → 对**当前激活槽位**的 `config.toml`：

| 步骤 | 做什么                                                                                                                                                             | 为什么这样                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 备份 | `config.toml.qb-turnstate-backup`（只在新接管时写）                                                                                                                | 给人看 / 手工兜底，**不是**恢复的依据                          |
| 改   | `model_provider = "qb_turnstate"` + `[model_providers.qb_turnstate]`（base 不带 `/v1`、`requires_openai_auth = true`、不写 `env_key`），toml_edit 增量改，其余原样 | 不写占位 Key：身份全靠槽位自己的 OAuth；`auth.json` 一个字不碰 |
| 记   | marker `state_dir/turnstate-takeover.json`：槽位 id / 标签 / 目录 / 接管前的 `model_provider`                                                                      | 关闭按它恢复，中途切槽位也不会恢复错                           |

「关闭识别」= 摘上游 → 按 marker **反向恢复那两处** → 删 marker。**不整份盖回备份**：接管期间
Codex 自己写进去的项目授权 / MCP / 偏好都要留着，整份盖正是 §7.10 那类事故的形状。
`model_provider` 只在仍是 `qb_turnstate` 时改回 —— 使用者接管期间自己改成了别的，那是他的
新决定，不是我们的残留。恢复失败保留 marker、报错，让人再点一次。

`ensure_table` 那个小函数是 §7.11 的坑：链式索引在空文档上建出来的是**内联表**，
`as_table_mut()` 对它返回 `None`，删键那类逻辑会静默失效。

### marker 是唯一真相，而且面板启动时要自动清

内存里的 `official_codex_armed()` 随面板消失，marker 不会。所以：

- 界面上「识别开着没」看 `RouterStatus.turnstate_takeover`，不看 `turnstate_official_armed`；
- 出站插件的互斥守卫两个都看（`armed || takeover().is_some()`）；
- **`lib.rs` 的 setup 里先跑一次 `disable()`**：上次没关干净（崩溃 / 被杀）留下的 marker 会让
  那个槽位的 Codex 对着一个死端口，而且「默认关闭、只在手动开启后生效」也不允许它跨重启续上。
  这跟智能调度正相反 —— 调度是落盘的承诺，识别是落盘的**债**。

同一处顺手清掉 0.24.0–0.24.6 留下的 `qb-router-codex-official` 环境（连目录、连复制进去的
OAuth 快照）与 `qb-router-official` provider。先查记录在不在再删 —— `Repository::remove`
删不到也回 Ok，不查的话每次启动都写一条「已清理」。

### 互斥的理由从「保守」变成「事实」

0.24.6 时两边不共享文件，互斥理由只能写成「两个程序各自维护 turn-state，互相干扰的可能性
无法排除」。现在两边**都改同一个槽位的 `config.toml`**（识别改 `model_provider`，插件整份接管），
同时开就是两个程序抢同一个文件 —— 守卫还是那两道，文案改成这句。

### 验证边界

跟 0.24.0 一样：单测（纯函数 + 幂等 + 反向恢复）过了，**真实官方 Codex 走路由采集/注入 292
只能由使用者本人用他的账号实测**。见 `docs/KNOWN-ISSUES.zh-CN.md`「0.24.0 → 0.24.7」一节。

## v0.24.8：许可附加条款 —— 「必须链接回本仓库」能做到的极限

使用者的原话是：别人改了发到 GitHub，「必须链接到本仓库，就是在本仓库下面的分支那种」。
先说清做不到的部分，再说做了什么。

### 做不到：强制以 fork / 分支形式发布

许可证约束的是「拿到代码之后必须做什么」，管不到「必须托管在哪、用什么方式建仓库」。
GitHub 的 _forked from_ 是平台功能；在本仓库下开分支更需要写权限。就算写一条
「修改版必须以 GitHub Fork 形式发布」，也不可执行，而且它不在 AGPL §7 允许的附加条款之列 ——
属于「进一步限制」，接收者有权删掉（§7 末段），OSI / FSF 也不再认它是开源许可。
换成 CC BY-SA（条款里有「附链接」）不适合软件；RPL 那类「改了就必须公开」也不要求 fork。

### 做了：AGPL §7 (b)(c)(e)

`LICENSE-ADDITIONAL-TERMS.md`，三条：

| 条         | 依据                                                      | 效果                                                                   |
| ---------- | --------------------------------------------------------- | ---------------------------------------------------------------------- |
| 保留署名   | §7(b)「要求保留指定的合理法律声明或作者署名」             | README + 界面「关于」页必须原样保留「基于 QB Gate … 源码：<仓库地址>」 |
| 改版标明   | §7(c)「禁止歪曲来源，或要求改版以合理方式标明与原版不同」 | 名称 / README / 法律声明里必须写明是改版、非原作者发布                 |
| 不授予名称 | §7(e)「拒绝授予商标权」                                   | 改版不能叫 QB Gate，署名里如实提到原名除外                             |

这三条是 §7 明确允许的，「不属于进一步限制、接收者不得删除」这句话直接写进了文件。

### 四处都要指着它，缺一处就等于没加

§7 末段：加了附加条款的人「必须在相关源文件里写明附加条款，或指明去哪里找」。所以：

- 各 crate `lib.rs`、`src-tauri/src/main.rs`、`src/main.tsx` 头上三行注释（指明去哪里找）；
- README 授权声明（正式声明）里那段 GNU 标准文本多了一句「supplemented by the additional
  terms … set out in LICENSE-ADDITIONAL-TERMS.md」；
- 安装包 `licenses/`（`tauri.conf.json` 的 resources）和 Release 附件（`release.yml`）各带一份；
- 设置页「关于」= AGPL §0 的「适当的法律声明」，原版自己先把那行署名放上去 ——
  下游只要不删就合规，措辞别改。

`release:check` 对这四处逐一断言。少一处的后果不是「有点不规范」，而是下游拿到的那份
在法律上就是一份没有附加条款的 AGPL。

### 顺带修的

`THIRD_PARTY_NOTICES.txt` 表头还写着「GPL-3.0-or-later」—— 0.22.x 换许可时生成脚本改了、
文件没重新生成；而且 0.23–0.24 新增的 25 个依赖也不在里面。这次按锁文件重新生成。

## v0.25.0：用量归属修好 —— 依据没了要找新依据，不是把旧依据写得更响

### 症状：今天 822 条回复，用量卡写 0

`tokens.rs` 把默认目录 `~\.claude\projects` 里的转写归给槽位只认一样东西：
`bridge-session` 行上的 `ownerAccountUuid`。0.21.0 加它的时候实测 16% 的记录没有标记；
到 2026-09-20 再数是**全部**：Claude Code 2.1.271（09-15）起一份都不写了。
于是「今天」永远是 0、页脚一句「有未归属记录」—— 而这句话在使用者眼里就是「统计坏了」。

### 修法：三级判定，每一级都是官方客户端自己写的

| 级  | 依据                                                                               | 代价                             |
| --- | ---------------------------------------------------------------------------------- | -------------------------------- |
| ①   | 桌面端资料目录 `claude-code-sessions\<账户>\<组织>\local_*.json` 的 `cliSessionId` | 读几十个 15 KB 小文件建索引      |
| ②   | 项目目录名里的 `scratch-workspaces-<账户 uuid>-…`                                  | 零 I/O                           |
| ③   | 旧的 `bridge-session` 行                                                           | 整份扫一遍（只在前两级落空时做） |

第 ① 级是主力：桌面端每开一个 Code 页会话就写一条，账户 uuid 直接是它自己写在路径里的
（`AccountRoots::desktop_profile_dirs` 把 `Claude` 联结点与每个 `Claude-<标签>` 都扫一遍、
按 canonicalize 去重）。实测覆盖：同一天 107 份转写里 66 份带旧标记、23 份只能靠 ①、
7 份只能靠 ②，剩 11 份三级都归不出 —— 多是终端里直接起的旧会话，继续如实报「未归属」。
**不按「默认目录现在登的是谁」去摊**：那是拿此刻的快照认领几个月的历史，换过一次账户就全错。

顺带补了一直漏扫的子代理转写（`<会话>\subagents\agent-*.jsonl`，一天 27 份，归父会话）。

教训：**一个只有一条依据的归属，依据消失时的失败形态是「全部归零而且看起来像真的」。**
现在三级里任何一级消失都还有别的撑着，而且每一级在文件头写明了它来自哪里、实测覆盖多少。

## v0.25.0：酒馆的内置 GPT 桥接 —— 只能长成「本机酒馆调本机 CLI」这个形状

### 为什么是面板自带、为什么并进现有插件

Claude 那条桥是使用者自己的 `bridge.py`（驱动 `claude -p`，面板不分发）。GPT 侧什么都没有，
使用者选了「面板自带」，又追加「并进插件商店里的酒馆插件」。于是一份酒馆、两条桥：
`plugins::sillytavern::start` 拆成「起 Claude 桥接」「起酒馆」两段，`plugin_start(backend)`
按后端选路，酒馆已经在跑就复用。

### 形状由政策线决定

2026-09-20 查的公开文本：Anthropic 明文禁止第三方「route requests through … plan credentials」
与「intermediate … session tokens」，但不禁止使用者本人用未修改的官方二进制登录自己的订阅；
OpenAI 对「第三方前端经官方 CLI 用 ChatGPT 登录」**没有**明确允许或禁止的公开条款。
两条线的交集只有一种形状：**桥接只驱动未修改的官方 CLI 的公开无交互模式，令牌一个字不碰。**
所以 `gpt_bridge.rs` 是这样的：

- 每个请求起一次 `codex exec --json`，提示词从 stdin 喂（`exec_args` 有测试钉旗标）；
- `CODEX_HOME=<激活 GPT 槽位>\home`，`auth.json` 由 CLI 自己读；`-c model_provider="openai"`
  强制官方（槽位开着识别时 config 指向本机路由，桥接不该受牵连）；
- 只绑 `127.0.0.1`，Bearer 由面板生成；`-s read-only`；默认 `--ephemeral`；
- 子进程挂进 `KillOnCloseJob`（`qb-platform::process`）：`tokio` 的 `kill_on_drop` 只管 drop
  那一刻，面板被杀时 drop 不会跑，Job 是内核层的。

### 三个实测过才知道的细节

1. **要 exe，不要 `.cmd`。** npm 装的 `codex.cmd` 是 `node codex.js` 的壳，经 `cmd /c` 起时
   `-c key="value"` 的引号会被吃掉。真正干活的原生 exe 在
   `npm\node_modules\@openai\codex\node_modules\@openai\codex-win32-x64\vendor\…\bin\codex.exe`，
   收进 `detect::codex_candidates` —— 顺带补上了「挡得住 codex 命令、挡不住内部脚本」那条锁的缺口。
2. **`codex exec --json` 没有增量文本。** `agent_message` 只有完成事件，所以酒馆的「流式」
   只能是一条 chunk 带全文再 `[DONE]`。不假装能流。
3. **一次只跑一个。** 酒馆本来一次只发一发；`tokio::sync::Mutex<()>` 串行化，超过 300 秒结束。

### 它替不了的

Codex 自带的系统提示替换不了，角色扮演质量取决于模型；不传图、不给工具；酒馆那边的连接
自己配（面板不改酒馆的 `settings.json` / `secrets.json`，跟「候选一律由使用者点采用」同一口径）。
真机端到端只能使用者本人用他的账号做 —— 写进 KNOWN-ISSUES 与桌面档案的待验证清单。

## v0.26.0：反重力 —— 先读它的 app.asar，再决定能做什么

使用者要把 EasyAntigravity 融进来：反重力做官方账户、进软件页、被 IP 锁保护、保留它的功能、接酒馆，
还要做中转站。动手之前没有照 EasyAG 的形状抄，而是把反重力 Hub（v2.15.0）的 `app.asar` 解开读了
`dist/main.js` / `languageServer.js` / `paths.js` / `updater.js`，又在语言服务器二进制里数了几个字样。
四个结论决定了整轮的边界，每一条都有出处：

| 结论              | 出处                                                                                       | 落到哪                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 没有中转路径      | `languageServer.js` 把 `--api_server_url` / `--cloud_code_endpoint` 写死，只认 Google 登录 | 中转侧每个入口显式拒绝（`reject_if_no_relay_path`）；使用者把「Gemini 协议线路」另开一轮 |
| 没有多槽位        | 二进制里 `CredRead/CredWrite` 43 处、`oauth_creds` 0 处 → 令牌在凭据管理器                 | 「官方账户 · 反重力」只有启动 / 关闭；槽位给了酒馆用的 Gemini CLI                        |
| 调试端口总是开着  | `main.js`：没传 `--remote-debugging-port` 就补 `0`，端口写进 `DevToolsActivePort`          | 汉化引擎读文件取端口，不像 EasyAG 那样写死 9333                                          |
| 单实例 + 托盘后台 | `requestSingleInstanceLock` + `runInBackground`                                            | 起之前先关（`close_antigravity_for_launch`），三步同桌面端中转                           |

### 「保留所有功能」与「不抄来源不明的二进制」怎么同时成立

EasyAG 四个功能里三个是页面脚本（汉化、审批、拦截），MIT，逐字带入（`assets/antigravity/inject.js`），
Rust 侧只换六个占位符。第四个「免 TUN 代理」是一份 561 KB 的 `version.dll`，`config.json` 里自己写着
`"_proxy_core": "based-on-antigravity-proxy"` —— 它不是 EasyAG 的代码，MIT 那份 LICENSE 管不到它，
而且做的事是往 Google 的安装目录丢 DLL、注入语言服务器、更新后回写。使用者听完之后定了：不做。
「保留所有功能」于是有了一个明确的例外，写在 ATTRIBUTION、DISCLAIMER §8、KNOWN-ISSUES 三处。

### 为什么加两个 `Client` 变体而不是一个「反重力」概念

`Session` / 租约 / 看门狗 / 一键关闭全按 `Client` 走，绕开它就要复制一整条链。代价是 231 处引用
要逐个补 —— 那正是穷尽 match 的意义：漏掉的那一处编译器当场报，而不是悄悄接错档。中转侧的分支
一律显式拒绝，`client_base_url` 给的 `NO_RELAY_PREFIX` 让万一漏到配置里的地址自己说明为什么 404。
两个变体（Hub / IDE）而不是一个：它们是两个可执行文件、两个单实例，启动与收进程都分开，
只是共用一个门禁开关（同一个 Google 账户，只锁一个就是给另一个留门）。

### 酒馆接的是 Gemini CLI

Hub 的 `--headless` 走语言服务器未公开的 stdin 协议 —— 跟 Codex 那条「不用 app-server 协议」是同一条线。
能像 `codex exec` 那样驱动的是 Google 自己的 Gemini CLI：公开的无交互模式、`--output-format json`、
`GEMINI_CLI_HOME`（`packages/core/src/utils/paths.ts` 核过）。`gemini_bridge.rs` 复用 `gpt_bridge` 的
HTTP 骨架与提示词框架，只换执行与解析。界面上从头到尾写「Gemini CLI」，不写「反重力」——
额度是否共享没有核实过，写成一样就是骗人。

## v0.27.0：汉化一次都没生效过 —— 判定条件问错了问题

0.26.0 的自动附加是这么写的：

```rust
let before = metadata(&port_file).modified().ok();   // ← 在 launch 返回之后才采样
for _ in 0..30 {
    sleep(1s);
    if metadata(&port_file).modified().ok() != before { start(); return; }
}
```

**它等的是端口文件的修改时间发生变化。** 而 Chromium 在进程刚起来的几百毫秒里就把
`DevToolsActivePort` 写完了 —— `workspace::launch`（关旧实例 → spawn → 托管会话 → 租约）返回时，
文件已经是新的了，`before` 采到的就是那个新值。于是 `before == now` 恒成立，30 次全落空。

实机日志里连着两次都是同一句：

```
2026-09-20T11:56:40Z  起 Hub 之后 30 秒没等到调试端口文件，汉化引擎没有自动附加
2026-09-20T20:45:23Z  起 Hub 之后 30 秒没等到调试端口文件，汉化引擎没有自动附加
```

而那个文件的修改时间是 20:44 —— **它一直都在**。

三件事凑在一起才让这个 bug 活了一整个版本：

1. **判定问错了问题。** 「文件变了吗」是「端口起来了吗」的一个**代理指标**，而代理指标会在
   时序变化时悄悄失效。现在直接问那个真问题：`GET /json/list` 列不列得出页面
   （`cdp_ready`）—— 文件在不在、变没变都不重要，能应答就能注入；
2. **失败只写审计日志。** 界面上一片安静，使用者看到的只有「还是英文」。现在失败原因进
   `note_attach_error`，反重力页的引擎卡直接显示；
3. **成功是自称的。** 就算附加上了，`sockets` 数的是「开了几条连接」、`inject_count` 数的是
   「`Runtime.evaluate` 发出去几次」，而回执（含 `exceptionDetails`）被 `handle_event` 整个丢掉 ——
   没有任何一处证明脚本真的在页面里跑起来了。现在注入之后紧跟一条**面板自己的**只读表达式
   （`VERIFY_EXPR`，不是 EasyAG 的脚本），读回 `window.__ea_engine_running` 与字典条数，
   界面显示的是**核实过**的页面数。

这跟档案里「`real_multiplier` 恒等于站点自己公布的两个数相乘、而 20 条单测全绿」是同一类失效：
**看起来在工作，而衡量它的那个量本身是假的。**

### IDE 的端口是面板补的

Hub 的 `main.js` 没传 `--remote-debugging-port` 时自己补 `0`，所以它的端口总是开着；
IDE 是 VS Code 分支，**默认不开**。0.27.0 在 `qb-platform::sessions::desktop_arguments`
（按 client 给参数的那一处，不在调用方另拼）给 `Client::AntigravityIde` 加 `--remote-debugging-port=0`。

两个选择值得记：

- **传 `0` 而不是写死一个号码。** EasyAG 写死 9333；写死的那个号在别人机器上会撞占用，
  而症状是「汉化偶尔不生效」，查不出来。传 `0` 让 Chromium 自己挑，端口写进它自己的用户数据目录，
  面板从那个文件读回来 —— 位置表 `install::antigravity::devtools_port_file(product, roaming)`
  现在按产品给路径（Hub 是 `%APPDATA%\Antigravity`，IDE 是 `%APPDATA%\Antigravity IDE`）；
- **只有面板起的那一份能汉化。** 使用者自己从开始菜单起的 IDE 没有这个参数，引擎附不上去。
  这是事实，界面上就得这么说 —— 装了第三方汉化壳的人还要多一条：那层壳可能不把参数传给里层。

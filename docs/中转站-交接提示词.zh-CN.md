## 1. ⛔ 数据模型（定稿，不许改）

```
Provider（站点 / 域名）      共享一份，三个软件共用，不按软件复制
└─ Route（分组 + 那把 Key）  ⬅ 按软件独立，同一个站点在不同软件下是不同的行
   └─ Credential            一个分组一把 Key，没有第三层
```

**依据**（都已核实，不要再查一遍）：

| 来源 | 证据 |
|---|---|
| cc-switch v3.20.3 | `src-tauri/src/database/schema.rs:27-43` 的 `providers` 表 `PRIMARY KEY (id, app_type)`；`proxy/server.rs:39` 的 `current_providers: HashMap<app_type, (id, name)>` |
| 使用者自己的 sub2api / sub2guard | 层级是「域名 → 分组 → 账户 → 模型」，分组按**通道档次**分不按模型分；总站只是方便管底下的 key |

跟 cc-switch 的**唯一分歧**：它把站点也按 app 复制一份，我们**不复制**——使用者明确说总站是共享容器。

**软件识别靠路径前缀**（照 cc-switch `proxy/server.rs:291-333`）：

| 路径 | 判为 |
|---|---|
| `/v1/messages` | Claude Code（Anthropic 协议，裸路径兜底） |
| `/cd/v1/messages` | Claude 桌面端 —— **只有它需要前缀**，因为协议跟 Claude Code 一样，分不开 |
| `/v1/responses` · `/v1/chat/completions` | Codex（OpenAI 协议自带区分） |

⚠ **cc-switch 的默认端口也是 15721，跟我们撞**。端口被占时如实报错并把端口号写进错误里，**不静默换端口**，错误信息里要点名「可能是 cc-switch 占着」。

### 2.6 调度设置弹窗

- **右列的「⚡ 启动智能调度」是启停按钮**，点了就启动/停止。
  ⛔ 不要把它改成"打开设置"——设置是它**下面单独一个「⚙ 调度设置」入口**，那个才开弹窗。
- 弹窗内容：三个口径复选框（便宜/快/稳）· 三条底线（成功率≥ / 首字P95≤ / 真实倍率≤）· 三个预设（写代码 / 跑批量 / 对话）· 实时赛道（每条线三维比值条 + 最弱项 + 缺数据的如实标出）· 页脚写迟滞 8% 的理由 + 启动/停止按钮。
- ⛔ **是复选框不是推子**。理由写在界面上：推子显示 50% 的精度而那个精度不存在。
- ⛔ 评分是**跟池里最好那条的比值**，不是池内 min-max。
- ⛔ 「缺数据」**不写成 0 分**。

**调度运行时的视觉**（⛔ 不要加横幅）：
- 按钮进「调度中」态，带呼吸点，小字显示当前口径

## 3. ⛔ 自动探测（定稿）

**协议和倍率都自动来，手填只是兜底。**

- **⚡ 按钮 = 探三种协议 + 拉 `/api/pricing`**
  - 协议：`ProbeRequest` 带 `client` + `wire_api`，一次一种，探三次
  - 探通 → `true`；上游明确拒绝 → `false`；网络或 Key 的问题探不出来 → **留 `null`**
  - ⛔ **探不出来的不许猜成「不支持」** —— 三态存在的意义就是接住第三种情况
  - 倍率：`StationRates.model_ratio` / `completion_ratio` / `cache_ratio` 从 `/api/pricing` 拉；拉不到就**如实写「站点没开 /api/pricing」**，不编一个数
- **手填的两项都降级到高级选项里**：
  - 「倍率兜底 · 站点没开 /api/pricing 时才用」，说明写死「这是**你自己填的**，不是站点公布的」
  - 「协议 · 手动改」，说明写死「正常别动，只在探不出来而你确知答案时才改」
- 依据：`RouteDialog.tsx:110-111` 本来就写着「计费倍率由检验时从站点的 /api/pricing 拉，不在这里手填 —— 手填一个 completion_ratio 会让『计费翻倍』这个显示变成猜的」。同一条理由对 `model_ratio` 一样成立。

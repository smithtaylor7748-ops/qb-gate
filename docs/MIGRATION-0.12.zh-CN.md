# 从 v0.11 升级到 v0.12

## 升级前

关闭旧面板，保存正在运行客户端的内容。检查 Windows 已安装应用是否同时有 ClaudeGate 和 QB Gate；旧名称需要单独卸载，不能靠新版自动覆盖。保留 `%LOCALAPPDATA%\ClaudeIpGate` 和现有官方账户、酒馆目录。

程序安装不会迁移官方凭证。首次启动先恢复未完成的文件与软件部署日志，再执行数据库迁移。旧 JSON 数据先备份到运行期数据目录，再通过一个 SQLite 事务导入。失败时显示恢复页面，避免用空配置覆盖无法读取的数据。

## 数据去向

- 服务商、API 凭证引用、中转环境、扩展安装、会话、操作记录保存在 `workspace.sqlite3`。
- API Key 使用当前 Windows 用户 DPAPI；换机器或 Windows 身份后不能保证解密，界面会要求重新填写。
- 官方 OAuth 保持在客户端原生目录或现有槽位中，不导入数据库，也不纳入新版配置快照。
- 中转环境位于运行期目录下的 `environments/<ID>/`；官方目录中的残留 API 配置需要显式预览迁移。
- 旧混合档案拆为官方与中转独立启动方案。历史 Desktop 中转记录保留为服务记录，不假称可启用桌面中转。
- 启动方案只描述一个身份。启动官方方案前仍需在官方账户页切换对应槽位。

## 恢复规则

快照使用时间戳加 UUID，源文件在恢复前完整读取和校验。恢复前自动备份当前状态；保留策略保护恢复来源与这份自动备份。恢复不会换官方账户、软件安装根或系统时区。

快照保存内部元数据、实际官方槽位 settings、Codex TOML 和中转环境 settings/TOML。它不保存官方 OAuth、客户端二进制、Skills 全部文件或 Claude 的会话状态文件。恢复后扩展安装状态会重新核验；缺失或已修改的资产需要从扩展详情处理。

软件回滚独立于配置快照，以完整安装单元恢复主程序与 Codex 配套程序，并更新安装记录。迁移安装根目录请使用高级维护中的专用入口。

## 中断或回退

启动恢复页面会显示具体失败原因，保留日志，不自动删除问题文件。处理文件被占用、权限或磁盘空间后点击重试。应急移除执行锁可在恢复模式中使用。

需要回到 v0.11 时，先退出 v0.12，保留整个运行期目录副本，再安装旧包。旧版仍读取迁移前保留的 JSON；v0.12 新增数据不会自动反向同步给旧版。旧版不能管理新版独立中转会话或理解新版文件日志，切勿让两个版本同时管理配置。不要把新版数据库与快照发到公开 Issue。

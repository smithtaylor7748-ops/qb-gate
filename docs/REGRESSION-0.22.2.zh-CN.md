# 0.22.2 本机 IP 自测与体检状态（2026-09-16）

## 问题与修复

- 一次「检测本机 IP」原先顺序调用 `probe_ip` 与 `probe_purity`，后者又向同一个 IPPure 接口查询一次。现在只取一次本机读数，IP、系数和住宅 / 家庭 IP 判断使用同一份数据；判断阈值继续使用后端发布的标准。
- 总览曾把「可以计分的项数」写成「已检测项数」。旧人工复核记录没有关联 IP 时，即使已经取得本机系数与住宅判断，也显示为未核实、4/5。现在分别统计已测与可计分项目；本机结果成功但尚未关联人工复核时，显示「已自测」及实际读数。
- 不补写或伪造人工通过记录。当前出口未知、已变更或新请求失败时，不以旧的通过结论计分；缺少来源字段仍保持未知。
- 弹窗与对象状态对人工通过记录使用相同的当前 IP 校验。最新请求失败或正在刷新时不能用旧 IP 记录通过，保存错误会在界面显示。
- 删除「还有 N 项待检查」横幅和相应提醒内容。
- 指定 IP 输入框仍为可选查询，结果独立；本机按钮与完整体检不受其内容影响。

## 验证范围

- 使用与应用相同的 Rust `ip_info()` 在本机实测成功：返回有效 IPv4、IPPure 系数 3、住宅判断 true。临时读取程序已移除，单测不联网、不碰用户运行期状态。
- 增加无人工结论、旧记录未关联 IP、请求失败不采用旧读数的评分回归；增加同一快照自测、失败后重试恢复回归。
- 界面回归覆盖完整体检后「已测 5/5」与「已自测」同时可见、指定查询不覆盖当前结果，以及移除待检查横幅。
- 没有添加依赖开发机路径、配置或工具链的运行时代码。

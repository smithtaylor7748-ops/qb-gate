# QB Gate 浏览器助手

Based on QB Gate, Copyright (C) 2026 smithtaylor7748-ops.
Source code: https://github.com/smithtaylor7748-ops/qb-gate

需要 Chrome 116 或更新版本，以及包含「Chrome 插件联动」功能的 QB Gate。现有旧版 QB Gate 不含连接服务。

1. 打开 `chrome://extensions`，开启「开发者模式」，选择「加载已解压的扩展程序」，选择本目录。
2. 在 QB Gate 官方账户页打开「环境体检」详情，找到「Chrome 插件联动」，点击「生成配对码」。中转站的「查套路 → 使用 Chrome 已登录账户」中也有同一入口。
3. 点击 Chrome 工具栏里的本插件，把配对信息粘贴到「连接与配对」，点击「保存并连接」。每次重启或重新开启 QB Gate 联动后需重新配对。
4. 要保护浏览器时，点击「开启保护」。只有 IP 锁放行才能开启。

开启保护后，出口 IP 变化（即使新 IP 也在白名单）、IP 锁不放行、与面板断联或心跳超时，会关闭插件所在 Chrome 资料的全部窗口。插件不结束后台进程、不关闭其他资料。隐身窗口仅在 Chrome 扩展设置允许此插件在隐身模式运行时可覆盖。普通窗口的测试不能证明隐身窗口受保护。

这是一项检测后关闭窗口的保护，不是网络防火墙，不能保证新网络上的请求在检测前被阻断。公网出口由 QB Gate 定期探测；Chrome 独立代理或 PAC 可能使用不同出口，该值不能证明 Chrome 的真实出口相同。插件开启保护后，可观察的网络连接类型变化、离线或代理配置实际变化也立即触发关闭。仅网速/延迟估计变化会请求面板复查，不直接关窗；浏览器未提供连接类型时，仍依赖出口巡检与离线事件。心跳每 2 秒由面板发送，插件每 5 秒检查，超过 12 秒无有效心跳触发关闭。关闭 Chrome 后重新打开需手动开启保护；若 Chrome 只重启了扩展后台而保护仍在进行，会关闭窗口并要求重新开启。扩展禁用/卸载、浏览器强制停止执行扩展时，插件本身无法继续执行保护。

「检查当前 Chrome」在这个 Chrome 打开 QB Gate 的一次性检测页，沿用语言、时区、字体、WebRTC 与请求头检测。另只读实际 WebRTC 策略和代理模式/控制方，不传代理地址、密码或 PAC 内容。报告回到本机面板，不进入 IP 锁裁决。

在 Chrome 登录 New API 或 Sub2API 站点后，在插件选择匹配的 QB Gate 站点与类型，点击「连接已登录账户」。插件仅当次读取此页明确列出的会话存储键，以及同一 Cookie Store、同一站点的 `session` Cookie；不读取密码或刷新令牌。会话经已配对的本机连接交给 QB Gate，验证余额与账单接口成功后用现有系统加密保存。登录失效后重新点击连接即可，不必再次在面板登录。不会创建模型 API Key，不会调用收费模型。

「读取公开价格」匿名请求 New API `/api/pricing` 或 Sub2API `/api/v1/model-plaza`。站点要求登录或未开放价格时如实报错；公开单价与官方价的比值只是报价对照，不是账单实扣结论。各项单位与缺失价格由 QB Gate 同一解析器处理。

权限：`activeTab`/`scripting` 仅手动读当前页；`cookies` 读取已授权站点的登录会话；`storage` 保存配对与临时保护状态；`privacy`/`proxy` 只读检测；`alarms` 用于后台恢复与未保护时重连。中转站权限逐站由 Chrome 提示授权。解除配对会删除本地配对令牌并停止保护，已交给 QB Gate 的账单登录仍由面板管理。
